接雨水：比较两侧最高挡板，先结算较低的一边

题意和示例

给定非负整数数组 height，每个元素是一根宽度为 1 的柱子。雨水只能留在左右都有挡板的低洼处，求所有位置的积水总量。

例如 [3, 0, 1, 3]：中间两列分别存 3 和 2 单位水，答案为 5。不是数有几个凹槽，而是把每一列的水量相加。

再看 [0,1,0,2,1,0,1,3,2,1,2,1]，答案是 6。挡水的柱子可以相距很远，不一定紧挨着低处。

考查点

  • 把二维的积水形状转成一维的逐列求和。
  • 从左右最高值的公式出发，判断哪些信息已经足够确定答案。
  • 双指针每次只结算一列，避免重复计算。
  • 区分“当前柱高”和“走过区域的最高柱高”，不能混用不同版本的证明。

Java 代码

下面选择比较两侧历史最高值的写法，方便把代码与正确性证明逐项对上。输入约定为非空引用、元素非负；长度不足 3 时直接返回 0。

class Solution {
    public int trap(int[] height) {
        if (height.length < 3) {
            return 0;
        }

        int left = 0;
        int right = height.length - 1;
        int leftMax = 0;
        int rightMax = 0;
        long water = 0;

        while (left <= right) {
            leftMax = Math.max(leftMax, height[left]);
            rightMax = Math.max(rightMax, height[right]);

            if (leftMax <= rightMax) {
                water += leftMax - height[left];
                left++;
            } else {
                water += rightMax - height[right];
                right--;
            }
        }

        return Math.toIntExact(water);
    }
}

累计值使用 long；返回类型与题目接口保持一致。如果把这段代码用于水量可能超过 int 的扩展输入，最后的精确转换会抛出异常，而不是静默溢出。业务接口允许时应直接返回 long。

文字推导与正确性

先得到每一列的公式

令 L[i] 是从数组起点到 i 的最大高度，R[i] 是从 i 到数组末尾的最大高度，两者都包含当前位置。

这一列的水面最高只能到 min(L[i], R[i])，否则会从较低的一侧流走。因此：

water[i] = min(L[i], R[i]) - height[i]

因为最大值包含当前位置，差值天然非负。左右任意一侧没有更高挡板时，这一列就是 0。

逐列扫描左右最高点需要 O(n²) 时间。预先计算前缀、后缀最大值能降到 O(n)，但还要两个长度为 n 的数组。

为什么只保留两个最大值就够了

每轮更新后，leftMax 是 [0, left] 的最大高度，rightMax 是 [right, n-1] 的最大高度。尚未结算的区间是 [left, right]。

如果 leftMax <= rightMax，左指针所在列的左侧最高挡板已经精确知道，就是 leftMax。它的右侧至少存在一根高度为 rightMax 的挡板，所以真正的右侧最高值不会低于 leftMax。

于是公式里的较小值一定是 leftMax。右侧即便还有更高柱子，也不会改变这一列的水量，可以立即加上 leftMax - height[left]。

反过来，leftMax > rightMax 时，右指针这一列的右侧最高值精确已知，左侧又已有足够高的挡板，所以立即加上 rightMax - height[right]。

不是猜另一侧最终有多高，而是证明另一侧已经足够高。

为什么相等时也能移动，为什么不会漏算

两个最高值相等时，任选一侧结算都成立。代码统一处理左侧，不需要单独跳过重复高度。

每轮只移动一个指针，对应恰好结算一列。循环使用 left <= right，最后相遇的一列也会处理；随后指针交错，所有列各处理一次。

用 [3, 0, 1, 3] 手推：第一轮两侧最高值都是 3，结算左端得到 0；接下来两轮左侧水量分别为 3、2；最后右端为 0，合计 5。

复杂度和边界

  • 时间复杂度 O(n)：左右指针总共移动 n 次。
  • 额外空间 O(1)：只保存指针、最大值与累计水量。
  • 空数组、单柱、双柱：无法围住水，返回 0。
  • 全零、等高、单调递增或递减：每列水量都为 0。
  • 重复高度不是特殊情况，例如 [2, 0, 2] 得 2，[2, 2, 2] 得 0。
  • 高挡板夹着长低谷时，累计值可能很大，不能只因为单个高度是 int 就断定总和安全。

负高度和 null 不属于上述输入约定；若用于开放接口，应先决定拒绝还是转换非法输入，不能直接把负数当成地下蓄水空间。

面试时忘记怎么办

先别背指针移动规则，写出 min(左侧最高, 右侧最高) - 当前高度。用 [3, 0, 1, 3] 验证，说明水量按列累加。

暂时推不出常数空间解，就先给出前后缀最大值数组方案：线性时间、线性空间。这是完整且容易验证的解法，不必为了优化而写一段解释不了的代码。

再问自己：“哪一侧已经不需要知道另一侧的精确最大值？”答案是历史最高值较小的一侧。另一边已经提供了足够高的挡板，当前列就可以定案。

最后明确自己的实现比较的是历史最大值，并且先更新、再结算、最后移动。不要一边比较当前柱高，一边套用历史最大值版本的证明。

一句话总结

接雨水的双指针不是同时找两堵最高墙，而是不断结算已经有足够挡板保证的一列。
