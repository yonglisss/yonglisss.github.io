AG-UI：把 AI 接进产品，别只接一串聊天文字

智能体能查资料、改数据，产品界面却只显示“正在思考”，用户很难知道任务走到了哪一步。AG-UI 是连接智能体与用户应用的开源事件协议，把文字、工具调用和状态变化变成前端可处理的信息。它进入了本次 GitHub 日榜，值得正在做 AI 应用的开发者关注。

智能体能查资料、改数据，产品界面却只显示“正在思考”，用户很难知道任务走到了哪一步。AG-UI 是连接智能体与用户应用的开源事件协议，把文字、工具调用和状态变化变成前端可处理的信息。它进入了本次 GitHub 日榜，值得正在做 AI 应用的开发者关注。

📌 这个项目是干什么的

  • 规范智能体与用户界面之间的交互，不是新模型，也不是完整业务系统。
  • 支持流式消息、工具调用展示、状态同步和人工参与，适合需要展示执行过程的产品。
  • 与 MCP 分工不同：MCP 让智能体使用工具，AG-UI 处理智能体怎样与用户应用交互，两者可以配合。

🔍 为什么值得关注

更有借鉴意义的是把“回答内容”和“应用状态”分开。聊天文字供人阅读，结构化事件驱动界面，不必从一句“任务完成了”里猜测数据库是否已经更新。

工具调用有开始、参数和结果等事件；状态管理提供完整快照与增量更新。比如做待办助手，可以把生成建议显示在对话中，再用状态变化更新任务列表，避免两边各说各话。

但工具参数传输结束，不等于工具执行成功。界面应根据实际结果更新成功状态，而不是看到结束事件就显示绿色对勾。这比多做一个聊天气泡更重要。

🧪 谁适合试，怎么开始

适合已有智能体后端、准备接入网页界面的开发者。官方快速开始提供脚手架：

npx create-ag-ui-app@latest

按向导选择方案，再依生成项目的说明配置、启动。先不要接整个业务系统：只做一个“读取任务、生成建议、更新列表”的小闭环，检查流式文字、调用结果和状态更新是否对应。

需要对照实现时，可看官方 Dojo 示例及源码，优先选与你后端框架一致的一条集成路径。

⚠️ 使用提醒

协议解决交互格式，不替你完成鉴权、数据库事务和跨设备同步。涉及删除、付款等操作，仍应由业务后端校验权限与参数，不能把前端确认当成安全边界。

不同集成的版本与能力需要分别核对，别把示例可运行等同于生产可靠。项目采用 MIT 许可证；本篇依据官方资料梳理，未进行本地接入实测。
