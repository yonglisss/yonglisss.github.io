同一句“上月收入多少”，可能因为退款、税费和时间口径不同，得到几个都像对的数字。NVIDIA 开源的 Auto Ontology，为数据库和智能体之间补上一层业务定义。本次核验时它出现在 GitHub 日榜；值得看的不是回答速度，而是怎样让查询结果有据可查。

📌 这个项目是干什么的

  • 面向做数据问答、经营分析和企业智能体的开发者，不是通用聊天工具。
  • 从数据库元数据生成业务术语、字段映射与表间关系，把“客户”“收入”等概念关联到真实数据。
  • 提供网页界面，也能通过 MCP 和接口接入已有智能体；回答可返回 SQL 与查询步骤。

🔍 为什么值得关注

它把流程拆成生成、人工确认、回答三个阶段。系统先整理术语和关系，人再修正并认证定义，智能体据此查找候选信息、生成和检查 SQL。重点不是让模型猜懂所有表，而是把业务知识变成能维护的公共资产。

另一个实用设计是区分“系统能运行”和“问题能回答”。MCP 提供就绪检查与可回答性检查：数据库没连通、语义层没编译，和数据根本不包含广告支出，是不同问题。开发自己的数据助手时，也值得把这些失败原因分开呈现。

🧪 谁适合试，怎么开始

适合已有数据库、愿意投入时间梳理指标口径的团队。只想上传一份文件随便问问，不必先部署这套系统。

最短验证路线是照 README 跑示例销售库：准备 Docker Compose v2、uv 和 NVIDIA API 密钥，复制并填写环境配置，按步骤导入示例库、启动服务，再开启语义编译。不要只执行启动命令就认为可用了。

先选三个能手工核对的问题：一项收入汇总、一次跨表查询、一个数据不覆盖的问题。检查 SQL、原始记录，以及它是否明确说明无法回答，再考虑连接自己的业务库。

⚠️ 使用提醒

项目采用 Apache 2.0 许可证，但开源不等于免模型调用成本，也不代表查询一定正确。本文是官方资料核验，不是部署实测。

首次试用只接脱敏样例。官方文档明确：未配置 Vault 时，界面保存的连接凭据会以未加密形式存入 Postgres；后端和导入服务端口也应保持在私有网络。人工确认指标定义、限制数据库权限，仍然不能省。
