book-to-skill：把技术书和内部文档，编译成 Agent 随用随取的 Skill

把整本 PDF 塞进模型上下文，当然能问问题，但每次都要重新处理大量原文。今日 GitHub Trending 上的 book-to-skill 提供了另一条路：先把书籍或文档“编译”为结构化 Agent Skill，之后只按问题加载相关章节，更适合需要长期复用的知识。

📌 这个项目是干什么的

book-to-skill 可处理 PDF、EPUB、DOCX、Markdown、HTML 等资料，也能合并文件夹、通配符匹配的一组文件。它先用确定性的 Python 提取器清理文本、识别目录与章节，再由 Agent 提炼框架、决策规则、反模式和术语，最终生成 SKILL.md、章节文件、词汇表、模式库与速查表。

重点不是“给书做摘要”，而是把知识整理成可调用的工作方法。比如把架构手册转成 Skill 后，开发时可以直接询问某个设计决策；没有涉及的章节不会提前占用上下文。

🔍 为什么值得关注

第一，适合高频复用，而非一次性问答。 项目把大文档的解析成本放在转换阶段，查询时通常只加载核心 Skill 和相关章节。官方基准显示，相比整本放入上下文，单次问题的输入 token 可减少 24～51 倍；这是项目自测结果，应视为工作负载相关数据，而非普遍保证。

第二，输入与输出结构透明。 文档提取和章节切分由 Python 工具完成，生成物则是可审查、可编辑的 Markdown，不需要绑定专用向量库。它兼容 Agent Skills 规范，可用于 Claude Code、GitHub Copilot CLI、Amp、Codex 和 Hermes Agent。

第三，安全边界考虑得比较具体。 项目会清理不可见 Unicode，检查 DOCX 中的危险 XML，并提供生成后提示注入扫描。不过扫描只是辅助，内部敏感资料仍应配合本地权限、私有仓库和模型数据策略使用。

🧪 谁适合试，怎么开始

它适合经常查阅技术书、规范、运行手册、研究资料或团队文档的开发者，也适合想把知识库嵌入编码工作流的小团队。最短安装方式是：

npx skills add virgiliojr94/book-to-skill

安装后，可从一份自己有权使用的文档开始：

/book-to-skill ./my-book.pdf

首次建议选择章节清晰、篇幅适中的资料，生成后抽查 SKILL.md、章节索引、关键定义和引用位置，再用几个已知答案的问题测试准确性。纯文字 PDF 可走快速提取；包含大量代码、表格和公式的技术资料更适合 Docling 模式，但处理更慢。

⚠️ 使用提醒

扫描版 PDF 没有文字层，需要先 OCR；图表中的文字也不会自动提取。转换器在本机处理文件，但如果生成阶段使用云端模型，送入模型的文本仍受相应服务商条款约束。

更重要的是版权：工具采用 MIT 许可证，不代表输入书籍或生成内容可以公开分发。购买的书、公司内部资料和受限论文，生成的 Skill 应默认保持私有。当前最新正式版为 v1.4.0；正式接入团队流程前，建议固定版本并审查生成结果。
