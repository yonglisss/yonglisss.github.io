二叉树的最大深度：先定义返回值，再写递归

题意和示例

给定二叉树的根节点 root，返回从根走到最远叶子时，沿途经过的节点数。这里数的是节点，不是边；空树返回 0，只有根节点则返回 1。

例如层序表示 [3,9,20,null,null,15,7]：根节点是 3，左孩子是 9，右孩子是 20，而 20 的两个孩子是 15 和 7。最长路径可以是 3 → 20 → 15，经过三个节点，答案为 3。

再看 [1,null,2]：只有一条向右的路径，答案为 2。节点值不参与深度计算，重复值和负数都不会改变算法。

考查点

  • 明确函数含义：maxDepth(node) 返回以 node 为根的子树深度，而不是该节点距离原树根的距离。
  • 找到递归终点：空节点贡献零层，不能返回一。
  • 正确合并子问题：最长路径只选择一侧，不能把左右深度相加。
  • 说明隐藏成本：递归调用占用栈空间，树退化成链时尤其需要注意。

Java 代码

以下使用题目提供的 TreeNode 类型，其 left、right 字段分别指向左右孩子。

class Solution {
    public int maxDepth(TreeNode root) {
        if (root == null) {
            return 0;
        }

        int leftDepth = maxDepth(root.left);
        int rightDepth = maxDepth(root.right);
        return 1 + Math.max(leftDepth, rightDepth);
    }
}

不需要全局最大值，也不需要额外传入当前层数。每次调用把自己的答案交给父节点即可。

文字推导与正确性

从最小的树倒推

先放一棵空树：没有节点可数，所以深度是 0。

再放一个叶子节点：它的左右孩子都是空树，两个子问题都返回 0，加上自己这一层，结果就是 1。这一步也检查了代码有没有把节点数误写成边数。

当前节点只负责选更深的一边

从当前节点出发走向某个叶子，下一步只能进入左子树或右子树。假设左右子树深度分别为 L、R，能走到的最深位置就是更深的那一侧，再加上当前节点：

depth(node) = 1 + max(L, R)。

示例中的节点 20 收到两个叶子各自返回的 1，于是返回 2；根节点收到左边的 1 和右边的 2，最终返回 3。

把 max 改成加法会把两条不同分支拼起来，那就不再是一条根到叶子的路径。

为什么整棵树都算对了

空树的返回值符合定义。假设两个更小的子树已正确返回深度，那么所有从当前节点出发的根到叶路径，都属于“走左边”或“走右边”之一。取两者最大值再加当前节点，恰好覆盖最长路径。

因此从空树开始逐层向上合并，根节点得到的就是整棵树的最大深度。执行过程是先向下调用，再从叶子向上返回答案。

复杂度和边界

设节点数为 n，树高为 h。

  • 时间复杂度 O(n)：每个节点只处理一次，每次只做常数次比较和加法。
  • 额外空间 O(h)：来自同时尚未返回的递归调用。平衡树通常为 O(log n)，单链树最坏为 O(n)。
  • 空树、单节点、仅有左孩子或右孩子都由同一递推式处理，不需要补丁分支。
  • 节点值不做运算，因此不会因负值、重复值或节点值极大而溢出。返回值只与节点数相关；在题目规模下使用 int。

栈深度是递归实现的实际限制。 对非常深的退化树，Java 可能抛出 StackOverflowError，不能仅凭时间复杂度合格就保证运行安全。

如果输入深度不可控，可以改用队列做层序遍历：每轮先记住当前队列长度，只处理这一层的节点，再把深度加一，直到队列清空。时间仍为 O(n)，额外空间为 O(w)，w 为最大层宽；不要把这种队列空间误写成 O(h)。

面试时忘记怎么办

先别背代码，画“空树”和“只有根节点”两个例子，把返回值定为 0 和 1。

然后问自己：“左右子树如果已经报出各自深度，根还需要做什么？”答案只能是选更深的一边，再算上自己。这样就能重新写出递推式与递归终止条件。

可以这样说明：

我让函数返回当前子树的深度。空树返回零，非空树返回左右深度最大值加一。每个节点访问一次，时间是 O(n)，调用栈是 O(h)；若树可能很深，我会换成层序遍历，避免依赖递归栈。

最后用单链树检查答案是否等于节点数，用左右都存在的树检查自己有没有误把两边相加。

一句话总结

先约定“空树深度为零”，再让每个节点把“较深子树的答案加一”交给父节点。
