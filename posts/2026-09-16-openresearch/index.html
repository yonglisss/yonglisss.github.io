让 AI 查论文、改代码并不难，难的是并行探索之后还能回答：哪个假设有效、结果对应哪版代码、过程能否复现。今天登上 GitHub 热门榜的 OpenResearch，瞄准的正是这段“研究过程管理”。它把 Claude Code、Codex、OpenCode、Cursor 等编程 Agent 放进本地优先的研究工作区，用 Git 记录实验，而不是只保留一段聊天。

📌 这个项目是干什么的

OpenResearch 面向需要文献调研、提出假设、运行实验和整理产物的研究者与研发团队。每条探索方向可进入独立 Agent 会话和 Git worktree，避免多个任务互相覆盖；实验变体组织在 Git 原生的树中，每次运行关联固定提交、日志、差异、文件和结果。

它不是新的基础模型，也不替你判断研究结论，而是给现有编程 Agent 增加并行执行、过程留痕和复现实验的工作层。项目采用 MIT 许可证，目前最新版本为 2026 年 9 月 16 日发布的 v0.2.3。

🔍 为什么值得关注

第一，解决的是 Agent 研究的可追溯性。 一次“跑成功”不等于可以复现。把提示、代码变更、实验结果与提交绑定，比把过程散落在聊天记录里更适合长期项目。

第二，并行探索有明确隔离边界。 Git worktree 让不同假设各自在独立工作区推进，适合比较算法、参数或实现路线，也降低 Agent 同时改同一目录造成冲突的概率。

第三，本地模型路径较完整。 官方文档说明可通过 OpenCode 连接 LM Studio、oMLX、Ollama 或兼容 OpenAI API 的本地服务；模型连接信息保存在本地数据目录，不会改写已有 OpenCode 配置。

🧪 谁适合试，怎么开始

它更适合计算机科研、数据实验和需要保留证据链的工程探索；只想问答或偶尔查资料，不必额外引入这套工作流。

macOS 或 Linux 可按官方方式安装并启动：

curl -LsSf https://openresearch.sh/install.sh | sh
orx up

启动后访问本机 127.0.0.1:4791。第一次建议只建一个小实验：让两个独立会话验证同一问题的不同方案，再检查提交、日志和产物是否足以复现，不要直接迁移重要项目。Windows 目前为 Beta，需先安装 Git for Windows。

⚠️ 使用提醒

“本地优先”不等于完全离线：论文检索、GitHub 操作、下载和 Agent 命令仍可能联网。本地模型还需要支持工具调用，并匹配实际上下文长度。安装脚本执行前应先审阅内容；涉及未公开论文、数据集或密钥时，也要核对所选 Agent、模型服务和外部工具各自的数据边界。项目版本仍处于 0.x，关键研究流程应保留独立备份与人工复核。
