Reasonix：让长时间编码 Agent 更容易控制和回退

让代码 Agent 连续工作并不难，难的是运行数小时后仍能看懂它做了什么，并在走偏时安全撤销。Reasonix 是一个 MIT 开源的本地编码 Agent：核心引擎用 Go 编写，可通过终端、桌面端、浏览器或支持 ACP 的编辑器使用，重点解决长任务中的上下文、权限与恢复问题。

📌 这个项目是干什么的

Reasonix 把模型、工具和插件写进 reasonix.toml，DeepSeek 只是预设，也可接入兼容 OpenAI API 的服务。它支持把规划模型与执行模型拆成两个相对稳定的会话，并在工具输出变旧后进行裁剪、压缩上下文，降低长对话不断膨胀的问题。

项目还提供计划模式、工具调用审批、工作区沙箱与逐轮检查点。也就是说，Agent 可以持续修改项目，但使用者仍能查看过程、限制权限，并按检查点回退，而不是只能接受最终结果。

🔍 为什么值得关注

第一，它没有把“自主运行”等同于“无限授权”。权限确认、任务暂停策略和检查点都有独立文档，适合借鉴到企业内部 Agent 工作流。

第二，同一套本地引擎覆盖 CLI/TUI、桌面端和 VS Code。编辑器扩展通过 ACP 启动本地 reasonix acp 后端，模型配置与工作区会话不必绑定在某个界面里。

第三，扩展边界较清楚：MCP 可提供工具、提示词和资源，Extension Protocol 边车还能监听运行事件、增加 Provider 与结构化界面。它更像可组合的 Agent 引擎，而非只包装一个模型聊天窗口。

🧪 谁适合试，怎么开始

适合经常做跨文件重构、测试修复或长时间代码任务，并愿意自己配置模型服务的开发者。CLI 最短路径是：

npm i -g reasonix
reasonix setup
cd /path/to/project
reasonix

先在可回滚的测试仓库运行 /init，再交给它一个有明确验收条件的小任务；确认审批、检查点和恢复流程可用后，再逐步增加任务时长。macOS 也可通过 Homebrew 安装，桌面端另有官方安装包。

⚠️ 使用提醒

“工作区沙箱”和检查点不能替代操作系统级隔离。模型仍会读取文件、调用工具并产生 API 费用，敏感项目应使用最小权限凭据、独立 worktree 或容器。VS Code 扩展不内置 CLI，需要先安装 Reasonix。项目更新频繁，正式接入前建议固定版本；截至 8 月 8 日，桌面端最新稳定 Release 为 v1.21.3，并提供多平台安装包与校验信息。
