浏览器自动化常卡在两个细节：独立浏览器没有登录态，接管日常浏览器又可能与用户争抢标签页。ego lite 提供了一款可由外部 Agent 操作的浏览器，让任务在隔离的 Space 中运行，同时复用用户主动迁移的 Chrome 登录、Cookie、扩展和书签。它当天进入 GitHub 总榜，值得经常用 Codex、Claude Code 处理网页任务的开发者关注。

📌 这个项目是干什么的

  • 由 ego lite 浏览器与 ego-browser Skill 组成，Agent 可调用 snapshot、fill、click、navigate 等 JavaScript 工具。
  • 每个 Agent 或任务使用独立 Space；用户仍可正常浏览，也能接管或停止任务。
  • 当前仅支持 macOS，Apple Silicon 与 Intel 均有安装包；Windows、Linux 仍在路线图中。
  • 仓库采用 MIT 许可证，最新正式 Release 为 v1.2.5。

🔍 为什么值得关注

它把“共享登录态”和“隔离工作区”放进同一套交互。整理后台数据、录入表单、跨站检索等必须登录的任务，不再需要频繁扫码或手工复制 Cookie。

ego-browser 也不绑定某个内置助手，而是给 Codex、Claude Code、Cursor 或自定义 Agent 提供连接层。Agent 可用脚本组合多步网页操作，减少反复调用工具、读取结果再继续的往返。官方给出了与 agent-browser 的四项任务对比，但“最高 2.5 倍更快”等数据来自项目方测试，应视为参考，而非通用结论。

🧪 谁适合试，怎么开始

适合使用 macOS、已有 Agent CLI，并经常处理登录后网页任务的开发者。最短路径是先安装 Skill：

npx skills add citrolabs/ego-lite

首次运行任务时再按引导安装应用。建议从公开页面提取表格等低风险流程开始，确认快照、点击和输入稳定后，再尝试登录后的业务系统。

⚠️ 使用提醒

迁移 Chrome 数据意味着 Agent 可能接触真实账号。不要先从支付、企业后台或敏感页面测试；应使用低权限账号，并为提交、删除、发送等操作保留人工确认。

还要看清开源边界：MIT 许可证覆盖仓库内容，README 明确说明浏览器本体是单独提供的免费下载，并不等于安装包以同样方式开源。Linux、Windows 用户目前也无法使用完整方案。
