环形链表：为什么快慢指针一定能相遇

题意和示例

给定单链表的头节点 head，判断沿着 next 走下去，是否会再次访问同一个节点。有环返回 true，否则返回 false；不要求找出环的入口，也不修改链表。

例如，节点依次为 3 → 2 → 0 → -4，最后一个节点又指回值为 2 的那个节点，结果是 true。如果最后一个节点指向 null，结果就是 false。

注意区分“值相同”和“同一个节点”：两个不同节点都存着 2，并不能说明有环。题目示例中有时用 pos 表示尾节点连回的位置，那只是描述链表的方式，不是方法参数。

考查点

  • 能否从“重复访问节点”想到用集合记录节点，再进一步省去集合。
  • 能否解释速度差为什么保证相遇，而不只背出快慢指针模板。
  • 能否正确处理空链表、自环，以及快指针走两步时的空指针风险。
  • Java 中用 == 比较节点引用，而不是比较 val。

Java 代码

下面使用题目提供的 ListNode 类型，其 next 字段指向下一个节点。两个指针都从头节点出发，但必须先移动，再判断是否相遇。

public class Solution {
    public boolean hasCycle(ListNode head) {
        ListNode slow = head;
        ListNode fast = head;

        while (fast != null && fast.next != null) {
            slow = slow.next;
            fast = fast.next.next;

            if (slow == fast) {
                return true;
            }
        }

        return false;
    }
}

文字推导与正确性

先建立一个容易证明的基线

沿链表前进，把访问过的节点放进集合。碰到已经访问过的节点，就存在环；走到 null，就没有环。这能解决问题，但需要额外保存节点。

快慢指针把“保存全部历史”换成“让两次遍历互相追赶”：slow 每轮走一步，fast 每轮走两步。

无环为什么不会误报

无环时，每个节点在从头开始的路径上只出现一次。移动完成后，快指针走过的边数是慢指针的两倍，两者不可能停在同一个非空节点。

最终 fast 或 fast.next 为 null，循环结束，返回 false。循环中的短路判断保证访问 fast.next.next 前，前两层引用有效；两步之后得到 null 是允许的。

只要循环还能执行，慢指针也能安全前进一步：在无环路径上，它不会先于快指针到达末尾；有环时则不会走到末尾。

有环为什么一定相遇

设入环前有 a 个节点，环长为 c。慢指针走进环后，快指针也已经在环中。

此后只考虑环上的位置。每轮快指针比慢指针多走一步，所以二者的相对位置每轮变化一格，并按环长取模。至多再经过 c 轮，相对位置就会变成零，也就是指向同一个节点。

因此，有环时算法一定返回 true，而不是靠运气碰面。这里每轮恰好多走一步很重要，不必借助“快指针经过慢指针时就算相遇”这样的模糊解释：代码只比较每轮结束的位置，距离取模的推导已经足够。

为什么不能在移动前直接比较

初始化时 slow == fast，即使是普通的无环链表也成立。这只是因为两者从同一个起点出发，不是发现了重复路径。

先移动、后比较，才能排除这种初始重合。单节点自环同样能正确识别：第一次移动后两个指针仍指向该节点，返回 true。

复杂度和边界

令 n 为从头节点可达的不同节点数。

  • 时间复杂度为 O(n)。无环时快指针到达末尾；有环时，慢指针先走过入环前的路径，再用至多一个环长完成相遇。
  • 额外空间复杂度为 O(1)，只保存两个节点引用。
  • 空链表、单节点且无环：循环不执行，返回 false。
  • 单节点自环、尾节点连回头部、尾节点连回中部：都能识别。
  • 重复值、负数值不影响结果；算法不对节点值做运算，也没有数值求和导致的溢出问题。
  • 不要用固定循环次数猜测有环，也不要通过断开 next 来标记访问状态，这会引入错误或修改输入。

面试时忘记怎么办

先把集合方案讲完整：“我记录访问过的节点引用，再遇到同一个节点就说明有环。”这是一个可验证的正确起点，不必一上来强背最优解。

接着问自己：“如果不保存历史，能否让一个遍历追上另一个遍历？”由此引出每轮一步和两步的两个指针。

证明时只抓两个分支：无环一定走到空；有环时二者都进入环，相对位置每轮变化一格，至多一个环长后重合。最后补上 O(n) 时间、O(1) 额外空间。

写代码前再确认三件事：比较节点引用、先移动后比较、循环条件检查 fast 和 fast.next。这比记住整段模板更不容易出错。

一句话总结

快慢指针判环的依据不是“跑得快就会追上”，而是进入环后相对位置每轮变化一格，必然走到重合的位置。
