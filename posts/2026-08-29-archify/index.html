Archify：让 AI 画出的架构图更漂亮，也更可核验

让编码 Agent 画架构图并不难，难的是图中关系是否来自代码、修改后能否稳定复现，以及能不能直接拿去评审。Archify 是一个面向 Cursor、Claude Code、Codex CLI、OpenCode 等工具的 Agent Skill：Agent 先生成带类型的 JSON 中间表示，再由本地程序校验并编译成可交互的 HTML/SVG。它今天进入 GitHub Trending，适合正在把 AI 引入架构梳理和技术评审的团队关注。

📌 这个项目是干什么的

Archify 支持 Architecture、Workflow、Sequence、Data Flow 和 Lifecycle 五类技术图。输入可以是代码仓库，也可以是一段系统描述；输出除了独立 HTML，还可导出 PNG、SVG、WebM 和分享卡片。

它与普通“文本生成图片”工具的区别，在于把内容与渲染拆开：组件、关系、边界和来源先写入 Typed JSON IR，再经过 Schema、布局、线路、标签等检查。原始 JSON 会保留，因此后续可以在对话中只改 Redis、鉴权位置或回滚路径，而不是重新生成一张不可控的图片。

🔍 为什么值得关注

第一，图不只用于展示，还能辅助评审。Archify 可比较两份已校验的架构快照，生成 Before / Delta / After，区分新增、删除、语义变化、移动和重路由。

第二，它对“可信”保持克制。仓库关联图可记录特定 revision 和源码位置，但项目明确不会把作者写入的连线包装成真实运行时影响分析，也不会自动判断风险、合并安全性。

第三，交付形态实用。生成物是自包含文件，搜索节点、查看上下游和演示路径都可在浏览器完成，适合放进设计评审、README 或版本说明。最新稳定版 v2.15.0 还加入品牌标识支持，并继续强化校验与跨平台安装检查。

🧪 谁适合试，怎么开始

它更适合开发者、架构师，以及需要维护系统文档的研发团队。最短路径是先安装 Skill：

npx skills add tt-a1i/archify -g

然后让 Agent 分析一个熟悉的小仓库，例如：“使用 archify 生成高层运行时架构图，只保留 8～12 个核心组件，突出主要路径和信任边界。”先把结果与代码逐项核对，再尝试 Sequence 或架构快照对比。官网的 Proof Lab 提供 11 个带 JSON 源和校验回执的示例，可先用来判断成品是否符合团队需求。

⚠️ 使用提醒

“通过结构校验”不等于“架构事实正确”。如果 Agent 漏读动态配置、基础设施或跨仓库调用，图仍可能不完整；关键评审必须由熟悉系统的人确认。仓库目前开发版本与稳定 Release 并存，团队使用时应固定版本，并保存 Typed Source 与代码 revision。项目采用 MIT 许可证，但图中引用的品牌素材和代码仓库仍需遵守各自授权。
