Open Code Review：把 AI 代码审查从“聊天建议”变成可控流程

通用编码 Agent 也能审查代码，但遇到大改动时，常见问题是漏文件、评论位置漂移，以及输出质量随提示词变化。阿里巴巴开源的 Open Code Review（OCR）提供了更工程化的选择：用确定性流程控制审查范围、文件分组和规则匹配，再让 LLM 负责理解上下文与判断缺陷。

通用编码 Agent 也能审查代码，但遇到大改动时，常见问题是漏文件、评论位置漂移，以及输出质量随提示词变化。阿里巴巴开源的 Open Code Review（OCR）提供了更工程化的选择：用确定性流程控制审查范围、文件分组和规则匹配，再让 LLM 负责理解上下文与判断缺陷。

📌 这个项目是干什么的

Open Code Review 是一款 AI 代码审查 CLI。它读取 Git diff，让可配置的模型结合完整文件、代码搜索和其他变更文件生成行级评论；也支持 ocr scan，直接扫描整个仓库、目录或指定文件。

它不只面向个人本地检查。官方还提供 GitHub Actions、GitLab CI、Gerrit 等集成方案，并可接入 Claude Code、Codex、Cursor 等编码 Agent。项目采用 Apache-2.0 许可证，支持 Windows、macOS 和 Linux；当前正式版为 v1.12.0。

🔍 为什么值得关注

第一，流程约束比“再写一段更长的提示词”更可靠。 OCR 先确定需要审查的文件，把相关文件组成独立任务，并按文件特征匹配规则；模型专注于动态取上下文和判断问题。这种混合架构更适合需要稳定覆盖率的团队流程。

第二，审查结果可以进入现有工程链路。 除了终端输出，它还能把结果保存为 JSON，方便交给其他 Agent 或 CI 继续处理。审查中断后也能通过 session 恢复，不必从头消耗模型调用。

第三，官方公开了评测方法。 项目使用 50 个开源仓库、200 个真实 PR 和 10 种编程语言构建基准，并明确说明其策略偏向精确率、召回率相对更低。这个取舍很重要：它更希望减少误报，但不能替代完整测试和人工审查。基准结果仍属于项目方测试，落地前应在自己的代码库复测。

🧪 谁适合试，怎么开始

它适合经常审查 PR、维护多语言仓库，或想把 AI 审查接入 CI 的开发者和团队。先确认 Git 版本不低于 2.41，然后安装：

npm install -g @alibaba-group/open-code-review

接着运行 ocr config provider 和 ocr config model 配置模型，在一个熟悉的小仓库里执行 ocr review。建议准备几个人工确认过的问题，对比漏报、误报、耗时和 token 成本，再决定是否进入 CI。若不想单独配置模型，可查看 Delegation Mode，让现有编码 Agent 执行模型部分。

⚠️ 使用提醒

代码可能被发送到所配置的模型服务，私有仓库必须先核对数据保留、权限和合规策略。AI 评论也不是质量结论：低召回意味着真实问题仍可能漏过。更稳妥的定位，是把它作为测试、静态分析和人工审查之前的增量检查层，而不是审批替代品。
