搜索旋转排序数组：先认出有序的一半，再决定往哪找

题意和示例

一个元素互不相同的升序整数数组，被从某处切开，再把前一段接到末尾。给出旋转后的 nums 和整数 target，返回目标的数组下标；找不到返回 -1。数组也可能保持原来的升序排列。

例如，nums = [4, 5, 6, 7, 0, 1, 2]：

  • target = 0，返回 4。
  • target = 3，返回 -1。

要求时间复杂度为 O(log n)。这里的关键前提是元素不重复，不是“可以任意打乱后再查找”。负数不会改变算法判断。

原题：搜索旋转排序数组。

考查点

  • 不依赖整个数组有序，而是找到当前区间中能可靠比较的一半。
  • 区分“这一半有序”和“目标在这一半”，两个条件缺一不可。
  • 统一使用闭区间 [left, right]，让退出条件和边界移动对应起来。
  • 解释为什么判断左半有序必须使用 <=，而不是只记住代码。

Java代码

先检查中点是否命中，再判断有序的一侧。中点既然已经排除，后面的搜索就不需要保留它。

class Solution {
    public int search(int[] nums, int target) {
        int left = 0;
        int right = nums.length - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] == target) {
                return mid;
            }

            if (nums[left] <= nums[mid]) {
                // 左半有序：检查目标是否在它的取值范围内。
                if (nums[left] <= target && target < nums[mid]) {
                    right = mid - 1;
                } else {
                    left = mid + 1;
                }
            } else {
                // 左半跨过旋转断点，因此右半有序。
                if (nums[mid] < target && target <= nums[right]) {
                    left = mid + 1;
                } else {
                    right = mid - 1;
                }
            }
        }
        return -1;
    }
}

文字推导与正确性

1. 二分需要的不是“全局有序”，而是“能安全排除一半”

直接根据 target < nums[mid] 向左走会出错。例如示例中点值为 7，目标 0 比它小，却在它右边。

旋转数组至多有一个下降断点。以中点划分后，左右两半不可能同时跨过这个断点，所以至少一半有序。我们先认出这一半，再决定保留哪边。

2. 先判断左半，再检查目标的取值范围

在元素互异的前提下，nums[left] <= nums[mid] 表示 [left, mid] 有序。若目标满足 nums[left] <= target < nums[mid]，只能继续搜索左侧；否则左半可以整体排除。

如果左半无序，那么 [mid, right] 必然有序。此时检查 nums[mid] < target <= nums[right]：满足就向右，否则向左。

为什么在中点处用严格不等号？因为开头已经判断过中点是否命中。两端的 left、right 尚未排除，因此范围判断仍包含它们。

3. 用一轮具体搜索检查判断顺序

对于 [4, 5, 6, 7, 0, 1, 2] 和目标 0：

  1. 初始中点下标为 3，值为 7。左半 [4, 5, 6, 7] 有序，但 0 不在它的取值范围，令 left = 4。
  2. 当前区间是下标 [4, 6]，中点值为 1。左半 [0, 1] 有序，目标在其中，令 right = 4。
  3. 剩下下标 4，命中并返回。

判断某一侧有序，不意味着一定往那一侧走；它只是提供了一个可以准确判断归属的范围。

4. 为什么不会丢掉答案？

维护不变量：如果目标存在且尚未找到，其下标一定在 [left, right] 内。

初始区间覆盖整个数组。每轮先处理中点命中；未命中时，有序侧的值域能准确判断目标是否可能在该侧。元素互异保证另一侧不会藏着相同值，因此每次排除的区间都不含目标，不变量继续成立。

每轮移动边界都会排除中点并缩小区间。如果最终 left > right，候选区间为空，说明目标不存在，返回 -1。

复杂度和边界

每轮最多保留原区间的一半，时间复杂度为 O(log n)；只保存三个下标，额外空间为 O(1)。

  • 单元素：先比较中点，命中返回 0，否则退出返回 -1。
  • 两元素：mid 可能等于 left，此时左半只有一个元素，仍然有序。这正是 nums[left] <= nums[mid] 需要等号的原因。用 [3, 1] 搜索 1 可以检查这一点。
  • 未旋转、目标在端点、目标不存在：沿用同一套闭区间规则，不需要特殊分支。
  • 负数与极端整数：只比较元素，不对元素做减法；中点使用 left + (right - left) / 2，避免直接相加下标。
  • 空数组：虽然不是本题通常讨论的输入，代码也会直接返回 -1。null 不在方法输入契约内。
  • 重复值：不属于本题条件。比如 [1, 0, 1, 1, 1] 中，端点相等不能证明左半有序；不能把这份代码直接当作允许重复值的版本。

面试时忘记怎么办

先写普通二分的闭区间骨架，只保留“中点命中就返回”。然后问自己：当前哪一侧能用两个端点判断目标归属？

不要同时背四个边界更新。先推导左半有序的分支：目标落在 [nums[left], nums[mid]) 内就向左，否则向右。再把右半的对称分支补全。

最后用 [3, 1] 搜索 1 检查 <=，用 [1] 搜索不存在的值检查区间能否退出。讲正确性时说明“每轮排除的一半为什么不可能有答案”，比只说“这是二分模板”更有说服力。

一句话总结

先用有序的一半确定目标的归属，再排除不可能包含答案的区间，旋转就不会破坏二分的效率。
