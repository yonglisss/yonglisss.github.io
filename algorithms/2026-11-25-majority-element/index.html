数组 · 投票法 · Boyer-Moore

多数元素：票数归零，为什么可以换候选人？

题意和示例

给定非空整数数组 nums，返回其中出现次数严格超过数组长度一半的值。题目保证这个值存在，因此答案唯一。

例如 [2, 2, 1, 1, 1, 2, 2] 返回 2：数组有七项，2 出现四次。[3, 2, 3] 返回 3。

注意，“出现最多”和“超过一半”不是一回事。[1, 1, 2, 3] 中 1 最多，却没有多数元素；这样的输入不属于本题范围。

原题：LeetCode 169 · Majority Element。

考查点

  • 能否利用“严格超过一半”这个强条件，而不是直接记录所有值的频次。
  • 能否说明两个不同的数为什么可以一起删除。
  • 能否区分候选人的剩余票数与它在整个数组中的出现次数。
  • 能否说清楚：题目不保证答案存在时，一遍投票还不够。

Java 代码

两个变量就能模拟抵消：candidate 保存尚未被抵消的值，votes 保存剩余数量。

class Solution {
    public int majorityElement(int[] nums) {
        int candidate = 0;
        int votes = 0;

        for (int num : nums) {
            if (votes == 0) {
                candidate = num;
            }
            if (num == candidate) {
                votes++;
            } else {
                votes--;
            }
        }
        return candidate;
    }
}

candidate 初始为 0 只是为了满足局部变量初始化要求，不代表默认答案。非空数组的第一个元素一定会在 votes == 0 时覆盖它。

文字推导与正确性

先想：删掉哪两个元素不会改变答案？

设多数元素为 M，它的数量大于所有非 M 元素的数量之和。每次取两个不同的值一起删除，有两种情况：

  • 一个是 M，另一个不是：两边数量同时减一，M 的数量优势不变。
  • 两个都不是 M：只有其他元素变少，M 的优势反而扩大。

因此，只要不断删除不同值组成的数对，M 就仍是剩余序列中的多数元素，也不可能被全部删光。这里依赖的是“比其余所有元素加起来还多”，不是仅仅比某一种元素多。

两个变量怎样代替真实删除？

处理过的前缀可以看成两部分：已经抵消掉的不同值数对，以及 votes 个相同的 candidate。

遇到同值就把它放进剩余部分，票数加一；遇到异值，就拿它与一个候选值配对删除，票数减一。当票数为零，前缀已经全部配成数对，可以用下一个数开启新的剩余部分。

所以，换候选人不是断言旧候选人绝不可能成为答案，而是当前没有未抵消的值需要保留。旧候选人之后仍然可能被重新选中。

用一次归零检查更新顺序

对 [2, 2, 1, 1, 1, 2, 2]，每步结束后的 (candidate, votes) 是：

读入 2 → (2, 1)
读入 2 → (2, 2)
读入 1 → (2, 1)
读入 1 → (2, 0)
读入 1 → (1, 1)
读入 2 → (1, 0)
读入 2 → (2, 1)

票数归零的那一步已经消耗当前元素；到下一步才用新元素重选。代码先检查零票、再计入当前值，正好实现这个过程。

扫描结束时，已经删除的都是异值数对，剩下的只有候选值。由于多数元素不可能消失，最终候选值只能是它。返回的是候选值，而不是票数；上例最终票数为一，但答案实际出现四次。

复杂度和边界

  • 时间复杂度 O(n)：每个元素只访问一次。
  • 额外空间 O(1)：只维护两个整数，不修改输入数组。
  • 单元素数组直接返回该值；全部相同也无需特殊处理。
  • 负数、零、重复值都按相等关系处理，不需要排序或数值运算。
  • votes 最大为数组长度，在 Java 数组长度可表示的范围内不会溢出；元素本身也不参与加减，因此极端 int 值不会造成算术溢出。
  • 空数组不符合题设。若用于业务接口，应先定义空输入的错误或返回语义，不能把初始化的 0 当成有效答案。

如果取消“多数元素一定存在”的保证，必须再遍历一次，统计候选值的真实次数，并检查 occurrences > nums.length / 2。失败时返回什么，要由接口约定。否则 [1, 2, 3] 也会产生一个候选值，却不是合法答案。

面试时忘记怎么办？

先交付一个可靠基线：“我可以用哈希表计数，时间 O(n)、空间 O(n)。”不要在忘记算法名时停住。

再从条件找优化：“多数元素比其他所有数加起来还多，那么删掉一对不同的数，它仍然占多数。”沿着这句话，就能推导出只保留一个值与剩余票数。

写代码前口述规则：“零票先选当前值；同值加一，异值减一。”拿 [2, 1, 2] 手推，确认归零后下一项能重新成为候选人。

最后补前提：“一遍投票直接返回，依赖答案必然存在；否则还要计数验证。”这比只背出 Boyer-Moore 的名字更能说明理解。

一句话总结

投票法不是猜出现最多的数，而是删掉所有能抵消的异值数对，让严格多数留下来。
