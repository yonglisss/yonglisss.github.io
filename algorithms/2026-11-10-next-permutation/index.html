下一个排列：为什么交换之后只需反转后缀

题意和示例

给一个非空整数数组，把其中的元素重新排列，得到字典序中紧接着当前数组的那一种排列。必须直接修改输入数组，只使用常数额外空间。元素可以重复，并不是只能处理互不相同的数字。

字典序的比较方法是：从左往右找第一个不同的位置，该位置的数更大，整个排列就更大。如果当前已经是最大的排列，则回到最小排列。

  • [1, 2, 3] 变为 [1, 3, 2]。
  • [1, 3, 2] 变为 [2, 1, 3]，不是 [2, 3, 1]，因为后者跳过了一个更小的候选。
  • [3, 2, 1] 变为 [1, 2, 3]。
  • [1, 1, 5] 变为 [1, 5, 1]。

原题：LeetCode 31：Next Permutation。

考查点

这题不是让你枚举全排列，而是让你利用字典序的优先级：左边尽量不动，必须增大的那一位尽量少增大，剩下部分尽量小。

需要掌握三个细节：从右侧定位非递增后缀；在后缀里选出严格更大的最小元素；证明交换之后后缀仍然非递增，因此不用排序。

Java 代码

方法没有返回值，答案保存在原数组中。输入按题意保证非空、非 null。

class Solution {
    public void nextPermutation(int[] nums) {
        int pivot = nums.length - 2;
        while (pivot >= 0 && nums[pivot] >= nums[pivot + 1]) {
            pivot--;
        }

        if (pivot >= 0) {
            int successor = nums.length - 1;
            while (nums[successor] <= nums[pivot]) {
                successor--;
            }
            swap(nums, pivot, successor);
        }

        int left = pivot + 1;
        int right = nums.length - 1;
        while (left < right) {
            swap(nums, left, right);
            left++;
            right--;
        }
    }

    private void swap(int[] nums, int i, int j) {
        int value = nums[i];
        nums[i] = nums[j];
        nums[j] = value;
    }
}

文字推导与正确性

1. 哪个位置必须改变？

以 [1, 4, 3, 2] 为例，后缀 [4, 3, 2] 已经按非递增顺序排列。固定开头的 1，无论怎样调整这个后缀，都无法得到更大的数组：它已经是这批元素的最大排列。

所以只能改变更靠前的位置。扫描时寻找最右侧满足 nums[pivot] < nums[pivot + 1] 的位置，这里就是开头的 1。它右侧必然是一个非递增后缀。

选择最右侧的可增大位置，是为了保留尽可能长的前缀。若先改变更左的位置，得到的更大排列一定不会是紧邻的那个。

2. 用哪个数替换它？

既然必须把 1 增大，就选右侧严格大于 1 的最小值，也就是 2。后缀是非递增的，从右往左找到的第一个严格更大的数，恰好就是这个值。

交换后得到 [2, 4, 3, 1]。前缀完成了最小幅度的增大，但后缀还不是最小排列。

这里不能使用“大于等于”：交换相同元素不会使数组增大。第一段扫描也必须跳过相等值，否则会把不能增大的位置误认为转折点。

3. 为什么反转就够了？

设转折点原值为 x，被选中的后缀元素为 y。由于从右往左选择第一个大于 x 的值，y 右边的数都小于等于 x；y 左边的后缀元素都大于等于 y。

把 y 换成 x 后，它左边的元素仍然不小于它，右边的元素仍然不大于它。也就是说，后缀依旧非递增。反转后就变成非递减，正是剩余元素能组成的最小后缀。

例子最终变成 [2, 1, 3, 4]。最右侧可增大的位置、最小的严格更大替换值、最小后缀，三者共同保证没有遗漏中间的排列。

4. 完全找不到转折点怎么办？

这说明整个数组非递增，已经是最大排列。此时 pivot 为 -1，代码从 pivot + 1 = 0 开始反转整个数组，直接回到最小排列，不进行交换查找。

复杂度和边界

  • 时间复杂度 O(n)：定位转折点、寻找替换值和反转后缀各自最多扫描一次数组。
  • 额外空间 O(1)：没有新建数组，也没有递归调用。
  • 单元素数组：pivot = -1，反转区间长度为一，数组保持不变。
  • 所有元素相同：没有严格上升位置，整体反转后仍然不变。
  • 重复值：必须按“非递增后缀”和“严格更大替换值”处理，例如 [1, 5, 1] 的下一项是 [5, 1, 1]。
  • 负数不影响比较逻辑。实现只比较和交换元素，不把数组拼成整数，也不计算元素之差，因此没有元素算术溢出问题。

面试时忘记怎么办

先写一个 [1, 4, 3, 2]，问自己：“只动末尾三个数，还能更大吗？”不能，就能找回从右侧寻找转折点的思路。

接着说明：“把转折点换成右侧刚好更大的数，再让剩下部分最小。”即使暂时没想起反转，也可以先想到把后缀排序，再利用后缀已有的非递增性质，将排序优化为反转。

最后核对两个比较符：找转折点时跳过 >=，找替换值时跳过 <=。用 [1, 1, 5] 和 [3, 2, 1] 手推一次，就能检查重复元素和回绕分支。

一句话总结

下一个排列不是随便找一个更大的排列，而是保留最长前缀、让一位最少增大，再把后缀压到最小。
