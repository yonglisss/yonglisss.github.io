两数之和：用哈希表记住走过的数字

题意与约束

给定一个整数数组和目标值，返回两个相加等于目标值的元素下标。同一个元素不能使用两次。原题保证恰好存在一个有效答案，返回下标的顺序不限。本文用自己的话概述题意，完整约束见 LeetCode 原题。

例如 nums = [2, 7, 11, 15]，target = 9，答案是 [0, 1]，因为 2 + 7 = 9。

从两层循环到一次遍历

最直观的方法是枚举每一对不同下标，时间复杂度 O(n²)。换一个问题：当前数字是 x，我需要的搭档就是 target − x。如果之前见过这个搭档，就能直接返回答案。

用哈希表记录“已经访问的数字 → 下标”。每一步先查询搭档，再保存当前数字。这个先后顺序能避免把同一个元素用两次，也能正确处理 [3, 3]、目标为 6 的情况。

逐步推导

  1. 初始哈希表为空。访问下标 0 的数字 2，需要的搭档是 9 − 2 = 7，表中没有 7。
  2. 把数字 2 和它的下标 0 存入哈希表。
  3. 访问下标 1 的数字 7，需要的搭档是 9 − 7 = 2，表中已有 2，对应下标 0。
  4. 返回下标 [0, 1]，因为 2 + 7 = 9，结束遍历。

Python 实现

def two_sum(nums, target):
    seen = {}
    for i, x in enumerate(nums):
        complement = target - x
        if complement in seen:
            return [seen[complement], i]
        seen[x] = i
    return []  # 扩展处理：输入不满足原题有解约束时

为什么正确

处理下标 i 之前，哈希表只含下标小于 i 的元素。如果命中搭档，两者下标必然不同，和也必然等于目标值。对任意有效答案，下标较大的元素被访问时，下标较小的搭档已经存入表中，所以不会漏掉答案。

复杂度与边界测试

哈希查询和插入平均为 O(1)，总时间平均 O(n)，额外空间 O(n)。这里使用平均复杂度，不把哈希操作视为无条件的最坏 O(1)。

  • [2, 7, 11, 15]，目标 9 → [0, 1]。
  • [3, 2, 4]，目标 6 → [1, 2]，答案不一定相邻于数组开头。
  • [3, 3]，目标 6 → [0, 1]，允许数值重复，但不能重复使用下标。
  • [-3, 4, 3, 90]，目标 0 → [0, 2]，负数不需要特殊分支。
  • [0, 4, 3, 0]，目标 0 → [0, 3]，零值也能正常匹配。

常见错误

先存入再查询会让 [3, 3] 在访问第一个 3 时错误地匹配自己。另一个误区是排序后直接返回排序后的下标：原题需要原数组下标，排序时必须额外保留位置。
