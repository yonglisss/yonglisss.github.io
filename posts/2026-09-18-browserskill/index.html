很多浏览器 Agent 要么启动一套全新环境，要么要求重新登录，遇到验证码、企业后台和个人工作流就容易卡住。腾讯开源的 BrowserSkill 提供了另一条路径：通过本地 CLI、守护进程和浏览器扩展，把支持 Shell 的 Agent 接入现有 Chrome 或 Edge，同时用独立窗口、标签借用和人工接管机制控制影响范围。

📌 这个项目是干什么的

BrowserSkill 不是新的通用 Agent，而是 Agent 与真实浏览器之间的桥接层。Agent 调用 bsk CLI，命令经本地 daemon 转发给扩展，再由扩展操作专用的 Agent Window。普通标签页不会自动交给 Agent；需要操作已打开页面时，必须显式借用，任务结束后归还。

它可以复用现有登录态，执行打开页面、读取内容、点击、输入、上传下载和截图等浏览器任务。遇到验证码、登录或确认弹窗时，Agent 还能请求人工接管。项目采用 MIT 许可证，支持 macOS、Linux 和 Windows；官方明确支持 Chrome、Edge，Firefox 尚在计划中。

🔍 为什么值得关注

第一，解决了真实登录态的断层。 自动化不必为每个网站重新准备账号，适合处理企业后台、内容运营和需要连续会话的网页任务。

第二，权限边界比“直接控制整个浏览器”更清楚。 新任务默认进入独立可见窗口，用户标签需要借用；同一会话的操作串行执行，结束时应主动停止 session。它不能消除误操作，但让可控范围更容易理解和检查。

第三，已经开始补齐工程化能力。 9 月 16 日发布的 0.3.0 增加了远程浏览器连接、长截图和可选操作审计。审计默认关闭，只记录脱敏后的操作元数据，不保存页面正文、截图、输入值或完整 DOM，适合回看 Agent 实际做过什么。

🧪 谁适合试，怎么开始

适合正在使用 Cursor、Claude Code、Codex、OpenClaw、Hermes Agent 等工具，并希望自动处理已登录网页的开发者和运营人员。建议先在低风险网站完成最小验证：安装 bsk CLI 与 Chrome/Edge 扩展，运行 bsk install-skill 和 bsk doctor，再让 Agent 打开 example.com、读取页面并停止 session。

不要一上来测试支付、删改数据或批量发布。先确认扩展连接、目标 harness 能发现 skill，并观察标签借用、人工接管和会话清理是否符合预期。

⚠️ 使用提醒

复用登录态也意味着 Agent 能触达真实账号权限。对付款、发送、删除、提交表单等不可逆动作，应保留人工确认，并使用最小权限账号。远程模式需要正确配置配对、凭据和 TLS；远程会话目前不支持文件上传下载。CLI、daemon 与扩展版本也要保持匹配，升级后应重新运行 bsk doctor。
