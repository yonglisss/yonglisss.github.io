合并两个有序链表：先接小的，再接剩下的

题意和示例

输入两条按非递减顺序排列的单链表，把它们的节点重新连接成一条同样有序的链表，返回结果的头节点。非递减允许相邻值相等，不能把重复节点丢掉。

例如，list1 = [1, 2, 4]，list2 = [1, 3, 4]，结果是 [1, 1, 2, 3, 4, 4]。

两条都是空链表时返回 null；只有一条为空时，可以直接返回另一条。本解法复用原节点，会改变输入链表的连接关系，不是复制出两份独立的数据。

原题链接：LeetCode 21：合并两个有序链表。以下按两条输入链表无环、节点不共享的常规题目模型讨论，不处理共享尾部的特殊输入。

考查点

  • 能否利用“已经有序”，只比较当前头节点，而不是收集所有值再排序。
  • 能否区分两个输入游标与结果尾指针：前者表示尚未处理的位置，后者表示下一个节点接在哪里。
  • 能否用虚拟头节点消除第一次插入的特殊分支，并在循环结束后接好剩余链表。

Java 代码

ListNode 由题目提供，包含 int val、ListNode next 和接收节点值的构造方法。循环条件要用 &&：只有两边都有节点时，才能比较值。

class Solution {
    public ListNode mergeTwoLists(ListNode list1, ListNode list2) {
        ListNode dummy = new ListNode(0);
        ListNode tail = dummy;

        while (list1 != null && list2 != null) {
            if (list1.val <= list2.val) {
                tail.next = list1;
                list1 = list1.next;
            } else {
                tail.next = list2;
                list2 = list2.next;
            }
            tail = tail.next;
        }

        tail.next = (list1 != null) ? list1 : list2;
        return dummy.next;
    }
}

文字推导与正确性

为什么只看两个头节点？

一条链表有序，就意味着它当前的头节点不大于后续任何节点。因此，两条剩余链表中最小的节点，必然出现在这两个头节点里。选出较小者，就能确定结果的下一个位置，无须往后搜索。

相等时选哪一边都不会破坏数值有序性。代码使用 <=，优先接第一条链表的节点；另一条的相等节点仍然保留，之后还会接入。

为什么需要 dummy 和 tail？

如果没有虚拟头节点，第一次接入时必须额外判断“结果头节点是否为空”。让 tail 从 dummy 出发，每一轮都执行同一种动作：接节点，再移动尾指针。最后返回 dummy.next，虚拟节点本身不属于答案，它的值取多少都不参与比较。

以示例的第一轮为例：先把第一条链表中的 1 接到 dummy.next，把 list1 移到 2，再把 tail 移到刚接入的 1。第二轮比较的是 2 和另一条链表的 1，不会再次处理同一个节点。

这里的“已完成结果”是从 dummy.next 到 tail 的前缀。tail.next 可能暂时仍指向该节点原来的后继，下一轮会按比较结果重新连接，不必每次主动断开。

为什么结果始终正确？

维持一个不变式：已选前缀有序，而且其中所有值都不大于两条剩余链表中的任何值。

开始时前缀为空，不变式成立。每一轮选择剩余节点的最小值，它不会小于已选前缀的末尾，也不会大于剩余节点；将其接入并移动相应输入游标后，不变式仍成立。

每一轮都会减少一个未处理节点，所以有限链表一定会结束循环。此时至少一条链表为空，另一条剩余部分本来有序，且所有值都不小于已选前缀的末尾，可以直接整段接上。最终每个原节点恰好出现一次，结果有序。

复杂度和边界

设两条链表长度分别为 m、n：

  • 时间复杂度为 O(m + n)，这是最坏情况上界；一条链表提前耗尽后，接入剩余部分只需一次指针赋值。
  • 额外空间复杂度为 O(1)，只新增一个虚拟节点和固定数量的引用。返回链表复用原节点。
  • 两边都为空：循环不执行，dummy.next 最终为 null。
  • 一边为空：直接接上另一边，不访问空引用的 val。
  • 重复值与全相等输入：只比较、不去重，因此所有节点都保留。
  • 负数和 int 极值：直接用 <= 比较，不做减法或累加，没有比较过程中整数溢出的问题。
  • 长度悬殊：不要遗漏循环之后的 tail.next，否则长链表的剩余节点可能丢失。

本解法不是保持输入不变的方案。若面试官要求保留原链表，应新建输出节点，并把额外空间改为 O(m + n)，不能继续声称原地复用。

面试时忘记怎么办？

先拿 [1, 4] 和 [2, 3] 手推：下一项依次选 1、2、3，然后把剩余的 4 接上。从这个过程还原代码，比背变量名可靠。

可以这样解释：“两条输入都已排序，所以剩余最小值只可能在两个头节点。我维护结果尾指针，每次接较小的头节点，并只推进被选中的那一条链表。”

写完一轮后，逐项检查三个动作：tail.next 接上了吗？被选输入向后走了吗？tail 自己向后走了吗？再检查循环后是否接上余段、返回的是否是 dummy.next。

若想起递归归并，也能解决这题，但调用栈最坏需要 O(m + n) 空间。要回答常数额外空间，使用这里的迭代写法。

一句话总结

有序链表归并只做两件事：两边都有节点时接较小者，一边耗尽后接上另一边的全部余段。
