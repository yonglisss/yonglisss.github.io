接雨水：比较左右最高挡板，确定一侧就结算

题意和示例

数组 height 表示一排宽度都为 1 的柱子，高度非负。雨水会从两端流走，求最终留在柱子之间的水量，而不是最大的一个水槽面积。

例如 [3, 0, 2, 0, 4]：两端挡板让中间三个位置分别留下 3、1、3 单位水，总量为 7。柱子本身占据的体积不能计入答案。

原题约束为 1 <= n <= 2 * 10^4、0 <= height[i] <= 10^5。标准示例 [0,1,0,2,1,0,1,3,2,1,2,1] 的结果是 6。

原题链接：LeetCode 42：接雨水。

考查点

  • 能否把总水量拆成每个位置的水量，而不是反复寻找凹槽。
  • 能否从左右最高值公式，推导出线性时间、常数额外空间的算法。
  • 能否解释“某一侧已经可以结算”，而不是只背诵移动较矮的一端。

这里比较的是两侧已经见过的最高挡板。下面采用这一版本，便于直接证明；不要把它的条件与比较当前柱高的另一种写法混用。

Java代码

class Solution {
    public int trap(int[] height) {
        if (height.length < 3) {
            return 0;
        }

        int left = 0;
        int right = height.length - 1;
        int leftMax = 0;
        int rightMax = 0;
        int answer = 0;

        while (left <= right) {
            leftMax = Math.max(leftMax, height[left]);
            rightMax = Math.max(rightMax, height[right]);

            if (leftMax <= rightMax) {
                answer += leftMax - height[left];
                left++;
            } else {
                answer += rightMax - height[right];
                right--;
            }
        }

        return answer;
    }
}

输入按原题约定为非空、非负整数数组；代码不修改数组，也不额外约定 null 的处理方式。

文字推导与正确性

先把一个位置算清楚

设 L[i] 是从左端到 i 的最高柱子，R[i] 是从 i 到右端的最高柱子，都包含当前位置。

那么 i 处的水量是 min(L[i], R[i]) - height[i]。两边较低的最高挡板决定水面高度；由于两个最大值都不低于当前位置，差值不会为负。

最直接的办法是每个位置向两边扫描，时间为 O(n²)。先存下前缀、后缀最大值，可以做到 O(n) 时间和 O(n) 额外空间。双指针则进一步省去这两张表。

为什么只用两个最大值就够了

每轮先更新最大值。此时 leftMax 是区间 [0, left] 的最大值，rightMax 是区间 [right, n-1] 的最大值；尚未结算的区间是 [left, right]。

如果 leftMax <= rightMax，左指针右方已经存在一根不低于 leftMax 的挡板。即使中间还有更高的柱子，也无法把左指针处的水面提高到 leftMax 以上，因为左侧最高挡板只有这么高。

所以左指针处的真实水量恰好为 leftMax - height[left]，可以计入答案后右移。反过来，若 leftMax > rightMax，就能确定右指针处的水量为 rightMax - height[right]，随后左移右指针。

两侧最大值相等时，两边都能结算；代码统一处理左边，避免分支重复。

用一个小例子检查更新顺序

对 [3, 0, 2, 0, 4]，右侧最高挡板始终足够高，左侧依次结算 0、3、1、3；最后一根高柱本身贡献 0，得到 7。

必须先把当前柱高纳入最大值，再计算水量。否则遇到更高的新柱时，会用旧水位减去新高度，错误地产生负贡献。

每轮恰好结算一个位置，且其水量已由上述条件确定。指针交错后没有遗漏，也没有重复累计，因此答案就是所有位置水量之和。

复杂度和边界

  • 时间复杂度 O(n)：每轮将未处理区间缩短一个位置。
  • 额外空间复杂度 O(1)：只维护指针、最大值和累加值。
  • 长度小于 3、全零、全部等高、单调升序或降序，答案都是 0。
  • 重复高度不需要去重，例如 [2, 0, 2] 结果为 2。两端都必须能挡水，不能只看某一边最高值。
  • 原题没有负数；若业务中允许负海拔，不能直接沿用最大值初始化为 0 的前提。
  • 原题范围内，最多只有 n-2 个内部位置蓄水，总量不超过 (n-2) * 10^5，小于 Java int 上限。若扩大数组长度或高度范围，应将累加器与返回值改为 long，并重新检查差值类型。

面试时忘记怎么办

先不要强行写双指针。拿 [2, 0, 2] 说明一个位置同时需要左右挡板，再写出 min(L[i], R[i]) - height[i]，把正确性基础讲清楚。

接着给出前后缀最大值数组的解法：它已经是线性时间，而且容易检查。若还有时间优化空间，再问：“哪一侧的最高挡板较低，能否不等另一侧全部扫描完就结算？”

最后明确循环不变量：左右最大值分别覆盖已经扫描的两端，每轮只结算有足够对侧挡板保证的位置。说完再补 O(n) 时间、O(1) 额外空间，比只说“短板效应”更完整。

一句话总结

接雨水不是猜凹槽，而是逐格结算：较低的已知最高挡板一侧，水量已经确定。
