让大模型回答一个数据问题并不难，难的是继续追问、比较不同分析路径，并看清结果从哪里来。微软开源的 Data Formulator 把自然语言、数据连接、转换过程和可编辑图表放进同一工作区。它今天进入 GitHub Trending，适合经常处理业务数据，又不想把分析过程压缩成一段聊天记录的人关注。

📌 这个项目是干什么的

Data Formulator 是微软研究院推出的 AI 数据探索与可视化工具。用户可以导入 CSV、TSV、Excel、JSON、截图或文本，也可以连接数据库和数据平台，再用自然语言提出分析需求。

它的重点不是“输入一句话，返回一张图”，而是用 Data Thread 保存问题、数据转换、解释和图表。你可以从较早的步骤创建分支，尝试另一种假设，而不必破坏原来的分析路径；图表也能继续编辑，最后整理成报告。

项目采用 MIT 许可证。当前稳定版为 0.7，0.8 beta 1 已提供预览；官方 README 明确支持 OpenAI、Azure、Ollama 和 Anthropic，底层通过 LiteLLM 接入模型。

🔍 为什么值得关注

第一，分析过程比单次答案更重要。 Data Thread 把追问与中间结果串在一起，还允许分支比较。对需要复核的数据分析来说，这比不断加长聊天上下文更容易追踪，也更适合向同事解释结论如何形成。

第二，它把“取数”和“画图”放进同一流程。 工具可以从文件开始，也能连接 MySQL、PostgreSQL、MSSQL、BigQuery、S3、Azure Blob 等数据源。加载计划可先由用户审核，再进入工作区，减少 Agent 在数据关系尚未确认时直接下结论的风险。

第三，结果不是不可修改的图片。 0.7 引入了 30 多种图表类型、样式优化 Agent，以及会话和工作区持久化。其图表能力建立在开源可视化语言 Flint 上，生成后仍能调整样式并组合成报告。

🧪 谁适合试，怎么开始

它更适合数据分析师、运营人员、产品经理，以及正在评估 AI 数据助手的开发团队。最短路径是先打开在线 Demo，用官方示例数据完成一次“提问—生成图表—创建分支—修改图表”的完整流程。

需要本地处理数据时，已安装 uv 的用户可直接运行 uvx data_formulator；也可以在虚拟环境中执行 pip install data_formulator，再运行 python -m data_formulator。建议先用脱敏 CSV 验证工作流，再考虑接入数据库。

⚠️ 使用提醒

0.8 beta 1 仍是预览版本，生产环境应优先评估稳定版 0.7。桌面构建目前未做代码签名或公证，只应从官方仓库的 workflow artifacts 或 release 下载。

接入真实业务数据前，还要确认模型供应商的数据处理政策、数据库账号的最小权限，以及生成 SQL、转换结果和图表结论是否经过人工复核。它降低的是探索门槛，不是数据治理与事实核验责任。
