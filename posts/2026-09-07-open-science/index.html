科研人员用 AI 做文献检索、数据分析和报告时，常在聊天窗口、Notebook、数据库与文件夹之间切换。真正麻烦的不是少一个对话框，而是结果出来后，很难回答“用了哪些输入、跑了什么代码、由哪次对话生成”。今日进入 GitHub Trending 的 AIPOCH Open Science，试图把这些环节放进一套可检查的桌面工作台。

📌 它能做什么

Open Science 是一款开源、local-first、模型无关的科研应用，支持 macOS、Windows 和 Linux。用户可以创建研究项目，让 Agent 读取文件、联网检索、调用科学数据源、运行 Python 或 R，再生成报告、表格和图像。

它比较有价值的设计是“来源记录”。生成物按不可变版本保存，并关联生产代码、执行历史、输入文件、环境信息和对应的对话分支；无法确认的证据会标记为缺失，而不是自动补全。研究者还可以修改较早的消息并创建新分支，在保留原路径的同时尝试另一种假设。

🔍 为什么值得关注

第一，它把可复现性放在 Agent 能力之前。 普通 AI 工具往往只交付答案，Open Science 则把命令、文件操作、连接器调用和产物放在同一项目里，方便复核过程，而不只是阅读一段看似合理的结论。

第二，它没有绑定单一模型。 首次配置可选择 Claude Code、OpenCode、Codex 或 CodeBuddy 等运行时，并连接内置模型服务、自定义网关或已有订阅。项目还提供科研 Skills、MCP 扩展，以及 PubMed、bioRxiv、ChEMBL、临床试验等连接器；具体目录应以安装版本为准。

🧪 谁适合试，怎么开始

它适合需要反复处理文献、数据和计算结果的研究者，也适合正在搭建 AI for Science 工作流的开发团队。最简单的试法不是立即导入敏感课题，而是准备一份公开数据和一个可核对的小问题：

  1. 从 GitHub Releases 下载对应系统的安装包；
  2. 配置模型，并按需启用 Python 或 R；
  3. 新建项目，写清目标、输入、约束和验收方式；
  4. 执行后检查工具记录、生成文件及 Provenance 页面，确认结果能否重现。

⚠️ 使用提醒

“本地优先”不等于完全离线。模型 API、网页搜索和科学数据库连接器仍可能把查询发送给外部服务，涉及未公开数据时应逐项检查权限、端点与数据政策。Agent 生成的分析也不能替代同行评审、统计检验或领域专家判断。

项目采用 Apache-2.0 许可证，当前最新稳定版为 v0.25.1，仍处于 0.x 阶段。建议先用非敏感数据验证稳定性，并对安装包做官方提供的校验，再考虑进入正式研究流程。
