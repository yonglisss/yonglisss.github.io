让编码助手改一个功能，它很快交出一批代码，却可能理解错需求、漏掉测试。Superpowers 是给编码 Agent 使用的开源技能与开发流程集合，不替换模型，而是把需求澄清、计划、实现和审查串起来。本次检索中它出现在 GitHub 日榜；比热度更值得看的是，它怎样约束“先写了再说”。

📌 这个项目是干什么的

  • 定位：一组可组合的技能，加上引导 Agent 调用技能的启动指令。
  • 场景：给现有项目加功能、排查故障，或把较大的需求拆成可检查的任务。
  • 对象：已经使用 Claude Code、Codex 等编码助手，但常被返工和验收拖慢的开发者。

🔍 为什么值得关注

第一，它把确认需求放在实现之前。官方流程先澄清目标，再根据工作规模决定在对话里确认，还是形成设计文档。10 月 9 日的更新专门重做了这一环节，避免大小任务都套同一套仪式。

第二，它把“完成”拆成证据链：计划说明改哪里、怎么验证；实现强调先写失败测试，再写最小代码；审查再检查是否符合计划。借鉴价值不只在提示词，而在每一步都留下可核对的产物。

第三，它不只有多 Agent 路径。文档也提供当前会话内执行、最后统一审查的方式。试用时不必默认选择最多子任务、最高成本的配置。

🧪 谁适合试，怎么开始

Claude Code 用户可按 README，在会话中安装：

/plugin install superpowers@claude-plugins-official

先拿一个有现成测试的小功能试用，例如给列表增加筛选。要求它先确认筛选规则与验收条件，再动手实现。验收只看三件事：有没有补问关键边界、测试能否复现问题、最终改动能否解释清楚。其他客户端按各自安装章节操作，不要照搬命令。

⚠️ 使用提醒

这是流程约束，不是正确性保证；仍要检查差异并实际运行测试。澄清、审查和子 Agent 都可能增加耗时与模型费用，小修改不要硬套完整流程。

项目采用 MIT 许可证。官方测试文档也提醒，行为评测会启动真实模型会话，部分使用宽松权限；首次体验只在隔离的测试仓库进行，不直接接生产凭据。本文为资料核验，未做安装实测。
