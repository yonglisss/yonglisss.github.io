把几段口播素材交给 AI，真正难的不是生成一句剪辑建议，而是准确删除口头禅、接好音画、加字幕并输出可继续检查的成片。video-use 是 Browser Use 团队开源的视频剪辑 Skill：把原始素材放进目录，用自然语言说明目标，它会先给出剪辑策略，确认后生成 edit/final.mp4。项目今日进入 GitHub Trending，单日新增约 500 Star。

📌 这个项目是干什么的

video-use 可运行在 Claude Code、Codex、Hermes、OpenClaw 等具备终端和文件权限的 Agent 中。它面向口播、教程、访谈、旅行混剪等素材，支持删除口头禅和停顿、自动调色、烧录字幕、在切点加入音频淡化，以及调用 HyperFrames、Remotion、Manim 或 PIL 制作动画叠层。

它不会把整段视频逐帧塞给模型。流程先通过 ElevenLabs Scribe 获得单词级时间戳、说话人和音频事件，再压缩为文字时间线；遇到重拍对比、模糊停顿或切点检查时，才生成带胶片帧、波形和词语标签的局部视图。剪辑决定写入 EDL，交给 FFmpeg 渲染，最后在切点执行自检。

🔍 为什么值得关注

这套结构把视频剪辑转化成 Agent 更擅长处理的“结构化文本 + 按需视觉”，避免粗暴抽帧带来的上下文浪费。更实用的是，它没有停在聊天建议：策略确认、渲染、自检和会话记忆都进入同一工作流，project.md 还能保存项目偏好，方便下次继续。

近期提交也在修复真实生产问题：默认保留源素材帧率，兼容竖屏旋转信息；多音轨素材可指定转写轨道，并在上传前拦截静音音轨，减少错误转写和无效费用。这说明项目正在补齐“能演示”到“可使用”之间的细节。

🧪 谁适合试，怎么开始

它适合经常剪口播、产品演示和教程视频，且已经使用编码 Agent 的开发者或内容团队。手动安装的最短路径是：

git clone https://github.com/browser-use/video-use ~/Developer/video-use
cd ~/Developer/video-use
uv sync

还需安装 FFmpeg，并配置 ElevenLabs API Key；项目要求 Python 3.10 以上。建议先用一段 1～2 分钟、单音轨的非敏感素材测试删停顿、字幕和切点，再逐步加入多机位与动画，不要直接拿正式长片开跑。

⚠️ 使用提醒

video-use 当前没有正式 Release，pyproject.toml 标注版本为 0.1.0，仍应按早期工具看待。转写会把音频发送到 ElevenLabs，不适合未经授权的会议、客户或隐私素材；动画还可能调用额外工具和模型。自动自检也不能替代人工审片，发布前必须检查事实、字幕、肖像与音乐版权、切点和声音。项目采用 MIT 许可证。
