字符串解码：用栈保存尚未完成的上一层

题意和示例

输入一段压缩后的字符串，k[内容] 表示把内容重复 k 次。括号可以嵌套，括号外的普通字母直接保留，要求返回完整展开结果。

  • 3[a]2[bc] → aaabcbc，两个重复块依次拼接。
  • 3[a2[c]] → accaccacc，必须先解开里面的 2[c]。
  • 2[abc]3[cd]ef → abcabccdcdcdef，末尾的 ef 不参与重复。

原题保证输入合法：长度为 1～30，只含小写英文字母、数字和方括号；次数为 1～300，数字只表示次数；展开结果长度不超过 100000。因此这里不额外处理括号缺失、负数次数或非法字符。

考查点

这题不是把数字后的几个字符复制一下，而是要区分每层括号的工作范围。

  • 遇到内层括号时，外层已经读到的前缀不能丢。
  • 每个左括号对应自己的重复次数，不能被内层数字覆盖。
  • 次数要按十进制累积，12[a] 不能当作重复两次。
  • 字符串构造有真实复制成本，不能只凭一次扫描就说时间是 O(n)。

Java 代码

用两个 Deque 分别保存次数和上一层前缀。它们总是同时入栈、同时出栈。

import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    public String decodeString(String s) {
        Deque<Integer> counts = new ArrayDeque<>();
        Deque<StringBuilder> prefixes = new ArrayDeque<>();
        StringBuilder current = new StringBuilder();
        int number = 0;

        for (int i = 0; i < s.length(); i++) {
            char ch = s.charAt(i);
            if (ch >= '0' && ch <= '9') {
                number = number * 10 + (ch - '0');
            } else if (ch == '[') {
                counts.push(number);
                prefixes.push(current);
                current = new StringBuilder();
                number = 0;
            } else if (ch == ']') {
                int repeat = counts.pop();
                StringBuilder parent = prefixes.pop();
                for (int j = 0; j < repeat; j++) {
                    parent.append(current);
                }
                current = parent;
            } else {
                current.append(ch);
            }
        }
        return current.toString();
    }
}

文字推导与正确性

为什么要把前缀也压栈？

假设读到 x2[a3[b]] 的第二个左括号。此时 a 是外层片段的前缀，x 又属于更外面的一层。只记次数，等内部的 bbb 算完，就不知道该接到哪里。

所以每次进入括号，都保存一份“回来以后继续做什么”：前缀对象和重复次数。随后用一个全新的 StringBuilder 处理括号内部，不能清空原对象，否则栈中保存的前缀也会被清掉。

四类字符对应四个动作

数字累积到 number；左括号保存状态并清零；普通字母追加到当前片段；右括号将当前片段重复后，接回上一层。

以 3[a2[c]] 为例：

  1. 第一个左括号保存空前缀和次数 3，开始新的片段。
  2. 读完 a2，第二个左括号保存前缀 a 和次数 2。
  3. 内层右括号把 c 重复两次接到 a 后，当前片段变为 acc。
  4. 外层右括号把 acc 重复三次接到空前缀后，得到答案。

注意：括号右边还有内容时，扫描会继续，因此不应在第一次遇到右括号时直接返回。

为什么每次出栈都是对的？

维持一个不变量：当前片段保存本层已经完成解码的内容；栈顶保存最近一层尚未恢复的外层状态。

读字母只扩展本层。进入左括号时，本层状态被完整保存，新层从空串开始，不变量仍成立。遇到右括号时，内部嵌套已经先处理完，当前片段正是该括号内的解码结果；弹出对应次数和前缀，拼接得到上一层的正确结果。

合法输入保证括号配对。扫描结束后，所有层都已恢复，当前片段就是整个字符串的解码结果。

复杂度和边界

设输入长度为 n，最终输出长度为 L，最大嵌套深度为 d。更精确地，令 C 为所有右括号展开时实际追加的字符总量。

  • 时间复杂度是 O(n + L + C)，包含扫描、逐层追加和最终 toString() 的复制。保守上界为 O(n + (d + 1)L)。
  • 空间复杂度是 O(n + L)，包含栈与字符串缓冲；不能只写 O(n)，因为展开结果可能远长于输入。

为什么不直接写 O(n + L)？1[1[abc]] 即使每层只重复一次，abc 仍会被逐层复制；把较长片段放进更多这样的括号，复制成本会随深度增加。这里给出的是本实现的保守界，不是声称每个输入都会达到它。

需要核对的边界：

  • abc：没有括号，直接返回原串。
  • 12[a]：多位次数正确累积。
  • a2[b]c：前后普通字母都不能丢。
  • 2[a]3[b]：进入下一块前，计数器已在左括号处清零。
  • 1[1[z]]：重复一次也必须正确恢复层级。
  • 300[a]：次数上界可用 int 保存；原题输出上界也避免了结果长度的整数溢出。若取消这些限制，需要另做长度与内存检查。

面试时忘记怎么办？

先别背代码，拿 x2[a3[b]] 问自己：进入内部后，回来还需要哪些信息？答案只有两个：原来已经写好的前缀、当前括号的次数。

接着写出四种字符的处理表：数字累积，左括号保存，字母追加，右括号恢复。最后用 12[a] 检查数字累积，用 3[a2[c]] 检查嵌套恢复。

解释复杂度时补一句：“扫描是线性的，但片段会逐层复制，我会把展开长度和嵌套深度也计入成本。”这比只说“用了栈，所以 O(n)”准确。

一句话总结

进入括号先保存前缀和次数，离开括号再把内部结果接回去；栈保存的不是字符，而是尚未完成的上下文。
