二叉树的锯齿形层序遍历：队列照常走，答案换方向

题意和示例

给定二叉树根节点 root，返回按层分组的节点值。根节点这一层从左到右，下一层从右到左，之后逐层交替；空树返回空列表。

例如，层序表示为 [3,9,20,null,null,15,7] 的树，输出是 [[3],[20,9],[15,7]]。这里 null 表示缺失的孩子，不是需要输出的节点值。

输入是一棵二叉树，不是二叉搜索树；节点值可以重复，不能根据值决定节点位置。

原题：LeetCode 103：Binary Tree Zigzag Level Order Traversal。

考查点

  • 用 BFS 队列划分层，而不是仅仅把所有节点依次取出。
  • 区分访问顺序与答案顺序：交替的是输出方向，孩子仍然左先右后入队。
  • 用双端队列完成常数时间头插、尾插，避免数组反复头插造成搬移。
  • 每层只切换一次方向，不能每访问一个节点就切换。

Java 代码

TreeNode 使用题目提供的定义，包含 int val、TreeNode left 和 TreeNode right。

import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Deque;
import java.util.List;

class Solution {
    public List<List<Integer>> zigzagLevelOrder(TreeNode root) {
        List<List<Integer>> answer = new ArrayList<>();
        if (root == null) {
            return answer;
        }

        Deque<TreeNode> queue = new ArrayDeque<>();
        queue.offerLast(root);
        boolean leftToRight = true;

        while (!queue.isEmpty()) {
            int size = queue.size();
            Deque<Integer> level = new ArrayDeque<>();

            for (int i = 0; i < size; i++) {
                TreeNode node = queue.pollFirst();
                if (leftToRight) {
                    level.offerLast(node.val);
                } else {
                    level.offerFirst(node.val);
                }

                if (node.left != null) {
                    queue.offerLast(node.left);
                }
                if (node.right != null) {
                    queue.offerLast(node.right);
                }
            }

            answer.add(new ArrayList<>(level));
            leftToRight = !leftToRight;
        }
        return answer;
    }
}

文字推导与正确性

先把层的边界固定下来

处理一层之前，队列里恰好保存这一层尚未处理的全部节点。先记下 size，本轮只取这 size 个节点。

处理时孩子会继续入队，因此不能用不断变化的 queue.size() 作为本层循环上限。否则下一层可能混进当前层，方向切换也就失去依据。

不反转队列，只改变收集位置

队列始终从头取节点，孩子始终先左后右加入队尾。这样下一层的节点仍按自然的从左到右顺序排列。

若本层需要正向输出，就把值追加到 level 尾部；若需要反向输出，就依次插到头部。例如本层访问顺序为 9,20，头插后的结果就是 [20,9]。

注意，反向层仍然先处理节点 9，再处理节点 20。输出是反的，并不意味着孩子也应该反着入队。

为什么每一层都会正确

初始时，队列只有根节点，天然满足“本层节点从左到右排列”。假设某轮开始时这一性质成立，那么固定次数出队就恰好处理完整一层，不多不少。

对这些节点依次加入非空左、右孩子，队尾得到的就是下一层从左到右的顺序，性质得以保持。与此同时，尾插保留本层顺序，头插反转本层顺序；层末取反方向标记，便与题目要求的交替方向一致。

因此，每个节点都只出现在所属层一次，各层方向也正确。new ArrayList<>(level) 按双端队列从头到尾的迭代顺序保存这一层，不会丢失已经组织好的方向。

复杂度和边界

设节点数为 n，最大层宽为 w。

  • 时间复杂度为 O(n)：每个节点入队、出队、插入本层容器各一次，所有层复制到列表的总成本也是 O(n)。
  • 不计返回结果，辅助空间为 O(w)，最坏为 O(n)。处理过程中队列可能同时含有本层剩余节点和下一层节点，但仍受常数倍层宽约束。
  • 返回结果保存所有节点值，需要 O(n) 空间。

空树直接返回 []，避免把 null 放进不接受空元素的 ArrayDeque。单节点得到 [[值]]；单链树每层只有一个节点，换方向不会改变结果。

重复值、负数都只作为数据搬运，不参与比较。代码不对节点值做算术运算，因此不存在节点值相加导致的整数溢出。偏斜树也不依赖递归，不会因树深导致递归栈溢出。

容易写错的还有一种做法：在 ArrayList 上持续 add(0, value)。宽层会因反复搬移元素退化为平方级开销；这里使用 ArrayDeque.offerFirst 避开了这个问题。

面试时忘记怎么办

先把普通层序遍历写对：队列、固定本层大小、非空孩子入队。不要一开始就尝试双栈或同时反转出队和入队方向。

如果想不起双端队列 API，可以先用普通列表收集一层，在反向层调用 Collections.reverse(level)。各层反转的总长度不超过节点总数，整体仍是 O(n)，这是可解释、可落地的备选解法。

再用一个至少有两层分叉的例子手推：第二层输出反转，但第三层入队顺序仍然正常。这个检查能抓住“连孩子入队顺序也反了”的错误。

最后向面试官说明：我维护的不是“按锯齿顺序访问”的队列，而是“按自然层序访问、按要求组织答案”的两个独立过程。

一句话总结

锯齿层序遍历不必改动 BFS 的访问秩序：先守住层边界，再切换这一层答案的收集方向。
