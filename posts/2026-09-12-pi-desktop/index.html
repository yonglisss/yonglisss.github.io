AI 编程工具常被绑定在终端、编辑器插件或云端服务里。今日进入 GitHub Trending 的 PI-Desktop 换了一种思路：把项目、会话、模型、代码审查和扩展能力放进独立桌面应用，同时保留本地项目与自选模型的控制权。它仍处于早期预览阶段，但已经提供 macOS、Windows 和 Linux 安装包，适合想尝试桌面化 Agent 工作流的开发者。

📌 这个项目是干什么的

PI-Desktop 是基于 Electron、React、Rust 和 pi Agent Harness 构建的本地优先 AI 编程工作台。用户可以打开本地代码目录，接入 OpenAI、Anthropic、Ollama、LM Studio 或兼容 OpenAI API 的服务，再让 Agent 读取文件、修改代码、执行命令和运行测试。

它提供 Agent、Plan、Goal 三种工作模式：Agent 直接执行；Plan 先生成冻结的实施计划，批准后才开始；Goal 则先确认目标与验收条件，由 Agent 自行选择路径。应用还支持 Skills、MCP、Subagents 和插件，并可导入 Claude Code、Codex、OpenCode、Pi 的本地会话。

🔍 为什么值得关注

第一，它把“能执行”与“可审查”放在同一个界面。 文件修改、命令输出和运行结果都有独立查看入口，高风险操作仍经过权限层，而不是只展示一段最终回答。

第二，它不强制绑定模型或编辑器。 同一会话可切换不同服务商和模型，本地模型与云端 API 都能接入；项目也不必迁移到专用云工作区。

第三，它的扩展边界比较完整。 Skills 负责复用工作方法，MCP 连接外部工具，Subagents 拆分独立任务，插件还能增加命令、面板、主题和常驻服务。这套分层对正在设计内部 Agent 平台的团队也有参考价值。

🧪 谁适合试，怎么开始

它更适合经常使用代码 Agent、希望统一管理多个项目和长会话，同时又在意执行权限与变更审查的开发者。最短路径是从 GitHub Releases 下载稳定版 v0.14.6，安装后进入“模型配置”添加服务，再打开一个可随时回滚的小型测试仓库。

第一次建议选择 Plan 模式，只让它完成一个范围明确的修改；重点检查计划审批、文件差异、命令权限和失败恢复是否符合自己的习惯。确认可靠后，再尝试 Subagents、MCP 或插件。

⚠️ 使用提醒

“本地优先”不等于完全离线：会话、设置和日志保存在本机，但发送给远程模型的上下文仍会到达所配置的服务商。插件也只是进程隔离和权限控制，并非完整的操作系统沙箱，只应安装可信来源。

项目明确标注为 Early Preview，扩展接口和桌面行为仍可能变化。当前最新版本是 v0.14.7-beta.1，求稳可先用 v0.14.6；macOS 的标签构建默认可能未签名，Linux x64 安装包要求 glibc 2.35 或以上。项目采用 LGPL-3.0 许可证，二次分发前应核对合规要求。
