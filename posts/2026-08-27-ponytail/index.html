AI 编程工具很容易把一个小需求做成一套新抽象：能用浏览器原生能力解决，却先装依赖、封装组件、补配置。Ponytail 是一个面向编码 Agent 的开源插件与 Skill。它不替你写业务，而是在动手前要求 Agent 依次检查：需求是否真的需要实现、项目里是否已有方案、标准库或平台原生能力能否解决，最后才写最少的必要代码。

📌 这个项目是干什么的

  • 为 Claude Code、Codex、OpenCode、Gemini CLI、Copilot CLI、Pi 等编码工具注入一套精简实现规则。
  • 把 YAGNI、复用现有代码、优先标准库与原生平台能力整理成固定决策阶梯。
  • 提供 lite、full、ultra 等强度，以及审查、审计、技术债检查等命令，既能约束新代码，也能检查现有改动。
  • 项目采用 MIT 许可证；官方最新 Release 为 v4.9.0，并持续修复 Windows、Codex、OpenCode 等环境的兼容问题。

🔍 为什么值得关注

更值得关注的不是“少写几行”，而是它把控制 AI 过度实现的原则变成了可重复执行的工作流。Agent 必须先读懂相关代码和真实调用链，再从“不做、复用、标准库、原生能力、现有依赖”逐级判断，而不是直接生成一套看似完整的新方案。

项目还公开了可复现实验：在真实 FastAPI + React 仓库的 12 个功能任务中，对比同一 Claude Code Agent，Ponytail 组平均减少约 54% 新增代码，代价和耗时也有所下降；但在本来就难以精简的后端 CRUD 任务中，各组结果接近。这个边界很重要：它主要减少过度建设，并不能让所有需求都神奇变短。实验由项目方完成，数据应视为参考，而不是普适保证。

🧪 谁适合试，怎么开始

适合已经使用编码 Agent、经常遇到“为了小需求引入大改动”的开发者或团队。建议先在非核心项目安装，挑一个容易过度实现的小需求做 A/B 对比，重点查看 git diff、新增依赖、测试结果与可维护性，而不是只数代码行。

Codex 可这样安装：

codex plugin marketplace add DietrichGebert/ponytail
codex plugin add ponytail@ponytail

安装后进入 /hooks 审查并信任两个生命周期 Hook，再新建会话。也可以先用审查命令检查已有改动，确认它的取舍方式符合团队规范后，再开启常驻模式。

⚠️ 使用提醒

“代码少”不等于“方案好”。领域规则、可读性、扩展性和团队约定仍需人工判断，不能为了压缩行数牺牲清晰度。官方规则明确保留安全校验、数据丢失防护、信任边界与可访问性，但项目方基准只覆盖有限模型、仓库和任务，落地前仍应运行自己的测试与安全检查。

Claude Code 和 Codex 的常驻激活依赖 PATH 中可用的 Node.js；缺失时 Skill 仍可使用，但生命周期 Hook 不会正常注入。安装第三方 Hook 前，也应像审查代码依赖一样先检查其权限和脚本内容。
