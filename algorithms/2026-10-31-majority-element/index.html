数组 · 投票法 · Boyer-Moore

多数元素：为什么两两抵消后，答案不会丢

题意和示例

给定一个非空整数数组，返回其中出现次数严格大于数组长度一半的元素。题目保证这个元素存在，因此答案也唯一。

例如，[2, 2, 1, 1, 1, 2, 2] 返回 2：数组长度为 7，2 出现 4 次。[3, 2, 3] 则返回 3。

注意，“多数”不是出现次数最多就够了。[1, 1, 2, 3] 中的 1 虽然最多，但没有超过一半，不满足本题前提。

原题：Majority Element。下面的解法依赖“非空且多数元素一定存在”，不把它扩展成任意输入的检测器。

考查点

  • 能否从哈希表统计次数，进一步缩减到常数额外空间。
  • 能否解释删除两个不同元素为什么不影响多数元素的身份。
  • 能否区分“当前剩余票数”和“在原数组中的实际出现次数”。
  • 能否指出：没有存在性保证时，投票结果还要再验证。

Java 代码

只维护候选值和剩余票数，不排序，也不修改输入数组。

class Solution {
    public int majorityElement(int[] nums) {
        int candidate = 0;
        int count = 0;

        for (int num : nums) {
            if (count == 0) {
                candidate = num;
            }

            if (num == candidate) {
                count++;
            } else {
                count--;
            }
        }

        return candidate;
    }
}

candidate 初始为 0 不代表偏向数字零：第一次循环时 count 为零，会先用当前元素覆盖它。负数和零都能正常作为候选值。

文字推导与正确性

先把统计问题改写成抵消问题

哈希表能记录每个数的次数，时间是 O(n)，但最坏需要 O(n) 额外空间。这里有更强的条件：答案的数量比所有其他元素加起来还多。

把两个不同的元素删掉，会发生什么？设多数元素为 M，数组长度为 n，它出现 m 次，且 2m > n。

如果删掉的一对包含 M，剩下的次数和长度分别是 m - 1、n - 2。由 2m > n 可知 2(m - 1) > n - 2，它仍超过一半。

如果删掉的两个都不是 M，M 的次数不变，数组反而更短，它的优势只会扩大。因此，反复删除不同元素，不会改变多数元素的身份，也不可能把它全部消光。

两个变量怎样模拟删除

扫描到某个位置时，可以把已处理的前缀理解为：删除若干对不同元素后，只剩 count 个相同的 candidate。

  • 票数为零：没有剩余元素，用当前数建立新候选。
  • 当前数等于候选：把它放进剩余集合，票数加一。
  • 当前数不同于候选：拿它抵消一个剩余候选，票数减一。

这里的 count 是抵消后的剩余数量，不是候选值在整个前缀中的频次，也不能当成最终频次。

以 [2, 2, 1, 1, 1, 2, 2] 为例，每处理一个元素，状态 (candidate, count) 依次为：

(2, 1) → (2, 2) → (2, 1) → (2, 0)
       → (1, 1) → (1, 0) → (2, 1)

候选中途变成 1 没关系，它只是剩余集合的代表，不是已经确认的答案。票数归零时，旧候选即使还留在变量里，也不再代表任何剩余元素。

为什么最终可以直接返回候选

循环始终在模拟合法的成对删除。多数元素不会在这种删除中失去多数地位，更不可能被完全删掉。

扫描结束时，剩余集合非空，而且其中所有元素相同，所以这个值只能是原数组的多数元素。

直接返回的依据是题目保证答案存在，而不是投票法能自动判断存在性。 对于不保证存在的变体，需要再扫描一次，统计候选的真实次数，检查是否严格大于 nums.length / 2；没有通过就应按接口约定返回“无答案”。例如 [1, 2, 3] 也会产生候选，但它并非多数元素。

复杂度和边界

时间复杂度为 O(n)：每个元素只处理一次。额外空间为 O(1)：只用两个整数变量。若增加候选验证，仍是 O(n) 时间和 O(1) 空间。

  • 单元素数组：第一次建立候选，直接返回该元素。
  • 全部相同：票数持续递增，结果不变。
  • 票数多次归零：允许反复换候选，无需回头扫描。
  • 偶数长度：恰好一半不算多数；例如长度 4 至少要出现 3 次。
  • 负数、零及 int 极值：算法只比较元素，不对元素做加减，不会因数值大小溢出；count 最多为数组长度，使用 int 即可。
  • 空数组或 null：不属于本题输入契约。这份实现不负责校验；用于业务接口时应另行定义异常或无答案行为。

面试时忘记怎么办

先交付能确认正确的方案：“用哈希表统计次数，找到超过半数的元素，时间 O(n)，空间最坏 O(n)。”不要为了立刻说出算法名而停住。

然后抓住题目最特殊的条件：“答案比其他元素总和还多，所以删除两个不同元素，答案仍然占多数。”从这个动作推回两个状态：当前剩下的值，以及还剩多少个。

实现时只检查一处顺序：票数为零，先设置候选；随后当前元素仍要参与加票。否则会漏掉新候选的第一票。

最后主动补充适用范围：“本题保证存在，所以一遍返回；若不保证，我会再数一次候选的真实频次。”这比只背出变量更新更能说明理解。

一句话总结

投票法不是猜谁出现最多，而是利用严格过半的优势，让答案经得住每一次不同元素的抵消。
