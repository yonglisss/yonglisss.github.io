让 Agent 操作网页，难点不只是“打开页面”：原始 HTML 会迅速占满上下文，登录状态难复用，多任务共用 Cookie 还可能串号。今日进入 GitHub Trending 的 Camofox Browser，把基于 Firefox 的 Camoufox 封装成面向 Agent 的 REST API、MCP 服务和 OpenClaw 插件，适合需要长期运行网页工作流的开发者评估。

📌 这个项目是干什么的

它不是通用聊天机器人，而是一层浏览器自动化服务。Agent 可以创建标签页、获取带稳定元素编号的可访问性快照，再按编号点击、输入、滚动或截图；相比直接读取整页 HTML，这种结构更适合交给模型处理。

项目还提供按用户隔离的会话、Cookie 与 localStorage 持久化、文件上传、下载捕获、代理配置、结构化日志和 Playwright Trace。既能独立运行，也能通过 MCP 或 OpenClaw 工具接入现有 Agent。

🔍 为什么值得关注

第一，接口是按 Agent 的输入方式设计的。 可访问性快照、元素引用和分页截断，能减少页面噪音，让模型围绕可操作节点工作，而不是反复解析大段 DOM。

第二，补上了长任务所需的工程能力。 会话隔离解决多人或多任务状态混用问题；持久化允许重启后继续使用登录态；Trace、请求 ID 和 OpenAPI 则方便排查“Agent 为什么点错了”。底层 Camoufox 在浏览器实现层处理多项指纹参数，但这不等于对所有网站都能稳定通过检测。

🧪 谁适合试，怎么开始

它适合开发网页调研、后台录入、测试或内部流程自动化的团队。当前 npm 包为 1.14.0，要求 Node.js 22 及以上。最短路径是先在隔离环境运行：

npx @askjo/camofox-browser

服务默认监听 9377 端口，首次安装会下载约 300MB 的 Camoufox。先用公开网页验证“建标签页—取快照—点击—留 Trace”的闭环，再决定是否导入账号状态。生产部署应配置 API Key、限制网络入口，并为不同任务分配独立会话。

⚠️ 使用提醒

反检测能力不能理解为“任意抓取许可”。网站服务条款、robots 规则、访问频率和数据合规仍需单独评估，不要用于绕过验证码、风控或权限控制。Cookie 导入等同于交出登录凭证，应使用低权限测试账号并保护 ~/.camofox 数据目录。

项目默认启用匿名崩溃/卡死遥测，可用 CAMOFOX_CRASH_REPORT_ENABLED=false 关闭；涉及内网地址或敏感业务时，建议先审查配置与源码。该项目采用 MIT 许可证，但底层浏览器及网站内容仍受各自条款约束。
