二分查找：用闭区间推导边界，不靠背模板

题意和示例

给定一个严格升序的整数数组 nums 和整数 target，返回目标值的下标；不存在则返回 -1。要求查找时间为 O(log n)，不能只用顺序遍历完成。

例如，nums = [-1, 0, 3, 5, 9, 12]：查找 9 返回 4；查找 2 返回 -1。返回的是下标，不是元素值。

原题约束：数组长度为 1 到 10^4，所有元素互不相同，且 -10^4 < nums[i], target < 10^4。有序是输入保证，不需要先排序；排序不仅增加开销，还可能改变原下标。

原题链接：LeetCode 704 · Binary Search。

考查点

  • 能否利用有序性，证明某一整段不可能包含答案。
  • 能否从区间定义推导循环条件，而不是混用不同模板。
  • 每次更新是否排除了已检查的中点，确保区间严格缩小。
  • 目标不存在时，是否能自然结束并返回 -1。

Java 代码

这里把待查范围定义为两端都包含的闭区间 [left, right]。

class Solution {
    public int search(int[] nums, int target) {
        int left = 0;
        int right = nums.length - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] == target) {
                return mid;
            }
            if (nums[mid] < target) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
        return -1;
    }
}

文字推导与正确性

先决定“还有哪些位置没排除”

维护的条件是：如果目标存在，它一定还在 [left, right] 中。 初始范围覆盖整个数组，因此这个条件成立。

闭区间在 left == right 时仍有一个元素，所以循环必须允许相等。此时如果写成 left < right，又没有循环后的单独检查，就会漏掉最后一个候选位置。

用一次比较排除一整段

取中点 mid。如果命中，直接返回。

如果 nums[mid] < target，由于数组升序，从 left 到 mid 的值都小于目标。这些位置可以一起丢弃，新的左边界是 mid + 1。

反过来，若 nums[mid] > target，从 mid 到 right 都不可能命中，新的右边界就是 mid - 1。

两种更新都只排除不可能的位置，因此保留了上述条件；同时，中点也被移出待查范围，区间必定严格缩小。

跟着一个失败案例走完

在 [-1, 0, 3, 5, 9, 12] 中找 2：

  1. [0, 5] 的中点是 2，值为 3，右边界改为 1。
  2. [0, 1] 的中点是 0，值为 -1，左边界改为 1。
  3. [1, 1] 的中点是 1，值为 0，左边界改为 2。

此时 left = 2 > right = 1，区间为空。候选位置已经全部排除，返回 -1，而不是返回最后一次的中点。

这也完成了正确性说明：答案若存在不会被误删；循环最终要么找到它，要么证明不存在。

复杂度和边界

每次比较后，剩余候选数至多为原来的一半，时间复杂度为 O(log n)；只保存三个下标，额外空间为 O(1)。

  • 单元素数组：命中立即返回 0；未命中时边界交错，返回 -1。
  • 目标在首尾或范围外：不需要特殊分支，区间更新会覆盖这些情况。
  • 负数与零：只影响比较结果，不影响下标计算。
  • 重复值：原题不含重复值。若扩展为非递减数组，这段代码仍能找到某个匹配位置，但不保证最左或最右下标。
  • 空数组与 null：空数组会直接返回 -1，但它不在原题输入范围内；代码不处理 null，调用方应保证数组非空引用。

中点用 left + (right - left) / 2，避免先计算 left + right 带来的整数溢出风险。循环内有 0 <= left <= right < nums.length，所以差值与最终中点都在合法范围内。代码不对元素做加减，负数也不会引入额外溢出问题。

面试时忘记怎么办？

不要先纠结用 < 还是 <=。先在纸上写一句：“左右端点都属于待查范围。”

接着用三个问题还原代码：

  1. 只剩一个位置，要不要查？ 要，所以用 left <= right。
  2. 中点已经比较过，还要不要留？ 不要，所以边界跳到 mid + 1 或 mid - 1。
  3. 左右边界交错意味着什么？ 候选为空，返回 -1。

最后手推 [5] 查 5、[5] 查 4，再推 [1, 3] 查 3。这几步能快速暴露漏查最后元素、边界不推进等错误。

面试表达可以收束为：“我维护闭区间，利用有序性排除不可能的一半；每轮严格缩小范围，所以既不会漏解，也不会死循环。”

一句话总结

二分边界不是三个独立的记忆点：确定闭区间之后，<=、mid + 1 和 mid - 1 就能一起推出来。
