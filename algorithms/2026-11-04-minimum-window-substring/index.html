最小覆盖子串：用达标种类数控制窗口收缩

题意和示例

给定字符串 s 和 t，在 s 中找一个最短的连续片段，让它包含 t 要求的全部字符。字符可以乱序，但出现次数不能少。找不到就返回空字符串。

例如 s = "ADOBECODEBANC"、t = "ABC"，返回 "BANC"。如果 s = "a"、t = "aa"，则返回 ""：有一个 a 不等于满足两个 a 的需求。

本题按区分大小写的英文字符处理，不接受 null。下面的实现额外兼容空字符串：目标为空时直接返回空串。若推广到任意 Unicode 文本，需要先约定按 UTF-16 单元还是 Unicode 码点计数，不能直接把 char 当成所有自然语言字符。

考查点

  • 用频次表达覆盖，而不是用集合判断“出现过”。
  • 维护窗口状态，避免每移动一次指针就扫描整张需求表。
  • 明确更新顺序：合法时先保存答案，再删除左端字符。
  • 区分“数量已经足够”和“刚好跨过达标门槛”，防止重复增加达标种类数。

Java 代码

窗口采用左闭右开区间 [left, right)。两张表只记录目标需要的字符。

import java.util.HashMap;
import java.util.Map;

class Solution {
    public String minWindow(String s, String t) {
        if (t.isEmpty() || s.length() < t.length()) {
            return "";
        }

        Map<Character, Integer> need = new HashMap<>();
        Map<Character, Integer> window = new HashMap<>();
        for (char c : t.toCharArray()) {
            need.put(c, need.getOrDefault(c, 0) + 1);
        }

        int left = 0;
        int right = 0;
        int satisfied = 0;
        int bestStart = 0;
        int bestLength = Integer.MAX_VALUE;

        while (right < s.length()) {
            char added = s.charAt(right++);
            if (need.containsKey(added)) {
                int count = window.getOrDefault(added, 0) + 1;
                window.put(added, count);
                if (count == need.get(added)) {
                    satisfied++;
                }
            }

            while (satisfied == need.size()) {
                if (right - left < bestLength) {
                    bestStart = left;
                    bestLength = right - left;
                }

                char removed = s.charAt(left++);
                if (need.containsKey(removed)) {
                    int count = window.get(removed);
                    if (count == need.get(removed)) {
                        satisfied--;
                    }
                    window.put(removed, count - 1);
                }
            }
        }

        return bestLength == Integer.MAX_VALUE
                ? ""
                : s.substring(bestStart, bestStart + bestLength);
    }
}

代码中的 count 是基本类型 int，与 Integer 比较时会拆箱，比较的是数值，不存在两个 Integer 用 == 比较对象身份的问题。

文字推导与正确性

先把需求拆成每个字符的配额

假设 t = "AABC"，需求是 A:2、B:1、C:1。窗口出现一个 A 还不够；出现三个 A 也不能抵扣缺少的 B。

因此维护 need 和 window，再让 satisfied 表示已经达到配额的字符种类数。它等于 need.size() 时，窗口才完整覆盖目标。

只在跨越门槛时更新状态

加入字符后，数量从“少一个”变成“刚好够”时，satisfied 加一。从“刚好够”变成“多一个”时不变，否则多余字符会被误算成新的达标种类。

移除字符时则反过来：如果移除前恰好够，移除后就缺一个，应先将 satisfied 减一。如果移除前有富余，删除一个不影响合法性。

例如 t = "AA"：窗口中的 A 从一个变两个才达标，从两个变三个不再加分；从三个删到两个仍合法，从两个删到一个才失效。

为什么满足后必须持续收缩

固定右端点，去掉左侧无关字符或多余字符，只会让答案更短。所以用 while 连续缩短，而不是只移动一次。

每次删除之前先记录候选答案，保证最后一个合法窗口也会被考虑。删到失效后再扩张右端点，补上缺少的字符。

为什么不会漏掉最优答案

对一个固定右端点，收缩过程会检查所有尚未丢弃的合法左边界，直到第一次失效，因此会记录该阶段最短的合法窗口。

已经被丢弃的左边界也不需要回头：它被丢弃时，对应的合法窗口已经记录过；以后右端点更远，保留这个旧左边界只会得到更长窗口。左右指针都单向前进，仍能覆盖全局最优解。

在示例中，第一次得到 "ADOBEC" 后可以记录长度 6，但删除左侧 A 就失效。继续向右补齐后重新收缩，最终得到长度 4 的 "BANC"。

复杂度和边界

令 m = s.length()、n = t.length()，k 为目标中的不同字符数。

  • 时间：哈希表操作按均摊常数时间计，为 O(m + n)。虽然有两层循环，但每个指针最多移动 m 次；构造返回子串的开销也不改变这个上界。
  • 辅助空间：两张表为 O(k)，不含返回字符串；若计入返回值，还需要与答案长度成正比的空间。固定英文字符集下，辅助空间也可写作 O(1)。
  • t 比 s 长、字符缺失、重复次数不足，都应返回空串。
  • 单字符、全部字符相同、大小写混用，都按各自频次处理；无关字符不能计入达标种类。
  • 频次和下标均使用 int，其取值受 Java 字符串长度限制；bestStart + bestLength 是有效右边界，不会超出 s.length()。没有需要处理的负数输入。

面试时忘记怎么办

先说一个可验证的朴素方案：枚举左边界，向右找第一个覆盖目标的片段。然后指出重复工作——相邻窗口的大部分字符相同，频次可以复用，不必重新统计。

接下来先写两个动作：加入字符、移除字符。拿 t = "AA" 手推数量 1 → 2 → 3 → 2 → 1，把“什么时候达标、什么时候失效”确定下来，再补指针循环。

最后用一句话检查循环方向：“未覆盖就扩张，已覆盖就记录并收缩。”如果记不起状态变量，也可以先扫描需求表判断覆盖保证正确，再优化为达标种类计数；不要为了背模板牺牲正确性。

一句话总结

最小覆盖子串不是找到字符就停，而是计数满足以后，持续删除左端直到刚好失效。
