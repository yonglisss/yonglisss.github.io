买卖股票的最佳时机：固定卖出日，只记住此前最低价

题意和示例

给定按日期排列的股价数组 prices，最多完成一笔交易：选一天买入，再选严格晚于买入日的一天卖出。返回最大利润；没有赚钱机会就不交易，返回 0。

例如 [7, 1, 5, 3, 6, 4] 的答案为 5：第 2 天以 1 买入，第 5 天以 6 卖出。不能用第 1 天的 7 减去后来的 1，因为这相当于先卖后买。

[7, 6, 4, 3, 1] 则返回 0。题目不是求“必须交易一次时最少亏多少”。

考查点

  • 把“选择两个日期”改写为“固定卖出日，寻找此前最低买入价”。
  • 用一个前缀最小值代替对所有买入日的反复扫描。
  • 让状态定义和更新顺序一致，明确不能先卖后买。
  • 区分单次交易与多次交易：不能把每一段上涨的收益累加。

Java 代码

下面的实现先计算今天卖出的利润，再把今天纳入最低价，直接对应“买入日在卖出日之前”。

class Solution {
    public int maxProfit(int[] prices) {
        if (prices.length < 2) {
            return 0;
        }

        int minPrice = prices[0];
        int best = 0;
        for (int day = 1; day < prices.length; day++) {
            best = Math.max(best, prices[day] - minPrice);
            minPrice = Math.min(minPrice, prices[day]);
        }
        return best;
    }
}

文字推导与正确性

从两层枚举中拿掉重复工作

直接做法是枚举所有 buy < sell，比较 prices[sell] - prices[buy]，时间复杂度为 O(n²)。

换一个顺序：先固定卖出日。今天的售价已经确定，要让利润最大，只需要此前的最低买入价，不需要保留每一个历史价格。

当卖出日右移一天，历史范围只增加一个价格。最低价可以直接取旧最低价和新增价格的较小者，不必重新扫描。

两个状态分别表示什么

进入 day 这轮循环时：

  • minPrice 是下标 [0, day - 1] 内的最低价格。
  • best 是此前所有卖出日能取得的最大非负利润。

所以 prices[day] - minPrice 就是今天卖出的最佳合法利润。先用它更新 best，再更新 minPrice，供明天使用。

在示例中，读到价格 1 时没有盈利，但最低价降为 1；读到 5 时最佳利润变为 4；读到 3 时不覆盖已有答案；读到 6 时才把答案更新为 5。

为什么不会漏解

第一轮之前，历史区间只有第 1 天，最低价初始化正确；还没有合法交易，答案为 0。

每轮都找到了以今天为卖出日的最优交易，又保留了此前最优答案。因此处理完今天，best 覆盖了截至今天的全部卖出日。随后更新最低价，下一轮的历史区间也保持正确。

所有可能的卖出日都处理过后，全局最优交易一定在其中；若所有差价都不大于零，初始的 0 就表示不交易。

有的写法先更新最低价再算利润，会额外产生一个“今天买、今天卖”的零收益候选。在本题允许不交易的条件下，它不改变答案；这里选择先算利润，是为了让代码与严格的日期约束直接对齐。

复杂度和边界

  • 时间复杂度 O(n)：每个价格最多处理一次。
  • 额外空间 O(1)：只保存最低价和最佳利润。
  • 只有一天：没有合法买卖日期对，返回 0。代码也对空数组返回 0，属于额外防御，不代表原题允许空输入。
  • 全程下跌或价格全部相同：返回 0，不能返回负收益。
  • 重复最低价：记住价格就够了，本题不要求返回具体日期。
  • 最低价在最后一天：只能供未来卖出使用，不能与此前高价配对。
  • 原题是非负股价场景；Java int 适用于本题价格范围。若业务改成允许完整 int 范围的正负值，差值应先转成 long 再计算，返回类型也需重新约定；负价格不属于本文题意。
  • 方法按题目约定接收非 null 数组，不额外约定 null 的返回值。

面试时忘记怎么办

先不要背变量名，写出目标：在 buy < sell 的前提下，最大化 prices[sell] - prices[buy]。

然后问自己：“卖出日固定了，还需要枚举每一个买入日吗？”答案是否定的，只要知道此前最便宜的价格。

最后按这个定义写顺序：用历史最低价计算今天的利润，保留更大答案，再把今天的价格纳入历史。拿 [2, 1] 检查是否错误地允许先卖后买，拿 [1, 2, 3] 检查是否误写成多次交易。

向面试官说明：一次遍历不是因为两个日期不重要，而是因为对每个卖出日，所有买入日的信息可以压缩成一个最低价。

一句话总结

固定右端的卖出日，用左侧前缀最低价替代对买入日的重复枚举。
