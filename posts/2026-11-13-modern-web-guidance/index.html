让编程助手做一个弹窗，它可能先装组件库，再写一套焦点和遮罩逻辑。但浏览器已经提供了不少原生能力。Modern Web Guidance 是一套面向编程智能体的开源技能，把现代网页开发知识和兼容性资料送进上下文。本次核验时，其源码仓库进入 GitHub 日榜；值得看的不是多一个提示词包，而是让技术选型有具体依据。

📌 这个项目是干什么的

  • 为编程助手提供布局、表单、性能、无障碍等方面的指南。
  • 支持搜索相关指南，再按编号读取，不必把整本文档塞进一次对话。
  • 面向使用 AI 开发网页的前端工程师，也适合维护内部开发规范的团队。

它不是新的模型，也不是安装后自动翻新整个网站的工具。源码仓库负责内容编写、校准与评估，分发仓库提供可使用的技能和指南。

🔍 为什么值得关注

第一，把“能不能用原生能力”放到写代码之前。模型见过大量旧代码，容易沿用旧方案；针对任务补充指南，比泛泛要求“使用最佳实践”更容易核对。

第二，指南不只列接口。官方导航抽屉示例先区分纯抽屉与兼作侧边栏的场景，再讨论 dialog、popover、焦点和关闭行为。值得借鉴的是先判断交互语义，而不是看到新接口就替换。

第三，保留按需取回知识的入口。团队也可以围绕常见任务组织自己的规范，让助手先查相关条目，再动手修改。

🧪 谁适合试，怎么开始

准备可运行 npx 的 Node.js 环境，在练习项目按官方说明安装：

npx modern-web-guidance@latest install

不想先安装，也可直接读取一份指南：

npx modern-web-guidance@latest retrieve "navigation-drawer"

第一轮只改一个菜单或弹窗。让助手先解释采用哪种元素、目标浏览器是否支持，再生成代码。验收时检查键盘操作、关闭后的焦点位置和手机端表现，不只看画面是否出现。

⚠️ 使用提醒

新能力不等于你的用户环境都支持。兼容性、降级策略与项目现有约束仍需逐项确认，指南不能代替真实浏览器测试。不要为了减少几行代码，批量替换已经稳定工作的组件。

源码仓库采用 Apache-2.0 许可证；复用时仍应遵守许可与声明要求。本文核验了文档和示例，未对项目效果做实测背书。
