长度最小的子数组：为什么达到目标后要连续收缩

题意和示例

给定正整数数组 nums 和正整数 target，找出元素之和大于等于 target 的最短连续子数组，返回它的长度。找不到就返回 0。

注意两个条件：必须连续；和只要达到目标即可，不必恰好相等。

例如 target = 7，nums = [2, 3, 1, 2, 4, 3]，答案是 2，对应 [4, 3]。虽然 [2, 3, 1, 2] 也达标，但长度不是最短。

target = 4、nums = [4] 返回 1；target = 8、nums = [1, 2, 3] 返回 0。

考查点

  • 能否利用“所有元素为正数”，而不是看到子数组就机械套模板。
  • 能否维护窗口 [left, right] 与窗口和的一致性。
  • 能否解释为什么收缩用 while，以及为什么先记录长度、再删除左端。
  • 能否用指针总移动次数解释线性复杂度，而不是看到嵌套循环就判断为平方级。

Java 代码

用 long 保存窗口和，避免把正确性建立在累计值一定不超过 int 上。下列实现按题意接收非空引用、正整数数组与正目标值；不额外定义 null 或非法输入的行为。

class Solution {
    public int minSubArrayLen(int target, int[] nums) {
        int left = 0;
        int best = Integer.MAX_VALUE;
        long sum = 0L;

        for (int right = 0; right < nums.length; right++) {
            sum += nums[right];
            while (sum >= target) {
                best = Math.min(best, right - left + 1);
                sum -= nums[left];
                left++;
            }
        }

        return best == Integer.MAX_VALUE ? 0 : best;
    }
}

文字推导与正确性

从枚举起点，变成只向右移动起点

直接枚举每个起点，再向右累加，最坏需要 O(n²) 时间。重复工作来自不同起点反复扫描相同元素。

正数让事情简单了：右端加入元素，和一定增大；左端移除元素，和一定减小。因此，不够时扩张，够了时尝试收缩，不需要让指针回头。

达标不是停止条件，而是收缩的开始

在示例中，右端走到索引 3 时，窗口 [2, 3, 1, 2] 的和为 8。先记录长度 4，移除 2 后和变成 6，暂时停止收缩。

右端加入 4 后，窗口 [3, 1, 2, 4] 的和为 10。移除 3，剩下 [1, 2, 4] 的和仍是 7，应继续记录长度 3，再移除 1。这就是必须用 while 而不是 if 的原因：一次加入可能允许连续删除多个元素。

最后加入 3，会依次检查 [2, 4, 3] 和 [4, 3]，把答案缩到 2。

每次更新必须发生在删除左端之前，因为此刻窗口才是已知合法的候选区间。

为什么丢掉左端不会漏掉最优答案？

始终保持 sum 等于当前窗口的实际元素和。收缩循环结束时，以当前右端结尾、起点不早于 left 的窗口都不达标：继续删除正数只会让和更小。

如果某个起点已经被删除，说明算法此前记录过一个从该起点开始的合法窗口。以后右端再往右移动，只会让这个起点对应的区间更长，因此无需再考虑它。

所以每一步要么检查合法候选，要么排除不可能改善答案的区间；全局最短长度不会被跳过。若一次合法窗口都未出现，哨兵值保持不变，最终返回 0。

复杂度和边界

  • 时间 O(n)：右指针前进 n 次，左指针累计最多前进 n 次。内层循环的执行次数不是每轮都重新从头计算。
  • 额外空间 O(1)：只维护两个指针、窗口和与最优长度。
  • 单个元素已达标时，最短长度就是 1；重复值不影响单调性，也不需要去重。
  • 总和不足时返回 0；等于目标也合法，条件不能写成 sum > target。
  • 空数组虽不属于原题通常使用的非空输入情境，此实现也会返回 0。
  • sum 使用 long，长度仍使用 int，与 Java 数组索引类型一致。

不能直接把这套证明用于含负数的数组。例如 target = 3、nums = [1, -1, 3]，该模板得到长度 3，却会漏掉长度为 1 的 [3]：删除左端的正数后和不够，但继续删除负数反而又会达标。“不够就停止收缩”在这里不成立。

面试时忘记怎么办

先从可靠的暴力解出发：“我可以枚举起点、向右累加，先保证答案正确，但最坏是平方级。”

接着抓住输入条件：“因为全是正数，右端扩张只会增加和，左端收缩只会减少和。两个端点可以一直向右走。”

写代码前，把动作说成三句话：加入右端；只要和达标，就先记录长度、再删除左端；没找到合法区间则返回零。

最后用示例中的 [3, 1, 2, 4] 手推，检查自己是否用了 while。若被问为什么不会漏解，就解释：被删除的起点已经贡献过合法答案，将来再延长只会更差。

一句话总结

正数保证窗口变化有方向：不够就扩，够了就连续缩，并在每次删除前记录答案。
