SkillEvaluator：给 AI 加技能，先测它有没有帮倒忙

给编程助手装了十几个技能，回答更长了，任务却未必做得更好。NVIDIA 开源的 SkillEvaluator，把“技能写得像不像样”和“智能体用了是否有效”分开评估。它进入本次 GitHub 日榜，值得维护技能库、交付 Agent 工作流的开发者关注。

📌 这个项目是干什么的

  • 第一层检查技能的结构、安全与运行环境兼容性。
  • 第二层分析指导内容的重复和语义重叠。
  • 第三层实际运行智能体，对比带技能与不带技能的任务结果。

它不是新的聊天助手，而是技能开发和验收工具。适合把反复使用的提示词整理成技能后，想建立质量门槛的个人或团队。

🔍 为什么值得关注

关键不是拿到一个总分，而是区分证据层次：格式正确，不代表没有安全问题；说明清晰，也不代表能提高任务成功率。

这种分层设计能减少无效投入。先查静态质量，再排查重复，最后把模型调用和沙箱预算花在效果对照上。给客户交付技能时，也更容易说清“检查过什么、还有什么没验证”，而不是只演示一次成功案例。

🧪 谁适合试，怎么开始

最短路径是跟随仓库 Quickstart，先跑随附的文本分析技能。准备 Git 和 uv 后：

git clone --depth 1 https://github.com/NVIDIA/SkillEvaluator.git
cd SkillEvaluator
uv run --python 3.13 skillevaluator quality-check \
  src/skillevaluator/tier3/reference_skills/text-analyzer \
  -r cli -r json -o reports/first-quality

这个入口不需要 API 密钥、GPU 或 Docker，安装完成后可离线运行。先看报告指出的问题，再替换成自己的技能目录，输出报告放在该目录之外。

下一步别急着跑全套：挑几条真实任务，明确预期产物和失败条件，再进入带技能与不带技能的对照评估。

⚠️ 使用提醒

静态质量检查不运行安全扫描，也不测智能体表现，不能把通过分数当成验收完成。完整安全检查还需配置扫描器；实时评估需要模型、智能体及沙箱，可能产生费用。

项目采用 Apache-2.0 许可证，目前标注为实验性、社区尽力支持，没有企业支持承诺。涉及模型评估时，要先确认技能文档和任务材料能否发送给所配置的服务商。
