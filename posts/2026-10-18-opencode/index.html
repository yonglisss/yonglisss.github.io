OpenCode：先让编程助手读懂仓库，再让它动手

接手陌生代码库时，最费时间的往往不是写代码，而是找到入口、理清调用关系。OpenCode 是开源 AI 编程助手，提供终端界面，也有桌面应用。它进入今天的 GitHub 日榜，但更值得关注的是一条具体工作流：先分析，确认方案，再修改。

📌 这个项目是干什么的

  • 面向需要读代码、改功能、维护项目的开发者，不是面向零基础用户的一键建站工具。
  • 在项目目录中启动后，可以围绕仓库提问，并用文件引用缩小讨论范围。
  • 内置分析与开发两类代理：分析模式默认禁止编辑文件，执行命令前需要许可；开发模式用于实际修改。

🔍 为什么值得关注

第一，把理解问题和执行修改分开。面对陌生项目，先让它解释某个接口的鉴权链路，比直接要求“重构整个模块”更容易检查，也更容易及时纠偏。

第二，把项目约定留在仓库里。官方入门文档介绍了初始化生成 AGENTS.md 的方式。检查后将它纳入版本管理，能让目录结构、编码习惯不再只依赖每轮对话重复交代。

第三，工具评价可以落到真实任务上。挑一个已有测试的小问题，对比定位速度、修改范围和测试结果，比比较回答是否流畅更有意义。

🧪 谁适合试，怎么开始

适合已有代码仓库、愿意检查差异和运行测试的开发者。

先看官方入门文档，确认选择的版本，再按对应指南安装、配置模型服务。在练习仓库启动后，先问：“这个接口从入口到数据库经过哪些文件？只解释，不修改。”核对文件位置后，再提交一个小改动需求。

验收只看三个结果：解释能否对上源码、差异是否超出需求、测试是否通过。本文依据官方资料整理，未做本机安装实测。

⚠️ 使用提醒

官网目前区分第一版与第二版文档，两者默认都使用 opencode 命令，不能按默认命令并存。仓库 README 与旧版文档的 npm 包名也不同，不要混用安装教程。

开源采用 MIT 许可证，不代表模型调用免费，也不代表代码不会发送给模型服务。试用前确认服务商、计费、代码保密要求，并保留 Git 回退点。分析模式也不是隔离运行环境。
