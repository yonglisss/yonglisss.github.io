团队接入 AI Agent 后，常见问题不是“不会调用模型”，而是上下文散落在聊天、代码托管、CI 和工单系统里，Agent 又往往共用高权限令牌，出了问题难追溯。Block 开源的 Buzz 尝试换一种做法：让人和 Agent 成为同一工作空间里的独立成员，用统一事件日志记录消息、代码变更、审批与工作流。它进入 GitHub 日榜，适合正在搭建多 Agent 研发流程的团队关注。

📌 这个项目是干什么的

  • Buzz 是可自托管的团队协作平台，桌面端、Agent 和脚本通过 WebSocket、REST 或 CLI 连接同一 Relay。
  • 底层采用 Nostr 事件模型；消息、反应、工作流步骤和 Git 事件都带签名，并进入统一审计链路。
  • Agent 拥有自己的密钥、频道成员关系和审计记录，不必伪装成人类账号或共享一枚全局令牌。
  • 项目由 Rust 单仓库构建，采用 Apache-2.0 许可证；当前桌面版最新 Release 为 v0.4.26。

🔍 为什么值得关注

第一，它把 Agent 从“聊天机器人”提升为可管理的协作成员。Agent 可以参与频道、检索历史、处理代码补丁和运行工作流，而权限与行为仍能按身份追踪。对于需要多个 Agent 并行工作的团队，这比给所有自动化脚本共用服务账号更清晰。

第二，Buzz 把沟通与研发活动建模为同类签名事件。分支讨论、评审决定、工作流运行和聊天记录可以留在一个检索与审计体系中，减少 Agent 为拼接上下文而跨多个系统抓取数据。这个思路比单纯再加一个 AI 聊天窗口更值得借鉴。

🧪 谁适合试，怎么开始

最适合两类读者：一是正在设计 Agent 权限、审计与协同机制的平台团队；二是愿意自托管、想验证“人机共用工作空间”的开发者。

只看界面可从 Releases 下载 macOS、Linux 或 Windows 安装包，但默认仍需可连接的 Relay。完整本地体验需要 Docker 与 Hermit；也可自行准备 Rust 1.88+、Node 24+、pnpm 10+ 和 just：

git clone https://github.com/block/buzz.git && cd buzz
. ./bin/activate-hermit
just setup && just build
just dev

建议先用测试仓库和低权限 Agent，验证频道协作、事件检索及审计链路，再考虑接入真实研发流程。

⚠️ 使用提醒

Buzz 仍处于快速迭代期，v0.4.26 之前连续多日发布新版本，接口与部署方式可能继续变化。它也不是安装桌面端就能替代 Slack 或 GitHub 的即用型产品：自托管 Relay 依赖 Postgres、Redis 等组件，生产部署、密钥保管、备份和权限设计都需要团队承担。

此外，“统一事件底座”是有价值的架构选择，但是否能降低实际协作成本，仍应通过小范围流程验证，而不是仅凭功能清单迁移现有系统。
