让 AI 直接编写 ECharts、Vega-Lite 等图表配置，常见问题不是不会画，而是配置冗长、标签拥挤、比例尺和布局容易出错。微软开源的 Flint 在自然语言与具体图表库之间增加了一层可编辑的可视化中间语言：Agent 只需描述数据字段、语义和图表类型，编译器负责补齐布局细节。项目当天进入 GitHub TypeScript 热门榜，适合正在做数据分析 Agent 或自动报告的团队关注。

📌 它解决什么问题

Flint 的核心不是再封装一套聊天界面，而是把“想表达什么”与“用哪个图表库渲染”分开：

  • 用 70 多种语义类型标注字段，例如价格、温度、排名和国家；
  • 根据数据量、画布尺寸和图表类型，推导比例尺、间距、标签与图例；
  • 同一份紧凑输入可编译为 Vega-Lite、ECharts、Chart.js、Plotly，或原生 Excel 图表；
  • 提供 MCP Server，让支持 MCP 的 Agent 查找模板、校验、渲染并打开交互式图表。

这种设计的价值在于：模型生成的是较短、可读的规范，确定性的编译器处理容易出错的配置细节。人仍能修改输入，也不必把业务流程绑定到单一渲染后端。

🔍 为什么现在值得关注

Flint 最新正式版本为 0.4.0，新增 38 种 Plotly 图表类型和 18 个可编辑的 Excel 原生模板；0.3.0 还加入了图表类型切换与属性编辑。它既能作为 TypeScript 库嵌入产品，也能作为 MCP 工具接入对话或编码环境，覆盖了“代码生成”和“Agent 调用”两条路径。

项目采用 MIT 许可证，由 Microsoft Research 与中国人民大学 IDEAS Lab 合作开发。相比让模型反复试错一份庞大的底层配置，它更像一个可验证、可替换后端的图表编译层。

🧪 谁适合试，怎么开始

适合开发数据问答、自动周报、研究分析和 BI 助手的团队。若只想体验 Agent 生成图表，可先查看官方在线编辑器，再按 MCP 指南配置：

npx -y flint-chart-mcp

若要在 TypeScript 项目里控制输入和输出，可安装核心库：

npm install flint-chart

建议先用一份小型、已脱敏的数据，比较同一输入在两个后端的输出，再决定是否接入现有报告流程。

⚠️ 使用提醒

Flint 仍处于 0.x 阶段，接口和模板可能继续变化；当前 Python 版本只是源码预览，尚未正式发布包。自动布局也不等于自动做对分析：字段语义、图表选择和结论仍需人工复核。MCP 读取本地 CSV、JSON 或 TSV 时，应限制可访问目录，不要把包含隐私或业务机密的文件直接交给未经审查的 Agent。
