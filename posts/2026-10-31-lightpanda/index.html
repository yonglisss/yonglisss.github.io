让 AI 抓取网页时，直接请求 HTML 可能漏掉 JavaScript 加载的内容，启动完整浏览器又会增加资源开销。Lightpanda 是为 AI 与自动化构建的无头浏览器，今天出现在 GitHub 日榜。它值得关注的不是性能口号，而是：你的任务是否真的需要完整浏览器。

📌 这个项目是干什么的

  • 用 Zig 编写，不是 Chromium 分支；提供 JavaScript 执行、DOM 操作、表单输入和 Cookie 等能力。
  • 支持把页面导出为 HTML 或 Markdown，适合给资料采集、网页问答准备输入。
  • 提供 CDP 服务，官方 README 给出了 Puppeteer 连接后提取页面链接的示例。

它更适合已有网页自动化任务的开发者，而不是想找一个日常上网软件的普通用户。

🔍 为什么值得关注

第一，把“访问网页”和“给人显示网页”分开考虑。对于取标题、找链接、抽正文的任务，先验证所需能力，比默认启动整套浏览器更有价值。

第二，保留现有自动化客户端的接入路径。可先拿一条 Puppeteer 流程试接 CDP，不必一开始就重写业务。不过，能连接协议，不等于原有脚本全部兼容。

官方提供了与 Headless Chrome 的性能对比，但测试页面、等待条件和机器环境都会影响结果。选型时应测自己的目标站点，不把宣传倍数直接当成成本预算。

🧪 谁适合试，怎么开始

先从 README 的 nightly 发布页下载对应平台二进制，运行 ./lightpanda version，再用一个允许自动访问的公开页面测试文本提取：

LIGHTPANDA_DISABLE_TELEMETRY=true ./lightpanda fetch --obey-robots --dump markdown https://example.com

接着选三类真实页面：静态文章、动态列表、需要交互的页面。检查正文是否完整、跳转是否正确，再与当前方案比较耗时和内存。先跑通一个小流程，不急着全量替换。

⚠️ 使用提醒

默认会发送使用遥测，上述环境变量用于关闭它。Linux 发布二进制依赖 glibc，不能直接假定 Alpine 可用；Windows 没有原生二进制，官方指向 WSL 安装路径。

仓库许可证为 AGPL-3.0，商业集成或修改后提供网络服务，应先评估具体义务。本文核验了官方说明，未做安装压测；涉及登录态、敏感资料和复杂站点时，仍需单独验证权限与兼容性。
