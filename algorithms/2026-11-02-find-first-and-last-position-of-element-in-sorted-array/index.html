查找元素的首尾位置：二分命中后，为什么还不能返回

题意和示例

给一个按非递减顺序排列的整数数组 nums，返回 target 第一次和最后一次出现的下标。不存在就返回 [-1, -1]，下标从 0 开始。

例如 nums = [5, 7, 7, 8, 8, 10]，查找 8 得到 [3, 4]；查找 6 得到 [-1, -1]。空数组也返回 [-1, -1]。

这里的“有序”允许重复元素。目标值一旦出现，就一定连成一段；任务是找出这一段的两端，而不是随便找一个命中位置。算法需要达到对数时间，不能命中后再向两侧逐个扫描。

考查点

  • 把普通二分改成边界搜索：相等时保留候选，但不结束。
  • 统一使用闭区间 [left, right]，让循环条件和更新规则一致。
  • 利用排序性质安全排除半个区间，而不是靠记忆拼出比较符号。
  • 处理空数组、全相等和查找失败，避免把插入位置误当成命中位置。

Java 代码

两次搜索都记录最后一次合法命中。左边界搜索命中后继续向左，右边界搜索则继续向右。

class Solution {
    public int[] searchRange(int[] nums, int target) {
        return new int[] {findLeft(nums, target), findRight(nums, target)};
    }

    private int findLeft(int[] nums, int target) {
        int left = 0;
        int right = nums.length - 1;
        int answer = -1;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] >= target) {
                if (nums[mid] == target) {
                    answer = mid;
                }
                right = mid - 1;
            } else {
                left = mid + 1;
            }
        }
        return answer;
    }

    private int findRight(int[] nums, int target) {
        int left = 0;
        int right = nums.length - 1;
        int answer = -1;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] <= target) {
                if (nums[mid] == target) {
                    answer = mid;
                }
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
        return answer;
    }
}

文字推导与正确性

先排除一个看似省事的办法

普通二分找到某个 8 后，再向左右扫描，确实能得到结果。但数组全是 8 时，扫描仍然遍历整个数组，最坏时间回到 O(n)。两端都必须用二分寻找。

找左端点：答案留在手里，更早的位置继续找

若 nums[mid] < target，根据有序性，mid 及其左侧都不可能是目标值，可以令 left = mid + 1。

若 nums[mid] > target，mid 及其右侧都过大，令 right = mid - 1。

关键是相等时：先记住 answer = mid，再令 right = mid - 1。右边即使还有目标值，下标也不会比当前候选更小，没有继续检查的价值。

循环始终保持：若存在比候选更靠左的目标位置，它一定还在待搜索区间内；尚未命中时，所有可能命中的位置也都保留在区间内。每一步排除的部分都不可能改善答案。区间变空后，候选就是最左位置；从未命中则仍为 -1。

找右端点：把“更小下标”换成“更大下标”

若 nums[mid] > target，向左搜索；若小于，则向右搜索。相等时保存 mid，同时向右继续。

同样地，可能比候选更靠右的答案不会被排除。终止时，保存的就是最右位置。

以示例中的 8 为例：左搜索依次检查下标 2、4、3，候选从 4 改成 3；右搜索检查下标 2、4、5，候选最终停在 4。于是返回 [3, 4]。

复杂度和边界

两次搜索都把区间规模近似减半，非空数组的总时间为 O(log n)，额外空间为 O(1)；空数组直接完成两次空循环。

  • 空数组：初始 right = -1，不访问任何元素。
  • 只有一个元素：相等返回 [0, 0]，不等返回 [-1, -1]。
  • 全部相等：两次搜索仍会收缩，返回 [0, n - 1]。
  • 目标缺失或在范围外：只有相等才更新候选，因此不会返回错误的插入下标。
  • 负数和重复值：只依赖有序关系，不要求元素非负。
  • 整数溢出：中点采用 left + (right - left) / 2，不用 left + right；也不通过搜索 target + 1 求右端点，因此无需承担目标值加一溢出的风险。

输入按题意应是非空引用且已排序的数组；null 或未排序数据不属于这份实现的输入契约。

面试时忘记怎么办

先写熟悉的普通二分骨架：闭区间、left <= right、中点加减一。不要一上来混用半开区间模板。

然后只问自己一个问题：“现在命中了，但我要更左的位置，下一轮还该查哪里？”答案是保存当前下标，再查左半边。把方向反过来，就得到右边界。

如果比较符号记不住，先分别写“小于、等于、大于”三种情况，确认每种情况排除的区间都安全，再合并分支。

最后手推 [8, 8] 查 8 和空数组查 8：前者能暴露命中后提前返回的问题，后者能检查循环是否越界。说明两次二分仍是对数时间，而不是线性扫描。

一句话总结

命中只说明当前下标可用；保存它，再朝需要的边界继续二分，才能找到整段重复值的两端。
