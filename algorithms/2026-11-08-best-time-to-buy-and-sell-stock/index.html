买卖股票的最佳时机：固定卖出日，只记住此前最低价

题意和示例

数组 prices 按日期记录股价。你最多完成一笔交易：选择一天买入，再选择后面的一天卖出。返回最大利润；没有盈利机会时，可以不交易，返回 0。

例如 prices = [7, 1, 5, 3, 6, 4]，在价格为 1 时买入、价格为 6 时卖出，利润为 5。不能用最早的 7 减去后面的 1：交易有时间方向。

对于 [7, 6, 4, 3, 1]，答案为 0，不是负数。这里也不允许把多次上涨的利润相加。

考查点

  • 将两个日期的枚举，压缩成一个卖出日期的枚举。
  • 用前缀最小值保存历史信息，不需要保存全部买入候选。
  • 精确定义状态的时间范围，保证买入严格早于卖出。

Java 代码

下面先用此前最低价计算利润，再把今天纳入最低价，避免把同一天当作买卖两端。

class Solution {
    public int maxProfit(int[] prices) {
        if (prices.length < 2) {
            return 0;
        }

        int minPrice = prices[0];
        int bestProfit = 0;
        for (int i = 1; i < prices.length; i++) {
            bestProfit = Math.max(bestProfit, prices[i] - minPrice);
            minPrice = Math.min(minPrice, prices[i]);
        }
        return bestProfit;
    }
}

文字推导与正确性

从暴力枚举里找重复工作

最直接的办法是枚举买入日 i 和卖出日 j，要求 i < j，比较 prices[j] - prices[i]。这样会产生平方级的日期组合。

把问题倒过来：如果已经决定今天卖出，应该在哪天买入？在今天之前价格最低的那天。卖出价格固定后，买入价格越低，利润越大。

所以没有必要逐个保存历史买入日，只需保存其中的最低价格。

两个变量各负责什么

进入下标为 i 的循环时：

  • minPrice 是区间 [0, i - 1] 的最低价。
  • bestProfit 是卖出日在 i 之前的所有合法交易与不交易方案中的最大利润。

先计算 prices[i] - minPrice，得到今天卖出的最优利润；再与旧答案比较。最后更新最低价，供下一天使用。

以 [7, 1, 5, 3, 6, 4] 为例：遇到 1 时，今天卖出会亏损，答案保持 0，但历史最低价变成 1；遇到 5 时得到利润 4；遇到 6 时答案提高到 5。

为什么没有漏掉更优交易

固定任何一个合法卖出日，代码使用的最低价都来自更早的日期，因此算出的候选交易合法。任何其他买入日的价格都不会比这个最低价更小，所以当天不存在更优利润。

循环检查了每一个可能的卖出日，并保留最大值，因此覆盖了全局最优交易。答案初始为 0，也覆盖了不交易的选择。

源稿先更新最低价再求利润也能得到相同答案：同日买卖只额外产生一个 0，不会提高答案。本版的顺序让“此前”这一状态含义更直接。

复杂度和边界

  • 时间复杂度为 O(n)：每个价格只处理一次。
  • 额外空间为 O(1)：只维护两个整数状态。
  • 只有一天时无法完成交易，返回 0；代码也对空数组返回 0。输入数组本身须非 null。
  • 全部相同、持续下跌时，答案保持 0；最低价重复出现不影响正确性。
  • 价格可以为 0。负数价格不属于本题股价输入的讨论范围。
  • 本题通常使用的非负小范围价格可用 int 存储利润；若接口推广为任意整数价格，减法应先转为 long，返回类型也须随之调整，不能沿用当前签名保证不溢出。

面试时忘记怎么办

先写出暴力式子：max(prices[j] - prices[i])，并标明 i < j。不要急着套动态规划模板。

然后固定 j，问自己：“这个减法要最大，前面的哪一个数最有用？”答案就是最小值，于是把内层枚举替换成一个历史最低价变量。

最后口述更新顺序：“今天先尝试卖出，用此前最低价更新最大利润，再把今天价格纳入历史。”补上一次扫描、常数空间即可。

如果面试官改成允许多次交易，先确认规则变化，再重新建模；不能直接沿用这份只做一笔交易的代码。

一句话总结

固定卖出日以后，所有历史买入候选都可以压缩成一个前缀最低价。
