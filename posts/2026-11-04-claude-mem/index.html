Claude-Mem：让 AI 接着上次工作，先验证它记住了什么

同一个项目开了新会话，又要解释目录结构、上次的报错和方案取舍。Claude-Mem 想减少的就是这类重复交接：记录工具使用中的观察，生成摘要，再供后续会话检索。它出现在本次 GitHub 周热门榜中，比起“永久记忆”的口号，更值得看的是信息如何被找回。

同一个项目开了新会话，又要解释目录结构、上次的报错和方案取舍。Claude-Mem 想减少的就是这类重复交接：记录工具使用中的观察，生成摘要，再供后续会话检索。它出现在本次 GitHub 周热门榜中，比起“永久记忆”的口号，更值得看的是信息如何被找回。

📌 这个项目是干什么的

  • 为 Claude Code 等智能体提供跨会话记忆，适合持续维护同一项目的开发者。
  • 通过生命周期钩子捕获工作过程，本地工作服务处理记录，SQLite 保存会话、观察和摘要。
  • 提供检索工具，让智能体查找过去的排错线索，而不是每次重读完整聊天记录。

🔍 为什么值得关注

关键设计是分层取回：先用 search 得到精简索引，再用 timeline 看附近发生了什么，最后按记录编号调用 get_observations 获取详情。

这比把历史全文塞进提示词更有借鉴价值：先定位，再展开。做自己的智能体产品时，也可以把“记多少”改成“当前任务需要取回什么”，并保留记录编号，让结论有出处可查。

🧪 谁适合试，怎么开始

先选不含客户资料的小项目，准备 Node.js 20 或以上及支持插件的 Claude Code。在 Claude Code 内按官方说明安装：

/plugin marketplace add thedotmack/claude-mem
/plugin install claude-mem

重启后记录一次真实排错，再开新会话询问原因和处理方式。检查三件事：有没有找到正确记录、是否混入无关项目、能否追溯到原始观察。本文核验了文档与示例，未实测安装效果。

⚠️ 使用提醒

记忆摘要不是事实保证，过期决策和错误解释也可能被保存，重要结论仍要对照代码与测试。

本地存储不等于数据全程离线。官方安装器提供托管观察服务及其他模型提供方选项，试用前要核对推理数据去向、账号与费用，别直接接入公司敏感仓库。

开源核心采用 Apache-2.0；官方另列托管云、团队同步等商业边界，不能把开源等同于所有服务免费。
