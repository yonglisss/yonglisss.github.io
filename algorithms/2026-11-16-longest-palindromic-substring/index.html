最长回文子串：先找中心，再推边界

题意和示例

给定字符串 s，返回其中最长的一段回文子串。子串必须连续；回文要求从两端向中间读到的字符逐一相同。

例如 s = "babad"，可以返回 "bab"，也可以返回 "aba"。题目不要求最长答案唯一。s = "cbbd" 时则应返回 "bb"，不能把不连续的字符拼成答案。

下文按原题的英文字母、数字场景处理字符。代码额外兼容 null 和空字符串，返回空串；这属于防御性处理，不是要求调用方必须传入这些值。

考查点

  • 把“枚举连续区间”换成“枚举对称中心”，避免逐个子串重新判断回文。
  • 同时覆盖单字符中心和两字符之间的中心，不能漏掉偶数长度答案。
  • 分清扩展失败时的指针与最后有效区间，写对长度及 Java 的截取边界。

Java 代码

主循环只维护最佳起点和长度；辅助函数返回给定中心能够扩出的最大长度。

class Solution {
    public String longestPalindrome(String s) {
        if (s == null || s.isEmpty()) {
            return "";
        }

        int bestStart = 0;
        int bestLength = 1;
        for (int i = 0; i < s.length(); i++) {
            int odd = expand(s, i, i);
            int even = expand(s, i, i + 1);
            int length = Math.max(odd, even);
            if (length > bestLength) {
                bestStart = i - (length - 1) / 2;
                bestLength = length;
            }
        }
        return s.substring(bestStart, bestStart + bestLength);
    }

    private int expand(String s, int left, int right) {
        while (left >= 0 && right < s.length()
                && s.charAt(left) == s.charAt(right)) {
            left--;
            right++;
        }
        return right - left - 1;
    }
}

文字推导与正确性

为什么枚举中心

最直接的暴力方法枚举所有子串，再逐一检查两端字符，总时间最坏为 O(n³)。问题在于：许多重叠区间的内部字符被反复检查。

换一个起点：已经确认中间是回文后，往外多包一层，只需判断新增的两个字符是否相同。对同一个中心，检查可以持续向外推进，不必重新检查内部。

"aba" 的中心是 b，初始指针为 (i, i)；"abba" 的中心是两个 b 之间，初始指针为 (i, i + 1)。主循环把这两种情况都交给同一个扩展函数。

失败的指针为什么还能算长度

以 "cbbd" 为例，在 i = 1 处检查偶数中心：left = 1、right = 2，两个字符都是 b，于是向外移动为 (0, 3)。此时 c 与 d 不同，循环停止。

停止时有效区间不是 [left, right]，而是 [left + 1, right - 1]。所以长度为：

(right - 1) - (left + 1) + 1 = right - left - 1。

一开始就不匹配的偶数中心会返回 0；扩展到字符串外侧时，这个公式也成立。

起点公式如何同时覆盖奇偶

如果长度为 2k + 1，单字符中心在 i，起点就是 i - k。如果长度为 2k，中心在 i 和 i + 1 之间，起点就是 i - k + 1。

用 Java 整数除法统一写，就是 i - (length - 1) / 2。返回结果时用起点加长度作为右侧开区间边界，避免把闭区间终点直接传给 substring。

为什么不会漏掉最优答案

任何非空回文都有且只有一个确定的几何中心：要么落在字符上，要么落在相邻字符之间。循环覆盖了所有这些中心。

对固定中心，只要新增的左右字符相等，扩展后仍是回文；遇到不等字符或边界就不能继续。因此辅助函数得到的是该中心的最长回文。比较所有中心的结果，就得到全局最长答案。

代码仅在严格更长时更新，因此同长答案保留先遇到的那一段。这符合题目允许返回任意最长答案的要求。

复杂度和边界

  • 时间复杂度 O(n²)。中心数量为 O(n)，每次最多比较 O(n) 对字符；全是相同字符时会接近最坏情况。
  • 额外工作空间 O(1)。这里只保留下标和长度，不使用动态规划表；若计入现代 Java 返回子串所需的存储，还需 O(L)，其中 L 是答案长度。
  • 单字符返回自身；"ab" 返回 "a"；"aaaa" 返回整串；"cbbd" 用来检查偶数中心。
  • 大小写按字符精确比较，不做转换。数字字符同样参与比较；本题没有数值加减，负数及数值溢出不是输入处理重点，合法题目规模内下标和长度可用 int。
  • Java 的 charAt 按 UTF-16 编码单元访问。若扩展到含补充平面字符的任意文本，需要另行定义“字符”并按码点处理，不能直接宣称这份代码覆盖所有 Unicode 场景。

面试时忘记怎么办

先写出两个例子："aba" 和 "abba"。它们会提醒你：中心有两类，不是每个回文都围绕单个字符。

然后只写扩展函数，在纸上跟踪 "cbbd" 的 (1, 2)。停在 (0, 3) 后，把有效区间标成 [1, 2]，长度公式就能现场推出来，不必死记。

若起点公式卡住，先分别推奇数和偶数长度，再合并。最后补一句：枚举所有中心，每个中心扩展到不能扩，所以不会漏掉最长回文，时间 O(n²)，额外工作空间 O(1)。

一句话总结

回文子串不必从两端猜起：穷举奇偶中心，向外验证对称，失败后退回有效边界。
