两个正序数组的中位数：把二分目标换成切分位置

题意和示例

给定两个按非递减顺序排列的整数数组，返回它们合在一起后的中位数。两个数组可以有一个为空，但不能同时为空；元素可以重复，也可以是负数。

例如 nums1 = [1, 3]、nums2 = [2]，合并后的顺序是 [1, 2, 3]，答案为 2.0。如果输入为 [1, 2] 和 [3, 4]，中间两个数是 2、3，答案为 2.5。

题目要求时间复杂度达到 O(log(m + n))。直接归并虽然容易写对，但需要线性时间，不能作为最终解法。

原题：寻找两个正序数组的中位数。下文基于有序、总长度至少为一的输入，不负责检查数组是否有序。

考查点

  • 二分的对象不是某个元素，而是较短数组左侧应当取几个数。
  • 用一个数量等式固定分区规模，再用两个跨数组的不等式判断分区是否正确。
  • 根据“左边取多了还是取少了”确定移动方向，而不是背更新公式。
  • 处理切在数组首尾、重复元素，以及偶数长度求平均的类型提升。

Java代码

i、j 都表示左分区从对应数组取出的元素数量，因而切分位置允许等于数组长度。

class Solution {
    public double findMedianSortedArrays(int[] nums1, int[] nums2) {
        if (nums1.length > nums2.length) {
            return findMedianSortedArrays(nums2, nums1);
        }
        int m = nums1.length;
        int n = nums2.length;
        if (m + n == 0) {
            throw new IllegalArgumentException("Both arrays are empty");
        }

        int half = (m + n + 1) / 2;
        int low = 0;
        int high = m;
        while (low <= high) {
            int i = low + (high - low) / 2;
            int j = half - i;

            int leftA = i == 0 ? Integer.MIN_VALUE : nums1[i - 1];
            int rightA = i == m ? Integer.MAX_VALUE : nums1[i];
            int leftB = j == 0 ? Integer.MIN_VALUE : nums2[j - 1];
            int rightB = j == n ? Integer.MAX_VALUE : nums2[j];

            if (leftA > rightB) {
                high = i - 1;
            } else if (leftB > rightA) {
                low = i + 1;
            } else {
                int maxLeft = Math.max(leftA, leftB);
                if ((m + n) % 2 == 1) {
                    return maxLeft;
                }
                int minRight = Math.min(rightA, rightB);
                return ((long) maxLeft + minRight) / 2.0;
            }
        }
        throw new IllegalArgumentException("No valid partition");
    }
}

文字推导与正确性

先决定左侧需要几个数

中位数把有序序列分成两部分。我们约定总数为奇数时，多出来的那个数放在左侧。因此左分区总量固定为：

half = (m + n + 1) / 2。

较短数组向左侧贡献 i 个元素，另一个数组就必须贡献 j = half - i 个。这样二分只剩一个自由变量。

为什么先换成短数组？当 m <= n、0 <= i <= m 时，有 m <= half <= n，所以 0 <= j <= n。既缩小搜索范围，也保证另一个切分位置不会越界。

数量对了，再检查大小

每个数组内部已经有序，所以各自左侧的数都不大于各自右侧。唯一还需要检查的是跨数组关系：

  • A 左侧最大值不能大于 B 右侧最小值，即 leftA <= rightB。
  • B 左侧最大值不能大于 A 右侧最小值，即 leftB <= rightA。

这两条成立，就保证整个左分区的任意元素都不大于整个右分区的任意元素。左边最大值便是奇数长度的中位数；偶数长度则取左边最大值与右边最小值的平均。

失败时为什么可以排除半边

若 leftA > rightB，A 给左分区的数太多了。继续增大 i 只会让 leftA 不减，同时 j 减小让 rightB 不增，矛盾不可能消失。因此 i 及其右侧都可排除，执行 high = i - 1。

若 leftB > rightA，A 给左分区的数太少。减小 i 会让 rightA 不增、leftB 不减，仍不可能修复，故执行 low = i + 1。

合法输入必然存在这样的分区：想象从完整有序序列左侧取出 half 个元素，它们在两个原数组中分别对应前缀。二分每次只丢弃不可能成立的切分，最终必能找到一个合法位置；重复值可能使合法位置不唯一，但答案一致。

用一个偶数示例走一遍

输入 A 为 [1, 2]，B 为 [3, 4]，half = 2。

  1. 初始 i = 1、j = 1，四个边界为 1、2、3、4。因为 leftB = 3 > rightA = 2，A 左边取少了。
  2. 移到 i = 2、j = 0。A 左侧最大值为 2，B 右侧最小值为 3；另外两侧为空，用哨兵参与比较。
  3. 两条跨数组关系成立，答案为 (2 + 3) / 2.0 = 2.5。

复杂度和边界

设较短数组长度为 s = min(m, n)。搜索的是 s + 1 个切分位置，时间复杂度可写为 O(1 + log(s + 1))，额外空间为 O(1)。交换参数至多递归一次，不会产生随输入增长的调用栈。

  • 一个数组为空： 短数组只有 i = 0 这一种切法，直接从另一个数组的中央边界求答案。
  • 全部相等或含重复值： 合法条件使用 <=，相等不需要移动切分。
  • 负数与首尾切分： 缺失的左边界用 Integer.MIN_VALUE，缺失的右边界用 Integer.MAX_VALUE。这里只比较大小，真实元素等于哨兵也不影响判断。
  • 平均值溢出： 先转为 long 再相加，不能先做两个 int 的加法再转型。这样也能处理两个元素都接近整数极值的情况。
  • 长度运算： 代码假定两个数组长度之和可用 int 表示，符合本题的小规模数组场景；这不等于对任意超大数组提供通用长度保障。
  • 非法输入： 两个空数组明确抛异常；null 和未排序数组不在题意约定内，末尾异常不能代替完整输入校验。

面试时忘记怎么办

先写出归并到中间的线性方案作为基线，说明它正确但没有达到对数要求。接下来不要硬背四个变量，先问自己：“如果中位数左右各需要固定数量的元素，我能否直接寻找分界线？”

在纸上写出这三行，就能恢复主体：

  1. i + j = (m + n + 1) / 2，所以只需二分 i。
  2. 画出两个数组切口，标记左侧最后一个和右侧第一个元素。
  3. leftA > rightB 意味着 A 左边取多了；反过来则取少了。

写完后用“短数组为空”和 [1, 2] + [3, 4] 检查切口边界与奇偶分支，再检查平均值是否先转为 long。这比只口述“用二分”更能展示推导能力。

一句话总结

固定左侧数量，在较短数组上二分切口；两条跨数组大小关系成立时，中位数只由切口边界决定。
