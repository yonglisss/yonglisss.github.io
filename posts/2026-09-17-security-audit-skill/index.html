让编码 Agent “找漏洞”很容易，难的是避免把猜测写成结论，并证明审查真正覆盖了哪些攻击面。Cloudflare 开源的 Security Audit Skill 给出了一套更严谨的做法：把代码安全审计拆成侦察、覆盖驱动排查、候选验证、结构化输出、独立复核和报告六个阶段，让发现过程可以追踪、检查和重复执行。

📌 这个项目是干什么的

它不是新的扫描器或漏洞数据库，而是一套供支持工具调用与并行子 Agent 的编码 Agent 使用的审计工作流。完整模式会先梳理架构、信任边界和输入面，再用 coverage-ledger.json 记录覆盖情况；每个候选问题交给新的验证 Agent 尝试证伪，最终写入 findings.json。

结果被明确分成三类：证据完整的 confirmed、仍有关键事实待核实的 needs_validation，以及已被证伪的 rejected。仓库还提供零依赖的 Node.js 校验器和 JSON Schema，检查覆盖账本与发现记录。项目采用 MIT 许可证，当前没有正式 Release 标签。

🔍 为什么值得关注

第一，把“找问题”和“确认问题”分开。 发现候选的 Agent 不负责最终背书，独立验证者优先尝试推翻它，能减少模型顺着自己先前结论继续编证据的风险。

第二，覆盖范围不再只靠一句“已全面检查”。 工作流把攻击面拆成可记录单元，并保留已检查、延期、阻塞和超出范围等状态。多次运行还能沿用旧账本，优先补空白、复查变化过的源码。

第三，输出适合进入工程流程。 严重度只能建立在已证明的影响上；无法安全执行或缺少部署事实时，结果必须停留在待验证状态。机器可读记录经过校验后再生成报告，比直接复制一段聊天结论更便于复核。

🧪 谁适合试，怎么开始

它适合维护 API、服务端、CLI、基础设施或 AI 应用的安全工程师与研发团队，也适合正在搭建内部 Agent 审计流程的人。先在非生产的小型仓库试用：

npx skills add https://github.com/cloudflare/security-audit-skill \
  --skill security-audit

随后让兼容的编码 Agent 对代码库执行安全审计。第一次不要追求“扫完整仓库”，可以限定一个熟悉的模块，重点检查覆盖账本、证据链和三类 verdict 是否经得起人工复核。

⚠️ 使用提醒

完整流程要求模型支持工具调用和并行子 Agent，并需要 Node.js。更关键的是，目标代码的构建、测试、模糊测试等执行必须放进禁外网、限制资源、隔离环境变量和写入路径的 OS 级沙箱；做不到时，不应执行不可信代码，只能把线索标为待验证。

它提供的是审计方法，不是“自动发现全部漏洞”的保证。官方也强调单次运行无法穷尽目标；高风险项目仍需人工审查、静态分析、测试和授权范围内的专业安全验证。
