AI 编程助手用久后，真正稀缺的往往不是模型能力，而是上下文空间。日志、网页快照、搜索结果和几十个文件一股脑进入对话，很快就会触发压缩，关键任务状态也可能随之丢失。今日进入 GitHub Trending 的 Context Mode，尝试用 MCP、沙箱执行与本地检索，把原始数据挡在上下文之外，只把需要的结果交给模型。

📌 这个项目是干什么的

Context Mode 面向 Claude Code、Codex CLI、Gemini CLI、OpenCode、Cursor 等 AI 编程客户端。它提供三类核心能力：

  • 在隔离进程中处理日志、CSV、构建输出等大体量数据，只返回统计或摘要；
  • 将文档和代码片段写入 SQLite FTS5 索引，按需用 BM25 检索相关段落；
  • 记录文件编辑、Git 操作、任务、错误和用户决策，在会话压缩后恢复必要上下文。

它更像 AI Agent 的“数据处理层”，不是替代模型，也不会自动让代码质量变高。

🔍 为什么值得关注

第一，它解决的是开发工作流中的真实浪费。 很多工具调用只是为了从大量输出中找几行错误，没必要让模型完整阅读。让程序先筛选、聚合，再把结果交给模型，既节省上下文，也减少模型做机械计算的机会。

第二，它把短期压缩和长期检索分开。 日志适合执行脚本后只留结论，API 文档和代码示例则需要保留原文、按需检索。Context Mode 针对两类数据提供不同路径，比“一律总结”更稳妥。

项目仓库给出的可复现实验覆盖 21 个场景：376KB 原始数据最终占用 16.5KB 上下文，整体节省 96%。但这仍是项目方基准，实际收益取决于任务、客户端适配和检索命中率，不能直接理解为所有会话都能节省 98%。

🧪 谁适合试，怎么开始

如果你经常让 Agent 分析长日志、浏览器快照、大型文档或多文件代码库，可以先试 MCP 模式。项目要求 Node.js 22.5 及以上；以 Claude Code 为例，最短验证路径是：

claude mcp add context-mode -- npx -y context-mode

安装后先选一个可重复的小任务，对比启用前后的工具输出、上下文占用与答案完整性。若效果稳定，再按官方文档启用 Hook，让客户端自动把大输出路由到沙箱或索引。不要一开始就把整个私有代码库导入。

⚠️ 使用提醒

沙箱执行和本地索引会增加一层依赖，也可能因摘要或检索不准遗漏细节；遇到安全、财务或生产故障分析，仍应回看原始数据。项目使用 Elastic License 2.0，并非 MIT/Apache：允许使用、复制和修改，但限制将其主要功能作为托管服务提供给第三方，企业集成前应先审查许可证。
