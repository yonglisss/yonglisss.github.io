合并 K 个排序链表：堆里只放每一路的候选节点

题意和示例

给定一个链表头节点数组，每条链表已经按非递减顺序排列。把全部节点合成一条仍然有序的链表，返回结果的头节点。重复值要保留，不能只返回去重后的数值。

例如，输入三条链表 [1,4,5]、[1,3,4]、[2,6]，输出为 [1,1,2,3,4,4,5,6]。

数组没有元素，或者数组中的链表全部为空时，结果都是空链表。下面按各条输入链表无环、节点不共享的通常链表模型讨论；实现直接复用节点，会改变原链表的连接关系。算法不依赖节点值为正，也不依赖某个固定数值上界。

原题：LeetCode 23：Merge k Sorted Lists。

考查点

  • 利用每一路已经有序的条件，把比较范围缩小到当前表头。
  • 用最小堆维护动态候选集，而不是每次重新扫描所有表头。
  • 正确移动结果尾指针，并补入刚取出节点的后继。
  • 区分复用节点与新建结果节点，准确说明额外空间和输入是否被修改。

Java 代码

ListNode 使用题目提供的定义，含 int val、ListNode next 和接收节点值的构造方法。

import java.util.PriorityQueue;

class Solution {
    public ListNode mergeKLists(ListNode[] lists) {
        if (lists == null || lists.length == 0) {
            return null;
        }

        PriorityQueue<ListNode> heap = new PriorityQueue<>(
            (a, b) -> Integer.compare(a.val, b.val)
        );
        for (ListNode head : lists) {
            if (head != null) {
                heap.offer(head);
            }
        }

        ListNode dummy = new ListNode(0);
        ListNode tail = dummy;
        while (!heap.isEmpty()) {
            ListNode node = heap.poll();
            ListNode next = node.next;
            tail.next = node;
            tail = node;
            if (next != null) {
                heap.offer(next);
            }
        }
        tail.next = null;
        return dummy.next;
    }
}

lists == null 是额外防御性处理。比较器使用 Integer.compare，不写 a.val - b.val，这样即使节点值扩展到整个 int 范围，也不会因减法溢出破坏堆的顺序。

文字推导与正确性

先找到真正需要比较的位置

如果每次在 K 个当前表头中扫描最小值，再把对应表头后移，思路完全正确，但处理 N 个节点最多需要 O(NK) 时间。

这里没有必要比较链表内部的每个节点。某条链表当前头节点后面的值都不小于它，所以这一条链表能参与下一次竞争的，只需要头节点。

于是问题变成：反复从至多 K 个候选节点里取最小值，并更新其中一路。最小堆正适合这个操作。

堆里保存什么

初始化时，每条非空链表只放入一个头节点。例子中的堆先保存值为 1、1、2 的三个节点，而不是一次性保存全部八个节点。

假设弹出的是第一条链表的 1，把它接到结果后，该链表新的候选就是 4。把这个后继放回堆，下一轮仍然只比较每条尚未耗尽链表的第一个未输出节点。

相同值的节点谁先弹出都可以；题目要求数值有序，不要求不同链表之间保持稳定次序。

为什么不会漏节点或选错节点

维护两个不变量：结果前缀已经有序；每条还有未输出节点的链表，恰有一个当前候选在堆中。

任何未输出节点都不小于自己所在链表的当前候选。因此，堆顶不仅是候选中的最小值，也是所有未输出节点中的最小值。把它接到结果尾部，前缀仍然有序。

弹出后只补入同一路的后继，候选集不变量继续成立。每个节点只会在前驱被取出时进入堆一次，头节点则在初始化时进入；因此既不遗漏，也不重复。堆空时所有链表已经耗尽，结果就是完整的有序合并。

代码先保存 next，再接入结果，明确区分“输入这一条链表的后继”和“结果链表的尾部”。结束时把尾部指向空，完成结果的收尾。

复杂度和边界

设 K 是数组长度，N 是全部节点数，H 是非空链表数。

  • 扫描数组需要 O(K)，逐个放入初始候选最多需要 O(H log(H+1))。
  • 每个节点入堆、出堆各一次，堆最多有 H 个节点。统一写为 O(K + N log(H+1)) 时间；通常 K 不小于 2 时，也常简写为 O(K + N log K)。
  • 额外空间为 O(H+1)：堆中的节点引用以及一个哑节点。没有复制 N 个节点。

保留 O(K) 很重要：即使数组里都是空链表、N 为零，也必须扫描整个输入数组。

需要检查的边界包括：没有链表、全部为空、只有一条非空链表、负数、所有节点值相同，以及各条链表长度差距很大。空节点不能入 PriorityQueue。哑节点的值是占位符，不参与大小比较，因此取 0 不会影响负数输入。

如果调用方要求保留原始链表，应改为新建结果节点，并把新增节点空间计入成本。输入带环或不同链表共享节点不属于这里的模型，不能直接套用这段原地拼接代码。

面试时忘记怎么办

先不背堆的模板，画出三条有序链表，问自己：“下一个最小值可能藏在某一路的中间吗？”答案是否定的，它只能来自某个当前表头。

接着先讲能写出来的方案：“每轮扫描所有表头，取最小的并后移。”再指出瓶颈是重复找最小值，于是用最小堆替换扫描。这比直接报出数据结构更能说明推导过程。

编码时记住三个动作：弹出节点、接到结果、补入后继。检查初始化是否跳过空链表，以及比较器是否使用安全比较。

最后解释复杂度：“堆只放每一路的一个候选，不是全部 N 个节点；还要算上扫描 K 个输入位置的成本。”如果追问替代解法，可以补充两两分治归并，但不必把两种实现混在一起。

一句话总结

多路归并的关键不是把全部数据装进堆，而是让每一路始终只有一个当前候选参与竞争。
