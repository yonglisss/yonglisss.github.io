多个 Agent 一起工作时，真正浪费时间的往往不是模型不会做，而是每个新会话都要重新理解项目、重复踩坑。腾讯开源的 TencentDB Agent Memory 试图把对话、操作经验、文档和代码统一整理成可管理的记忆资产。项目当天登上 GitHub 热门榜，适合正在搭建编码 Agent 团队或内部 AI 工作台的开发者关注。

📌 它解决什么问题

TencentDB Agent Memory 不只是保存聊天记录，而是把可复用信息分成四类：

  • Chat Memory：从原始对话逐层提取事实、场景和长期画像；
  • Skill：把跑通的任务沉淀为带步骤、资源和验证规则的 SOP；
  • Wiki：把文档整理成结构化页面与链接图谱；
  • CodeGraph：索引文件、代码符号、调用关系和影响路径。

这些资产由 Memory Hub 统一管理，可以设置 Owner、版本、状态和可见范围，再按角色“配装”给不同 Agent。例如，开发 Agent 使用产品 Wiki 和 CodeGraph，评审 Agent额外获得事故记录与发布检查 Skill，避免把所有历史一股脑塞进每个上下文。

🔍 为什么值得关注

很多 Agent 记忆方案主要回答“能否检索到”，这个项目进一步处理“谁能用、哪个版本有效、应该交给哪个 Agent”。其 private、team、restricted 与定向 Agent 授权，也让团队共享经验时保留权限边界。

最新发布的 v2.0.0-beta.1 首次完整开源 Memory Core、Hub、Knowledge、Proxy 和 SDK。Proxy 兼容 Anthropic 与 OpenAI 协议，可在每轮请求中注入指定 Agent 的记忆、Skill、Wiki 和 CodeGraph。项目采用 MIT 许可证，并提供中文 README、安装指南、Docker 镜像和演示。

🧪 谁适合试，怎么开始

适合有多个编码 Agent、需要跨会话保留项目约束，或想让团队 SOP 持续积累的开发者。建议先在脱敏的测试仓库验证完整链路：

git clone https://github.com/TencentCloud/TencentDB-Agent-Memory.git
cd TencentDB-Agent-Memory/deploy/global-images
cp .env.example .env
# 填写 memory 与 proxy 使用的模型地址、模型名和 API Key
./verify.sh
./start-all.sh

启动后访问 http://localhost:8125，先创建业务用户，再建立 Team、Agent 和可选 Task。不要一开始导入全部资料，先选一份项目文档和一个公开代码库，观察召回内容、权限与 Token 开销是否符合预期。

⚠️ 使用提醒

Team Memory 仍是 Beta：接口、镜像和资产结构可能变化，生产接入前要固定版本并备份数据。官方说明 CodeGraph 当前优先支持公开 HTTPS 仓库，私有仓库与 SSH 凭证仍在完善；全自动记忆路由也还在迭代。部署会启动 Core、Panel、Knowledge 和 Proxy 等多个服务，并需要两组模型配置，复杂度明显高于单机向量库。记忆中可能包含源码、决策和个人信息，务必先验证 ACL、数据保留策略与模型服务的数据边界。
