下一个排列：为什么交换以后，只需要反转后缀？

题意和示例

给定一个非空整数数组 nums，将它原地改成字典序中紧接着它的排列。元素可以重复；如果当前已经是最大的排列，就回到最小的排列。只允许使用常数级额外空间。

字典序比较的是两组序列第一个不同的位置，不是把整个数组拼成一个整数。

  • [1, 2, 3] → [1, 3, 2]：只动最后两位就能得到更大的排列。
  • [1, 3, 2] → [2, 1, 3]：最后两位已经无法变大，必须调整第一位。
  • [3, 2, 1] → [1, 2, 3]：没有更大的排列，回到起点。
  • [1, 1, 5] → [1, 5, 1]：相等元素不妨碍寻找下一个排列。

原题：LeetCode 31 · Next Permutation。

考查点

这题不是回溯枚举题。生成全部排列再排序，既浪费时间，也违背常数额外空间要求。

真正需要解释的是三个选择：

  1. 为什么要尽量晚地改变某一位？因为越靠左的差异，越先决定字典序。
  2. 为什么从右边找交换对象？因为待处理后缀已经单调不增，可以直接找到最小的严格更大值。
  3. 为什么最后不用排序？因为交换后仍能保持后缀单调不增，反转就足够。

注意这里说的是“单调不增”，包含相邻元素相等的情况，不是严格降序。

Java 代码

方法直接修改 nums，不返回新数组。输入按题意为非空、非 null 数组。

class Solution {
    public void nextPermutation(int[] nums) {
        int pivot = nums.length - 2;
        while (pivot >= 0 && nums[pivot] >= nums[pivot + 1]) {
            pivot--;
        }

        if (pivot >= 0) {
            int successor = nums.length - 1;
            while (nums[successor] <= nums[pivot]) {
                successor--;
            }
            swap(nums, pivot, successor);
        }

        reverse(nums, pivot + 1, nums.length - 1);
    }

    private void reverse(int[] nums, int left, int right) {
        while (left < right) {
            swap(nums, left, right);
            left++;
            right--;
        }
    }

    private void swap(int[] nums, int a, int b) {
        int temp = nums[a];
        nums[a] = nums[b];
        nums[b] = temp;
    }
}

文字推导与正确性

1. 先找到不能再靠右的修改位置

从右向左扫描，只要 nums[pivot] >= nums[pivot + 1] 就继续向左。

循环停止时，pivot 右边的后缀是单调不增的。它已经是这批元素能组成的最大排列，单独重排这段后缀，不可能让整个数组变大。

如果找到了 nums[pivot] < nums[pivot + 1]，就可以提高这一位，同时保留它左边的前缀。改变更靠左的位置会得到更大的跳跃，因此这里是最优的修改位置。

若一直退到 -1，整个数组都单调不增，说明当前就是最大排列。直接反转整个数组，便得到最小排列。

2. 将这一位提高到最小的可用值

以 [2, 4, 3, 3, 1] 为例，后缀 [4, 3, 3, 1] 已经单调不增，转折点是首位的 2。

从最右侧向左找第一个严格大于 2 的元素，会找到右边那个 3。交换得到：

[2, 4, 3, 3, 1]
          ↑
[3, 4, 3, 2, 1]

由于后缀从左到右不增，从右边找到的第一个合格元素，就是后缀中严格大于转折点的最小值。若误用“大于等于”，可能只交换两个相等元素，根本没有得到更大的排列。

successor 不需要额外判断是否越界：转折点右邻居已经严格大于它，因此后缀中一定存在交换对象。

3. 把剩余后缀压到最小

转折点变大之后，后面的部分应尽可能小。上例只需把 [4, 3, 2, 1] 反转，得到 [3, 1, 2, 3, 4]。

关键是证明交换后仍然可以反转，而不是重新排序。

设转折点原值为 x，交换位置原值为 y。这个位置左侧的后缀元素都不小于 y，当然也大于 x；它右侧的元素都不大于 x，否则从右往左时会先选中它们。

所以用 x 替换 y 后，后缀依然单调不增。反转自然得到单调不减的最小排列。

三步合在一起：保持最长前缀不变，将下一位提高到最小可行值，再取最小后缀。任何其他更大排列，都不可能比这个结果更接近原数组。

复杂度和边界

  • 时间复杂度 O(n)：找转折点、找交换对象、反转，最多做常数次线性扫描。
  • 额外空间 O(1)：只用下标和交换临时变量，没有复制数组。
  • 单元素数组：pivot 从 -1 开始，反转区间只有一个元素，数组不变。
  • 全部相等：找不到转折点，整体反转后仍不变，这是正确的回绕结果。
  • 重复元素：第一次扫描使用 >=，第二次使用 <=，不能改成严格比较。
  • 完全不增：必须反转整个数组，不能直接返回。
  • 数值安全：只比较和交换元素，不把排列转换为整数，也不对元素做加减，因此不存在元素算术溢出问题。即使扩展到负数或 int 极值，比较逻辑也成立。

测试应至少覆盖 [1]、[2, 2, 2]、[3, 2, 1]、[1, 1, 5]、[1, 5, 1]，以及上面含重复元素的完整推导。

面试时忘记怎么办

先拿 [1, 3, 2] 问自己：“只动最后两位，还能变大吗？”不能，因为 [3, 2] 已经最大。于是第一步不是背代码，而是定位这个“已经最大”的后缀。

接着说：“我必须提高后缀前面那一位，但只提高一点，所以找后缀里最小的严格更大值。”用后缀不增的性质，就能自然推出从右往左找。

最后检查提高这一位以后，尾巴是否已经最小。若不是，就把仍然不增的尾巴反转。补充说明没有转折点时整体反转，再给出 O(n) 时间和 O(1) 空间。

记不清比较符号时，用 [1, 1, 5] 检验：相等不算变大，所以转折点和交换对象都必须体现“严格更大”。

一句话总结

下一个排列不是随便交换，而是保留最长前缀、最小幅度提高下一位，再用反转得到最小后缀。
