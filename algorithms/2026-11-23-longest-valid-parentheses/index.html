最长有效括号：栈顶为什么是长度的左边界

题意和示例

输入一个只由 (、) 构成的字符串，返回其中最长的、括号能完整匹配的连续子串长度。没有合法片段时返回 0，空字符串也返回 0。

例如 ")()())" 的答案是 4，对应中间的 "()()"；"(()" 的答案是 2，不是 3。

这里的限制是连续。"())(()" 虽然能挑出两对括号，但不能跳过中间的字符把它们拼在一起，答案仍然是 2。

原题链接：LeetCode 32 · Longest Valid Parentheses。代码按题目约定接收非 null 的括号字符串，不为其他字符定义行为。

考查点

  • 用栈处理最近出现、尚未匹配的左括号。
  • 把字符匹配转成下标运算：配对成功后，如何求整个连续合法后缀，而不只是这一对的长度。
  • 用哨兵统一处理从下标 0 开始的答案。
  • 区分两类障碍：尚未闭合的左括号，以及已经无法匹配的右括号。

只计数成功配了几对不够：它会丢掉区间是否连续的信息。栈里应该存位置，而不是字符。

Java代码

使用 ArrayDeque<Integer> 实现下标栈。栈底保存边界，其上保存还没有匹配的左括号下标。

import java.util.ArrayDeque;
import java.util.Deque;

class Solution {
    public int longestValidParentheses(String s) {
        Deque<Integer> stack = new ArrayDeque<>();
        stack.push(-1);
        int best = 0;

        for (int i = 0; i < s.length(); i++) {
            if (s.charAt(i) == '(') {
                stack.push(i);
                continue;
            }

            stack.pop();
            if (stack.isEmpty()) {
                // 当前右括号无法匹配，后续区间不能越过它。
                stack.push(i);
            } else {
                best = Math.max(best, i - stack.peek());
            }
        }
        return best;
    }
}

文字推导与正确性

先确定“不能跨过去的位置”

从每个起点重新检查括号平衡，可以得到最坏 O(n²) 的暴力解。优化的关键不是更快检查同一个区间，而是扫描时记住阻断合法后缀的位置。

开始时把 -1 入栈，它是字符串左侧的虚拟边界。这样 "()" 在下标 1 完成匹配后，直接计算 1 - (-1)，就得到长度 2。

遇到左括号，只把位置压栈。它还在等待匹配，当前不能作为合法区间的结尾。

右括号要先弹栈，再看剩下的边界

遇到右括号时，栈非空：上一轮结束时要么保留了原有栈底，要么补入了新的边界。

先弹出栈顶，分两种情况：

  1. 栈空了：弹掉的是唯一的边界，没有左括号可配。当前右括号必然失配，把它的下标放回去作为新边界。任何后续合法子串都不能跨过它。
  2. 栈没空：弹掉的是一个左括号，匹配成功。此时的新栈顶 b 才是合法后缀左侧的障碍，候选长度为 i - b。

注意不是用刚弹出的左括号计算长度。那样只会算出最外侧这一对包住的区间，可能漏掉前面能连接起来的合法片段。

用一个例子检查边界的变化

扫描 ")()())"，栈按从底到顶记录：

下标字符处理后的栈本轮候选长度
初始—[-1]—
0)[0]失配，重置边界
1([0, 1]—
2)[0]2 - 0 = 2
3([0, 3]—
4)[0]4 - 0 = 4
5)[5]失配，重置边界

下标 4 的右括号只与下标 3 配对，但答案可以把之前的 "()" 接进来。这就是必须减去弹栈后的栈顶的原因。

为什么不会漏掉最长答案

扫描过程中，栈底始终是最近的失配右括号位置，或者初始哨兵；上面的下标是按顺序留下的未匹配左括号。

一次匹配成功后，新栈顶右侧到当前下标之间的括号均已匹配，且没有失配右括号，因此这一段是合法子串。若向左再扩一位，就会碰到仍未匹配的左括号或失配右括号，不能保持合法，所以它是以当前位置结尾的最长合法子串。

所有非空合法子串都以右括号结尾。遍历每个这样的结尾并取最大值，就不会漏掉全局最优解。

复杂度和边界

每个下标最多入栈一次、出栈一次，时间复杂度为 O(n)；全是左括号时栈会持续增长，额外空间复杂度为 O(n)。

需要检查的输入包括：

  • 空串、单个括号、全左括号、全右括号：返回 0。
  • "()()"：返回 4，不能把连续的两对拆开计长。
  • "(())"：返回 4，嵌套结构也要完整计长。
  • "(()"：返回 2，栈里剩下的左括号会限制起点。
  • "())(()"：返回 2，失配右括号阻止两侧拼接。

输入没有数值元素，负数与数值重复不适用；重复括号则是必须覆盖的常见情况。-1 只用作下标哨兵，不参与字符串访问。候选长度不超过 s.length()，用 Java int 存储下标和长度即可；本解法不额外分配 n + 1 的定长数组。

面试时忘记怎么办

先写出检查合法性的栈解法，再问自己：“现在要求长度，字符信息够不够？”不够，就把字符换成下标。

接着手算两个输入来恢复更新规则：

  • "()()"：第二次匹配不能只得到 2，说明要找弹栈之后的左边界。
  • ")()"：答案不能跨过开头的右括号，说明失配时必须更新边界。

最后用 "()" 检查从开头开始的情况。希望统一使用 右端点 - 边界，初始边界自然应该是 -1。

面试解释时可以这样说：“栈里存未匹配位置；匹配成功就减去剩余栈顶，匹配失败就把当前右括号设为新的边界。每个位置只进出栈一次。”

一句话总结

最长有效括号不只要知道配上了谁，更要知道配完之后，左边最近的障碍在哪里。
