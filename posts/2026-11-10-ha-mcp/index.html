智能家居自动化出问题，麻烦往往不在开关本身，而在实体名称、触发条件和执行记录分散各处。HA-MCP 把 Home Assistant 的查询与管理能力接到支持 MCP 的 AI 客户端，让排障不必从手工翻配置开始。它进入了本次核验的 GitHub 日榜，但比热度更值得看的是权限边界。

📌 这个项目是干什么的

  • 查询设备状态、历史数据和自动化执行轨迹，帮助定位“为什么没触发”。
  • 读取、创建或修改自动化、脚本与仪表盘，也能调用设备服务。
  • 面向已经使用 Home Assistant、愿意核对配置的开发者和智能家居玩家；不是买来就能接管所有品牌设备的万能助手。

🔍 为什么值得关注

它的价值不是再加一个聊天入口，而是把“找实体、读状态、查轨迹、改规则”接成工具工作流。例如先让助手检查走廊灯自动化最近一次执行，再解释哪个条件阻止了动作，比直接要求“修好灯”更容易核对。

另一个值得借鉴的设计是提供只读模式、逐工具开关和需要用户批准的工具安全策略。能查信息与能改家中设备，应当分开授权，而不是连通后默认全部放开。

🧪 谁适合试，怎么开始

现有用户先读安装文档。推荐的进程内集成要求 Home Assistant 2026.8.0 或更新版本，通过对应版本的 HACS 或市场安装，重启后添加 HA-MCP Server，再把配置页的连接地址填入客户端。只选一种服务器安装方式，别重复接入。

第一轮建议开启只读模式，只查一盏灯的状态和一条自动化的执行轨迹，对照管理界面确认结果。确认查询可靠，再考虑开放低风险修改；没有 Home Assistant 的读者可先看官方演示环境说明，不必为了试工具先改造全屋。

⚠️ 使用提醒

进程内服务器使用管理员权限，连接地址在秘密链接模式下就是凭证，不能贴进公开日志。优先使用专用账户和局域网连接，不为试用直接开放公网。

服务部署在家里，不代表客户端模型也在本地；设备信息会发往哪里，仍取决于所用客户端。门锁、取暖等高风险设备不宜作为首次测试对象。项目采用 MIT 许可证，但开源不等于操作安全。以上为官方资料核验，未进行家庭设备实测。
