最长递增子序列：先固定结尾，再决定接谁

题意和示例

给定整数数组 nums，从左到右保留若干元素，让保留下来的数字严格递增，返回最多能保留几个。允许跳过元素，不允许调整顺序；只求长度，不要求返回具体序列。

例如输入 [10, 9, 2, 5, 3, 7, 101, 18]，输出 4。[2, 3, 7, 18] 是一种选择，[2, 5, 7, 101] 也是。

两个容易混淆的例子：

  • [1, 3, 2, 4] 的答案是 3，因为子序列不必连续。
  • [2, 2, 2] 的答案是 1，因为相等不算严格递增。

原题链接：Longest Increasing Subsequence。下文采用二次时间的基础解法，不把它当作满足任意大规模输入的方案；空数组额外约定返回 0，null 不属于方法约定的输入。

考查点

这题的难点不是双重循环，而是给状态加上足够的信息。

如果只记录“前面最长能选几个”，就不知道那条序列的末尾是多少。例如前缀 [1, 100, 2] 的最长长度是 2，但末尾为 100 和末尾为 2，对接下来的 3 有完全不同的影响。

因此先固定最后一个元素：dp[i] 只讨论必须以 nums[i] 结尾的递增子序列。这样能不能接上新数，就可以用一次大小比较判断。

Java 代码

class Solution {
    public int lengthOfLIS(int[] nums) {
        int n = nums.length;
        int[] dp = new int[n];
        int best = 0;

        for (int i = 0; i < n; i++) {
            dp[i] = 1;
            for (int j = 0; j < i; j++) {
                if (nums[j] < nums[i]) {
                    dp[i] = Math.max(dp[i], dp[j] + 1);
                }
            }
            best = Math.max(best, dp[i]);
        }
        return best;
    }
}

文字推导与正确性

固定结尾之后，枚举倒数第二个位置

假设当前要计算 dp[i]。一条以 nums[i] 结尾的合法序列，要么只有它自己，要么存在倒数第二个元素 nums[j]。

后一种情况必须同时满足 j < i 和 nums[j] < nums[i]。前者保证原数组顺序，后者保证严格递增。满足条件时，在以 j 结尾的最优序列后追加当前元素，长度就是 dp[j] + 1。

所以先把 dp[i] 设为 1，再检查所有合法的 j，保留最大的候选值。不能只找左边最近的较小元素，因为更早的位置可能连接着更长的序列。

用一个短例子检查状态含义

对 [1, 3, 2, 4, 0]，计算出的 dp 为 [1, 2, 2, 3, 1]。

处理 4 时，可以接在 3 或 2 后面，得到长度 3。处理最后的 0 时，前面没有更小的数，只能得到长度 1。

这也解释了为什么不能返回最后一格：最后一个元素不一定在最优答案里。答案应当是全部 dp[i] 的最大值。

为什么不会遗漏，也不会算出不存在的序列

按下标从小到大计算，处理 i 时，所有 j < i 的状态已经求好。

对于任意一条以 i 结尾、长度大于 1 的最优序列，取出它的倒数第二个位置 j。它必然满足转移条件，因此一定被循环考虑，候选长度不会小于这条序列的长度。

另一方面，每个候选都来自一条实际存在的递增子序列，且仅在末尾数更小时追加 nums[i]，不会产生非法答案。结合单元素的初始状态，可归纳得出每个 dp[i] 都正确；再对所有结尾取最大值，就是全局答案。

复杂度和边界

  • 时间复杂度为 O(n²)：第 i 个位置检查前面 i 个位置，总比较次数为 n(n - 1) / 2。
  • 额外空间为 O(n)：使用长度为 n 的状态数组。
  • 单元素、全相等、严格递减数组均返回 1；空数组返回 0。
  • 负数不需要特殊处理，判断依据仍然是数值大小。
  • 直接用 < 比较，不用两个元素相减，避免极端整数相减溢出。状态存的是长度而非元素和，dp[j] + 1 不超过数组长度，使用 int 即可。

若面试官进一步要求 O(n log n)，可以改为维护“每种长度对应的最小结尾”，并二分寻找第一个大于等于当前数的位置。这里的“大于等于”用于替换，不能把重复值当成长度增长。该优化是另一种状态设计，不是简单把本题内层循环换成二分。

面试时忘记怎么办

先用 [1, 100, 2, 3] 问自己：只有“前缀最长长度”，能判断 3 接在哪里吗？不能，因为还缺少结尾信息。

接着把问题缩小成：“如果最后一个数必须选当前位置，最长能有多长？”这句话就能还原 dp[i]。

然后分两种情况：只选自己，长度为 1；或者枚举前面更小的数，在其最优结果上加 1。最后用 [1, 2, 0] 检查返回值，提醒自己取全局最大，而不是最后一格。

如果只想得起基础 DP，就先把正确解法、严格比较条件和 O(n²) 的代价讲清楚，不要在尚未解释正确性时急着背优化结论。

一句话总结

固定最后一个元素，枚举它能接在哪些更小的结尾之后；每个结尾各自求最优，最终再取最大值。
