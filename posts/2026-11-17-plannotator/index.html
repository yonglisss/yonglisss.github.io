编程 Agent 写得越快，人越容易在长对话和大批代码改动里漏掉关键决策。进入本次 GitHub 日榜的 Plannotator，把计划、文档和代码差异放进本地浏览器，让你直接批注，再把反馈送回 Agent。它解决的不是“再生成一次”，而是“怎样准确告诉它哪里不对”。

📌 这个项目是干什么的

  • 审阅计划、需求文档和 Agent 消息，把修改意见落到具体文本。
  • 查看本地代码改动或 GitHub、GitLab 合并请求，对行、片段或整个文件留言。
  • 通过插件、钩子和命令连接编程 Agent，而非要求你更换整套开发环境。

适合已经使用 Claude Code、Codex 等工具，但仍需要自己把关需求与代码的开发者。

🔍 为什么值得关注

第一，反馈有位置。比起在聊天框里说“这里需要重构”，批注能带上文件与行号，减少 Agent 猜测指代对象的空间。

第二，人工审阅和 AI 辅助分开。官方明确说明，核心代码审阅工具可以手动使用，AI 层是可选的；需要时再调用问答、审阅 Agent 或按重要性组织差异的导览。

对开发者更有借鉴意义的是这条闭环：生成结果、展示原文、定位反馈、回传修改。不要只优化生成速度，也要为验收设计一个低摩擦入口。

🧪 谁适合试，怎么开始

先按官方文档安装并连接你正在用的 Agent。安装器会下载二进制并配置相关集成，执行前应检查脚本，不要把它当成一个只读插件。

从一个小改动开始：让 Agent 修改一个函数，再用终端命令打开审阅：

plannotator review

挑一处边界条件留下意见，发送反馈，检查 Agent 是否正确修改，并自行运行测试。先验证这一轮闭环，再考虑多 Agent 收件箱等扩展功能。

⚠️ 使用提醒

本地审阅不等于所有功能都不联网：AI 审阅会把相关提示和代码上下文交给所选服务；分享功能也有独立的数据边界。敏感仓库先关闭分享，核对模型服务政策。

项目采用 MIT 或 Apache-2.0 双许可证，可任选其一；它不是正确性保证，也不能代替测试和人工批准。本文依据官方资料核验，未进行本地安装实测。
