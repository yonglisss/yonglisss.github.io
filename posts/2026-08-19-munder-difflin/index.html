Munder Difflin：把多个编码 Agent 组织成一间本地“办公室”

同时打开几个编码 Agent 不难，难的是分工、传递上下文和及时接管。近期登上 GitHub Trending 的 Munder Difflin，把现有终端 Agent 接进同一套本地桌面工作台，让它们像团队一样协作，而不是各自在窗口里孤立运行。

同时打开几个编码 Agent 不难，难的是分工、传递上下文和及时接管。近期登上 GitHub Trending 的 Munder Difflin，把现有终端 Agent 接进同一套本地桌面工作台，让它们像团队一样协作，而不是各自在窗口里孤立运行。

📌 这个项目是干什么的

Munder Difflin 是一款基于 Electron 的多 Agent 桌面应用。它通过 node-pty 启动真实的终端 CLI，而非重新实现 Agent。目前 README 列出了 Claude Code、Codex、OpenCode、Kimi Code、Qwen、Copilot CLI 等接入项，也支持 Ollama、LM Studio 和 vLLM 等自带模型路径。

每个 Agent 有独立终端、邮箱和持久记忆，由主管 Agent 负责分派、路由和升级任务。像素办公室只是可视化层，底层还有任务账本、生命周期钩子、成本记录与人工接管。

🔍 为什么值得关注

第一，它保留现有 CLI 的原生能力。开发者可以继续使用已经配置好的工具、订阅和模型，在上层增加协作机制，减少单一框架锁定。

第二，它把系统拆成两条通路：终端通路处理进程输入输出，事件通路处理钩子、消息、记忆和调度。这比“多开几个终端”更易排查任务究竟卡在执行、通信还是分工。

第三，项目仍在快速修补可用性。8 月 18 日发布的 v0.4.4 修复了 Windows Agent 间消息和首次启动问题，并新增 Skills 浏览器。但官方仍将其标为 working prototype，应按实验工具看待。

🧪 谁适合试，怎么开始

它适合经常并行处理代码任务、已使用多种编码 CLI，或研究多 Agent 调度的开发者。建议先在非敏感测试仓库只接两个 Agent，验证“拆任务—传消息—合并结果—人工接管”这条最小链路。

运行需要 Node.js 18+、npm、C/C++ 工具链，以及至少一个已加入 PATH 的受支持 CLI：

git clone https://github.com/chaitanyagiri/munder-difflin.git
cd munder-difflin
npm install
npm run dev

⚠️ 使用提醒

多 Agent 不会自动提高效率，还可能重复改文件、增加模型消耗。请从可独立验收的小任务开始，并保留 Git 分支和人工审查。

官方构建会发送有限的匿名事件，可在设置中关闭或设置 DO_NOT_TRACK；源码构建默认不发送。源代码采用 MIT 许可证，但内置像素美术资产仅限非商业使用，商业化前需替换素材或取得授权。
