团队开始同时使用 Claude Code、Codex、Cursor 等工具后，新的问题很快出现：每个人各自维护提示词、Skills 和规则，同一个坑反复踩，换一个客户端又要重新配置。今日进入 GitHub Trending 的 TeamAI CLI，试图用团队 Git 仓库统一管理这些资源，让 AI 编程经验像代码一样共享、评审和迭代。

📌 这个项目是干什么的

TeamAI CLI 是腾讯开源的团队协作命令行工具。它可以把 Skills、规则、文档、Agent、Hook、MCP 配置和非敏感环境配置集中到一个 Git 仓库，再同步到成员使用的不同 AI 工具。

核心流程并不复杂：成员用 teamai push 提交改进，工具创建分支和合并请求；审核合并后，其他成员通过 teamai pull 获取更新。项目还提供知识检索、代码库知识图谱和会话经验沉淀能力，但 README 已明确将“团队上下文”和“团队改进”标为 beta。

🔍 为什么值得关注

第一，它把 Agent 配置纳入了已有的工程治理。 团队不用再靠群文件分发提示词，而是借助 Git 留下版本、评审与回滚记录。对于涉及代码规范、发布流程或安全要求的规则，这比个人目录里各管一套更可靠。

第二，它不绑定单一 AI 客户端。 官方支持矩阵覆盖 Claude Code、Codex、Cursor、OpenCode、OpenClaw、Hermes 等工具，不过不同客户端支持的资源类型并不完全一致，接入前应先核对矩阵。

第三，它开始处理“经验如何回流”。 工具可根据用户纠正、拒绝工具调用、重复失败等摩擦信号，提醒团队把有价值的解决过程整理成学习文档；知识召回功能则默认关闭，需要主动启用。这种克制比自动收集所有会话更适合团队环境。

🧪 谁适合试，怎么开始

它更适合已经有多人使用 AI 编程工具，并且愿意维护共享 Git 仓库的研发团队。Node.js 需为 20 或以上。可以先从低风险的项目级 Skills 和规则开始：

npm install -g teamai-cli
cd /path/to/project
teamai init https://github.com/yourorg/your-teamai-repo

建议先找两三名成员，用一个测试仓库走通“初始化—推送—审核—拉取”，确认各客户端生成的位置和覆盖行为，再接入正式项目。当前 npm 稳定版为 0.23.1，0.24.0-beta.3 属于 beta 标签，不必为追新直接用于全员环境。

⚠️ 使用提醒

共享仓库中的规则会影响成员的 Agent 行为，合并权限应当比普通文档更谨慎。官方明确提醒不要把密钥放进共享的 env 配置；会话摘要、知识召回和代码库导入也可能涉及内部信息，应先制定采集范围与脱敏规则。项目采用 MIT 许可证，但 beta 功能仍在快速变化，升级前要阅读 Release 并保留回滚路径。
