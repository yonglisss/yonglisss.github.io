让 Agent 生成一段文字或一张表并不难，难的是让它安全地读写真实办公文件，并把结果交给人继续检查和修改。Univer 是一个开源 Office SDK，可在产品中嵌入电子表格、文档等编辑能力，也能在 Node.js 中无界面运行。它今天进入 GitHub Trending，近期发布 1.0.2，适合正在开发 AI 办公、数据分析或自动化产品的团队关注。

📌 这个项目是干什么的

Univer 不是一个独立的在线 Office，也不是套在大模型外面的聊天界面。它提供可组合的 Office 基础能力：表格、文档、公式引擎、Canvas 渲染、命令与事件系统，以及面向上层应用的 Facade API。

开发者可以把编辑器嵌入 SaaS、内部工具或 BI 流程，也可以在 Node.js 中让 Agent 读取、计算和修改工作簿。项目支持插件模式与预设模式：前者便于精细控制依赖和功能，后者更适合快速搭建。仓库采用 Apache-2.0 许可证；目前 Sheets 是最成熟的产品面，Docs 和 Slides 仍在持续完善。

🔍 为什么值得关注

第一，Agent 操作的是结构化对象，而不是只“看图点鼠标”。 工作簿、区域、公式、命令和事件都有 API，适合构建可重复、可检查的办公自动化。与纯视觉操作相比，这条路径更容易验证结果，也更适合服务端批处理。

第二，浏览器与 Node.js 使用同一套架构。 前端可以保留人类熟悉的编辑与复核界面，后端则以 Headless 模式执行公式计算或文档处理。对 AI 产品来说，这意味着“Agent 处理—用户复核”不必拆成两套完全不同的技术栈。

第三，它把扩展能力放在插件层。 团队可以从官方预设起步，再按需加入自定义命令、服务和 UI，而不是直接维护一套完整 Office 编辑器。仓库还提供 examples、Showcase 与 API Reference，便于先确认能力边界再投入集成。

🧪 谁适合试，怎么开始

更适合三类团队：要在产品里嵌入表格或文档编辑器的 SaaS 开发者；需要让 Agent 处理工作簿的自动化团队；希望自建 Office 交互面的内部工具团队。

最短路径是先打开官方 Showcase，确认目标交互是否已有示例；随后按安装文档使用 Preset Mode 建一个空白 Sheets 页面，尝试创建工作簿、写入单元格和读取结果。需要服务端处理时，再转向 Headless 指南，不必一开始就引入完整插件集合。

⚠️ 使用提醒

开源核心与 Univer Pro 的边界要先看清。实时协作、导入导出、打印、图表、透视表及部分服务端能力属于商业扩展，不能仅凭首页展示推断为开源仓库全部具备。

各 @univerjs/* SDK 包应保持在同一协调版本线上；Headless 模式要求 Node.js 18.17 或更高。项目覆盖面较大，正式选型前应针对文件兼容性、公式、性能和许可证逐项做最小验证。1.0.2 是补丁版本，发布说明称没有引入公开 API 变化。
