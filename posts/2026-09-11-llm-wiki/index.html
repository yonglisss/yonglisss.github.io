LLM Wiki：把散落文档编译成可持续维护的个人知识库

把 PDF、网页和笔记放进知识库不难，难的是持续整理：新资料该归到哪里、与旧内容有什么联系、答案能否回到原始出处。今日进入 GitHub Trending 的 LLM Wiki，选择让模型增量维护一套结构化 Wiki，而不是每次提问都从文档中临时检索并重新组织答案。

📌 这个项目是干什么的

LLM Wiki 是一款基于 Tauri 的跨平台桌面应用，支持 macOS、Windows 和 Linux。它采用三层结构：不可变的原始资料、由模型生成的 Wiki 页面，以及定义整理规则的 Schema；核心操作包括导入、查询和检查。

导入时，模型先分析实体、概念和潜在关联，再生成带来源字段的 Markdown 页面，并用 [[wikilink]] 建立连接。项目支持 PDF、Office 文档、电子书、网页剪藏等格式，也能把 Wiki 目录作为 Obsidian 仓库使用。关键词搜索与图谱扩展默认可用，向量检索则是可选项。

🔍 为什么值得关注

第一，它把一次性问答变成可复查的知识资产。 原始文件保留不动，生成页面记录来源，目录、概览和操作日志随导入更新。读者不仅得到答案，还能回到材料核对依据。

第二，它认真处理了增量维护。 文件会先计算 SHA-256，内容未变化就跳过；导入队列支持持久化、失败重试和进度查看。相比每次重建整个知识库，这条路径更适合长期积累。

第三，它没有把人工判断完全交给模型。 系统会把需要确认的问题放进 Review 队列，知识图谱还能提示孤立页面、稀疏主题和桥接节点。模型负责整理，人负责决定哪些连接和研究方向值得保留。

🧪 谁适合试，怎么开始

它适合需要长期整理研究资料、产品文档、读书笔记或项目档案的人。最短路径是从 Release 下载对应系统的安装包，创建项目后配置模型服务，再导入一小批主题集中的 Markdown 或 PDF；先检查生成页面、来源引用和交叉链接是否准确，再逐步扩大资料范围。

如果需要与 Claude Code、Codex 等工具联动，可在应用中启用仅监听 127.0.0.1 的本地 API 与 MCP 服务。建议先用只读检索验证效果，不要一开始开放 Shell 或批量导入敏感资料。

⚠️ 使用提醒

“本地桌面应用”不等于所有数据都留在本机：你配置的模型、嵌入和联网搜索服务可能收到文档内容，处理公司资料前要核对各服务的数据政策。Wiki 页面由模型生成，仍可能出现错误归类或错误关联，重要结论必须回看原始来源。当前最新 Release 为 v0.6.11，版本仍处于 0.x；项目采用 GPL-3.0，计划修改后分发或嵌入产品的团队应先评估许可证义务。
