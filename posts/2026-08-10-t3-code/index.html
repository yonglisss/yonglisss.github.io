同时使用 Codex、Claude Code 或 OpenCode 时，真正麻烦的往往不是模型能力，而是会话散落在不同终端，离开电脑后也很难安全接管。T3 Code 是一个 MIT 开源的 Agent 控制界面：它不替代编码 Agent，而是在本机运行服务，用 Web、桌面端和手机统一管理项目、线程与执行过程。

📌 这个项目是干什么的

T3 Code 目前可驱动 Codex、Claude Code、Cursor、Grok Build 和 OpenCode。对应 CLI 仍安装、登录并运行在用户自己的机器上，T3 Code 负责把它们接入统一界面；模型订阅、认证与执行权限不会被它自动提供。

它把客户端与执行环境分开：手机、Web 或桌面端通过 HTTP/WebSocket 连接 T3 服务端，而项目文件、Git、终端和 Agent 会话都留在服务端所在机器。远程访问可使用局域网、Tailscale HTTPS、SSH 转发或项目提供的中继连接。

🔍 为什么值得关注

第一，它解决的是“控制多个 Agent”，而不是再造一个 Agent。不同 Provider 被适配到统一的线程、审批、用户输入、检查点回退和会话停止接口，更适合需要并行查看多个编码任务的人。

第二，远程能力不是简单把终端暴露到公网。官方文档提供一次性配对令牌、二维码、Tailscale Serve 和桌面端 SSH 启动流程；托管 Web 页面只保存连接信息，后端仍由浏览器直接访问，不会替用户托管项目状态。

第三，上手成本较低。已有认证完成的 Provider CLI 时，可直接运行 npx t3@latest 打开本地 Web 界面，不必先安装桌面端。

🧪 谁适合试，怎么开始

适合同时使用两种以上编码 Agent、经常跑长任务，或希望离开电脑后查看进度并处理审批的开发者。最短路径是先准备 Node.js 22.16+ 的兼容版本，并登录至少一个支持的 CLI：

npx t3@latest

先在测试仓库完成一个短任务，确认文件变更、审批和停止流程，再尝试远程连接。需要手机访问时，优先按官方建议使用可信的 Tailscale 私网，并通过 npx t3 pair --tailscale 生成配对链接。

⚠️ 使用提醒

T3 Code 是控制面，不是安全沙箱。服务端拥有项目文件、终端、Git 和 Provider 会话权限，把端口直接开放到公网会扩大风险；敏感项目应使用私网、最小权限凭据和独立 worktree。项目 README 也明确标注仍处于很早期，Bug 与接口变化需要预期。当前要求较新的 Node.js 版本，且必须自行安装和认证 Provider CLI。截至 8 月 10 日，最新 Release 为 v0.0.32。
