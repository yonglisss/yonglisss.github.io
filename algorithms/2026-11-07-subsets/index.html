回溯 · 数组 · 枚举 · Java

子集：用递增下标，把回溯写成不重不漏的枚举

题意和示例

给定一个元素互不相同的整数数组 nums，返回所有可能的子集。每个元素最多取一次，空集也算一个答案；结果的排列顺序没有要求。

例如输入 [1, 2]，可以返回 [[], [1], [1, 2], [2]]。[2, 1] 和 [1, 2] 表示同一个子集，不能把它们当成两个答案。

原题：LeetCode 78 · Subsets。这里按原题的“不含重复元素”前提实现，不处理允许重复值的另一道变体题。

考查点

  • 用一个可变列表保存当前选择，并在递归返回后恢复现场。
  • 用下一个可选位置 start 消除排列顺序造成的重复，而不是事后用集合去重。
  • 分清“路径是一个答案”和“路径必须走到底才是答案”。
  • 保存路径的快照，避免所有结果引用同一个列表。

Java 代码

import java.util.ArrayList;
import java.util.List;

class Solution {
    public List<List<Integer>> subsets(int[] nums) {
        List<List<Integer>> result = new ArrayList<>();
        dfs(nums, 0, new ArrayList<>(), result);
        return result;
    }

    private void dfs(int[] nums, int start,
                     List<Integer> path, List<List<Integer>> result) {
        result.add(new ArrayList<>(path));
        for (int i = start; i < nums.length; i++) {
            path.add(nums[i]);
            dfs(nums, i + 1, path, result);
            path.remove(path.size() - 1);
        }
    }
}

path.remove(path.size() - 1) 的参数是 int 下标，调用的是按位置删除的重载，不是按元素值删除。整个方法不会修改输入数组，也没有跨调用保留的成员状态。

文字推导与正确性

当前路径已经可以交卷

先别急着背“选或不选”。问一个更直接的问题：如果现在已经选了 [1]，还需要继续选元素才能成为子集吗？不需要。因此每次进入 dfs，先把当前路径存入结果。

初次调用时路径为空，恰好把空集收进去。之后的循环是在这个子集上继续扩展，而不是为了让当前路径获得合法资格。

这也解释了为什么没有额外的终止分支：当 start 等于数组长度时，收集完路径，循环自然不执行，方法就返回。

只向右选，顺序就不会制造重复

假设输入是 [1, 2, 3]，选入下标 0 的 1 后，下一层只能从下标 1 开始。这样能得到 [1, 2]，却不会从 [2] 再回头选出 [2, 1]。

start 约束的是下标，不是数值大小。因此数组不必排序，即使输入是 [3, -1, 2]，规则依然成立。

选择下标 i 后必须递归到 i + 1。传 i 会重复使用同一个元素；每层都从 0 开始则破坏了递增下标约束。

返回后为什么必须撤销

以 [1, 2] 为例，收集顺序是：

  1. 初始路径 []。
  2. 选择 1，收集 [1]。
  3. 再选择 2，收集 [1, 2]。
  4. 返回时依次移除 2、1，路径回到 []。
  5. 根层再选择 2，收集 [2]。

每次子调用结束后，必须恢复到调用前的路径，后续分支才能从相同起点出发。new ArrayList<>(path) 则把当时的内容独立保存下来；只写 result.add(path)，后续撤销会连已保存的答案一起改变。

不漏也不重的理由

任意子集都可以按原数组下标递增排列。循环能够依次选择这些下标，所以每个子集都有一条能够到达的路径，不会遗漏。

反过来，每条路径的下标严格递增，同一个下标不会选两遍。由于原数组元素互异，一个子集只对应这一种递增下标序列，因此不会重复。

注意，“只在叶子收集会漏答案”针对的是这里的循环扩展写法。如果换成逐个元素做选或不选的二叉递归，在处理完全部元素的叶子收集，同样可以枚举所有子集，不能混用两种模板的收集位置。

复杂度和边界

设数组长度为 n，共有 2^n 个子集。每个元素在一半的子集中出现，复制出的元素总量为 n × 2^(n-1)（n ≥ 1）。

  • 时间复杂度：O(n × 2^n)，包括复制路径；不能只按递归节点数写成 O(2^n)。
  • 辅助空间：O(n)，来自当前路径和递归栈，不计返回值。
  • 返回结果占用空间：O(n × 2^n)。如果面试官问总空间，必须把这一项算进去。

边界核对：

  • 单元素 [0] 返回空集和 [0]，零不需要特殊判断。
  • 负数和正数只作为元素保存，没有求和、乘法或大小比较，不存在元素运算溢出。
  • 即使传入空数组，本实现也会返回 [[]]；这是实现的额外覆盖，不是在宣称原题允许空输入。
  • 若输入出现重复值，按下标枚举仍会产生相同内容的子集；不能直接把本解法当成重复元素变体的答案。
  • null 不属于这里的输入契约，代码没有额外兜底。枚举输出本身是指数级的，不适合任意放大 n。

面试时忘记怎么办

先画 [1, 2] 的四个答案，问自己：“空集在哪里收集？选了 1 后能不能停？”这两问会把“进入递归先保存路径”推出来。

再问：“如何让 [1, 2] 出现，但不让 [2, 1] 再出现？”答案是只能向更大的下标选择，于是得到 start 和递归参数 i + 1。

最后补齐三个动作：加入一个元素、递归、删除最后一个元素；保存答案时复制列表。讲复杂度时主动区分辅助空间和结果空间，比只背一个 O(n) 更准确。

如果仍然卡住，也可以先说明逐元素的“选或不选”方案，在全部元素决定完毕后收集答案；不要把它的叶子收集规则生搬到上面的循环模板里。

一句话总结

子集回溯的关键不是把路径填满，而是保存每个合法前缀，并用递增下标保证每种选择只出现一次。
